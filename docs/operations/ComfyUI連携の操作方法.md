# ComfyUI連携の操作方法

## 1. 前提

- ComfyUIを同じPCの`http://127.0.0.1:8188/`で起動する。
- 本アプリはDocker内から接続するため、`.env`では次を使う。

```dotenv
COMFYUI_BASE_URL=http://host.docker.internal:8188
COMFYUI_CONNECT_TIMEOUT=3
COMFYUI_TIMEOUT=10
```

`.env`を変更した場合は、設定キャッシュを消す。

```sh
docker compose exec app php artisan config:clear
```

初回または更新後は、DBマイグレーションとフロントエンドビルドを実行する。

```sh
docker compose exec app php artisan migrate
docker compose run --rm -T node npm run build
```

## 2. checkpoint・サンプラー・スケジューラを登録する

人物LoRAを登録する前に、系統ごとに利用する生成設定の候補を登録する。

1. 本アプリを開き、「デフォルト」欄の「系統を管理」を押す。
2. 「登録済みの系統」で設定対象の系統を選ぶ。
3. 「人物LoRAの生成設定」で種類を`Checkpoint`にする。
4. 「ComfyUIへ渡す値」に、ComfyUIのワークフローで使用する値を正確に入力する。checkpointは通常、`example.safetensors`のように拡張子まで入力する。
5. 「新規登録」を押し、登録済み設定の一覧に追加されたことを確認する。
6. 同様に、サンプラーへ`euler_ancestral`など、スケジューラへ`normal`など、実際に使用する値を登録する。

人物LoRAの新規登録・編集画面では、所属系統を選んだ後、この三種類を一つずつ選ぶ。三種類の候補が揃っていない人物LoRAは保存できない。

登録済み設定を変更する場合は一覧から一件を選び、値を直して「更新」を押す。人物LoRAが使用中の設定は削除できないため、先に該当人物LoRAを別の設定へ変更する。

同じ系統・種類・値は重複登録できない。保存できない場合は設定欄の下に表示される理由を確認する。セッション切れと表示された場合は、入力値を控えてページを再読み込みしてから操作する。

## 3. 系統別ワークフローを登録する

ワークフローを登録しない状態では、ComfyUIへ送信できない。系統ごとに使用するワークフローが異なる場合は、それぞれのAPI形式JSONを登録する。

1. 本アプリを開き、「デフォルト」欄の「系統を管理」を押す。
2. 「登録済みの系統」で設定対象を選ぶ。
3. 「ComfyUIワークフロー」のファイル欄で、その系統に使用するAPI形式JSONを選ぶ。
4. JSONの内容を確認し、positive、negative、seedそれぞれの「ノードID」と「入力名」を入力する。値はワークフローごとに異なる。
5. checkpoint、サンプラー、スケジューラについても、JSON内で値を持つ入力の「ノードID」と「入力名」を入力する。この三種類はそれぞれ一行以上が必須である。
6. 同じ値を設定するノードが複数ある場合は「入力位置を追加」を押し、すべての入力位置を登録する。不要な空行は「削除」で取り除く。
7. 出力先を人物LoRA別にする場合だけ、「出力先」に`filename_prefix`へつながる文字列入力のノードIDと入力名を一行登録する。本アプリは`tmp/{LoRA登録名}/{LoRA登録名}`を設定するため、ComfyUIの`output/tmp/{LoRA登録名}/`ディレクトリ内へ登録名を接頭辞とする画像が保存される。元JSONの出力先を使う場合は空のままにする。
8. 「ワークフローを保存」を押す。
9. 「設定済み：ファイル名」と表示されることを確認する。
10. 別の系統にも送信する場合は、対象系統を選び直して同じ操作を行う。

### ノードIDと入力名の確認例

API形式JSONでは、外側のキーがノードID、`inputs`直下のキーが入力名である。例えば次のJSONでは、checkpointのノードIDは`49`、入力名は`ckpt_name`になる。

```json
{
    "49": {
        "inputs": {
            "ckpt_name": "example.safetensors"
        },
        "class_type": "CheckpointLoaderSimple"
    }
}
```

よく使われる入力名には`ckpt_name`、`sampler_name`、`scheduler`があるが、ノードIDと入力名はワークフローごとに異なる。必ず登録するJSON自体を確認する。出力先が別ノードの文字列を参照している場合は、参照先の文字列入力を指定する。

開発時に提供されたJSONや、そのノードID・入力名は実運用の既定値ではない。実際に登録するAPI形式JSONに含まれる入力位置を指定する。

JSONを選択しただけでは保存されない。必ず「ワークフローを保存」を押し、「設定済み」の表示を確認する。

## 4. 通常のプロンプトを送信する

1. 通常どおり項目を選び、「プロンプトを表示」を押す。
2. 必要ならpositive／negative出力欄を直接編集する。
3. 「ComfyUIへ送信」を押す。
4. 「キューへ追加しました（ID: …）」と表示されることを確認する。

送信には出力を作った時点の系統を使う。positive／negativeは空でも送信できる。通常送信には確認ダイアログを出さない。

## 5. 人物LoRA差し替え候補を一括送信する

1. positiveを出力する。
2. 「人物LoRAを差し替えてコピー」を押す。
3. 送信する「人物LoRA＋トリガー」の行をチェックする。初回は全候補がチェック済みになる。
4. 必要に応じて「全候補を選択」「全候補を解除」を使う。検索中でも全候補が対象になる。
5. 「選択した候補をComfyUIへ送信」を押す。
6. 表示された件数を確認して承認する。
7. キュー追加件数と失敗件数を確認する。

チェック状態は同じブラウザーの`localStorage`に保存される。別ブラウザーや別端末とは同期しない。一回の送信上限は100件で、一件が失敗しても残りの送信を続ける。

候補を試しに一件だけ生成する場合は、対象行の「この1件を送信」を押す。確認なしでその候補だけをComfyUIへ送り、一括送信用チェックボックスの状態は変更しない。

## 6. 反応しない・送信できない場合

### 「保存できませんでした」と表示される

ページを再読み込みしてからもう一度操作し、設定欄の下に表示される具体的な理由を確認する。ワークフローでは次を確認する。

- checkpoint、サンプラー、スケジューラに、それぞれ一行以上の入力位置がある。
- 追加した各行のノードIDと入力名が両方入力されている。
- ノードIDと入力名が、選択したAPI形式JSONの`inputs`内に実在する。
- 同じ役割に同じノードIDと入力名を重複登録していない。
- 出力先を使わない場合、空の行を残さず削除している。

### ボタンを押しても表示が変わらない

フロントエンドのビルドが古い可能性がある。次を実行してブラウザーをハードリロードする。

```sh
docker compose run --rm -T node npm run build
```

### 「ワークフローが未設定」と表示される

対象系統のJSONを選択しただけで、保存していない可能性がある。「系統を管理」で対象系統を選び、「設定済み：ファイル名」と表示されるまで保存する。

### ComfyUIへ接続できない

次を確認する。

- ComfyUIが`http://127.0.0.1:8188/`で起動している。
- `.env`の`COMFYUI_BASE_URL`が`http://host.docker.internal:8188`になっている。
- `.env`変更後に`php artisan config:clear`を実行した。

Docker内からの確認例：

```sh
docker compose exec app php -r 'echo file_get_contents("http://host.docker.internal:8188/queue");'
```

### 人物LoRA差し替えボタンが無効

先にpositiveを出力し、人物LoRAの読込が完了している必要がある。登録済み人物LoRAがない場合も使用できない。

## 7. ワークフローを変更した場合

ノード構成を変えたJSONを再度アップロードし、positive／negative／seed／checkpoint／サンプラー／スケジューラと、必要なら出力先のノードID・入力名を選び直して保存する。JSONの行番号は使用しない。ノードIDと入力名が正しいことを保存時に検証し、検証に失敗した場合は以前の設定を保持する。
