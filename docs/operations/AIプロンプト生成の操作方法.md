# AIプロンプト生成の操作方法

## 1. この機能でできること

描きたいイラストを日本語などで説明すると、外部LLM APIを利用して画像生成向けの英語プロンプトを作成する。

生成される文面は次の二つである。

- `positive`：画像に含めたい人物、服装、構図、背景、照明、雰囲気など
- `negative`：画像に含めたくない崩れや低品質な表現など

生成結果はすぐに既存出力へ書き込まれない。モーダル内で確認・編集し、「既存の出力へ反映」を押した場合だけpositive／negative出力が置き換わる。

## 2. 外部LLM APIを設定する

この機能を使うには、Laravelの実行環境から到達できるOllama Chat API互換の外部LLM APIが必要である。LLMの導入、起動、配置方法はこの文書の対象外とする。

`.env`へ次の設定を追加する。

```dotenv
ILLUSTRATION_LLM_BASE_URL=http://illustration-llm:11434
ILLUSTRATION_LLM_MODEL=gemma3:12b
ILLUSTRATION_LLM_CONNECT_TIMEOUT_SECONDS=3
ILLUSTRATION_LLM_TIMEOUT_SECONDS=120
ILLUSTRATION_LLM_NUM_PREDICT=512
```

各項目の意味は次のとおり。

| 項目 | 内容 |
| --- | --- |
| `ILLUSTRATION_LLM_BASE_URL` | Laravelから接続できる外部LLM APIのベースURL。末尾の`/api/chat`は付けない |
| `ILLUSTRATION_LLM_MODEL` | 外部LLM APIで使用できるモデル名 |
| `ILLUSTRATION_LLM_CONNECT_TIMEOUT_SECONDS` | 接続が成立するまで待つ秒数 |
| `ILLUSTRATION_LLM_TIMEOUT_SECONDS` | 生成応答を待つ秒数 |
| `ILLUSTRATION_LLM_NUM_PREDICT` | 一回の生成で出力できる最大トークン数。通常は既定値の`512`を使用する |

設定例のURLとモデル名は、そのまま使えることを保証する既定の接続先ではない。利用する外部LLM APIに合わせて変更する。

`.env`を変更した場合は設定キャッシュを消す。

```sh
docker compose exec app php artisan config:clear
```

画面の変更が表示されない場合は、配信用アセットを再構築する。

```sh
docker compose run --rm -T node npm run build
```

## 3. Danbooruタグと自然文の違い

生成時に「プロンプト形式」を選択できる。迷った場合は、最初に既定の「Danbooruタグ」を試し、使用する画像生成モデルとの相性がよくない場合に「自然文」を試す。

### Danbooruタグ

イラストの内容を、短い英語の単語や語句に分けてカンマ区切りで並べる形式である。

```text
1girl, solo, long black hair, school uniform, classroom, sunset, looking outside
```

`1girl`は女性が一人、`long black hair`は長い黒髪、`classroom`は教室、`sunset`は夕暮れを表す。このようなタグをすべて暗記する必要はなく、日本語の説明から外部LLMが候補を作成する。

Danbooruタグには次の特徴がある。

- アニメ系の画像生成モデルでよく使われる。
- 人物、服装、背景などを項目ごとに追加・削除しやすい。
- 単語の並びなので、通常の英文として読むと不自然に見える。
- モデルによって理解できるタグや効果が異なる。

### 自然文

通常の英文でイラストの内容を説明する形式である。

```text
A girl with long black hair wearing a school uniform looks out of a classroom window at sunset.
```

自然文には次の特徴がある。

- 文脈を含む文章を理解しやすい画像生成モデルに向いている。
- 人物同士の関係、構図、雰囲気を文章で表現しやすい。
- タグ単位の追加・削除はDanbooruタグより行いにくい。

どちらが常に優れているわけではない。使用する画像生成モデルの推奨形式に合わせる。

## 4. プロンプトを生成する

1. プロンプト準備画面で「AIでプロンプトを作成」を押す。
2. 「イラストの指示」へ描きたい内容を入力する。
3. 「プロンプト形式」で「Danbooruタグ」または「自然文」を選ぶ。
4. 現在選択中のデフォルトを一緒に使う場合は、「現在のデフォルトプロンプトを含める」を選択したままにする。
5. 「生成する」を押す。
6. AIが生成したpositive／negative、反映時に追加されるデフォルト、使用モデル名・生成時間を確認する。
7. 必要に応じてAIが生成したpositive／negativeを直接編集する。
8. 内容を確認して「既存の出力へ反映」を押す。

指示は2,000文字以内で入力する。一枚のイラストとして、人数、人物の特徴、服装、場所、動作、構図、照明、雰囲気を具体的に書くと確認しやすい候補を得やすい。

入力例：

```text
黒髪ロングの女の子が一人、夕暮れの教室で窓の外を眺めている。
白いブラウスと紺色のスカートを着ている。横から見た構図で、柔らかい逆光。
```

人数や服装など、変えてほしくない条件は明記する。生成結果は外部LLMによる候補であり、入力内容や使用する画像生成モデルに対して常に最適であるとは限らない。反映前に内容を確認する。

## 5. 生成結果を編集・反映する

生成が成功しても、「既存の出力へ反映」を押すまでは現在のpositive／negative出力は変わらない。

- positiveは空白だけの状態では反映できない。
- negativeは空でも反映できる。
- 生成結果を編集してから反映できる。
- 「現在のデフォルトプロンプトを含める」が選択されている場合も、既存画面で選択解除した側のデフォルトは追加しない。
- デフォルトはAIへ送信せず、反映時にアプリケーションがAI生成部分の前へ追加する。
- モーダルを閉じると、進行中の画面側の生成要求は中断される。
- 生成や通信に失敗しても、既存出力は変更されない。入力を残したまま再試行できる。

反映後の出力は、通常の出力と同様に次の操作で使用できる。

- positive／negativeの直接編集とコピー
- クリップへの保存と呼び出し
- お気に入りへの保存
- 人物LoRAの差し替えコピー
- ComfyUIへの送信

反映後に通常の「プロンプトを表示」または「プロンプトを作成」を押すと、現在の選択項目から通常のプロンプトを作り直し、AI生成結果を上書きする。残したい場合は、先にクリップまたはお気に入りへ保存する。

## 6. 人物LoRAとの関係

人物LoRAとトリガーを選択した状態でAI生成結果を反映すると、次の順序でpositiveへ追加される。

```text
AIが生成したpositive

選択中の人物LoRAタグ

選択中のトリガー
```

人物LoRAとトリガーは外部LLMへ送らず、反映時に既存機能が追加する。これにより、反映後も「人物LoRAを差し替えてコピー」で人物部分だけを置き換えられる。

人物LoRAが未選択の場合でも、モーダルのチェックと既存画面の選択状態に応じてデフォルトをAI生成結果の前へ追加する。次の項目は選択状態を維持するが、AI生成結果へ自動追加しない。

人物LoRAを選択せずにAI生成結果を反映した場合も、「人物LoRAを差し替えてコピー」を利用できる。コピーする候補を選ぶと、現在のAI生成部分を維持したまま、その後ろへ候補の人物LoRAとトリガーを追加する。

- 衣装LoRA
- 服装
- その他のオプション項目

必要な内容がAI生成結果に含まれていない場合は、プレビューまたは反映後の出力を編集する。

## 7. 再利用するタグのまとまりを保存する

生成結果には、positive／negativeとは別に「再利用するタグのまとまり」が表示される。たとえば「黒髪ロングの女の子」という日本語名と、`1girl, black hair, long hair`という複数のDanbooruタグが一組の候補になる。

候補は生成しただけでは保存されず、最初はすべて未選択である。必要な候補だけにチェックを入れ、「選択した候補を保存」を押す。

- 保存先は、オプションの未分類にある「AIプロンプト」ブロックである。初回保存時に自動作成される。
- 保存後も自動的には選択されない。通常のオプションと同じように、使いたい候補を「AIプロンプト」ブロックから選ぶ。
- 保存した候補は、オプション管理画面で日本語名やタグ内容を編集したり、別のブロックへ移動したり、削除したりできる。
- 「AIプロンプト」ブロック自体はシステム管理のため、名前、カテゴリ、表示順、選択方式を変更できない。同名のブロックを自分で作成した場合、そのブロックは通常どおり編集できる。
- タグの順序、大文字・小文字、前後の空白だけが異なる同じ内容は重複として保存を省略し、結果に重複件数を表示する。
- 候補の保存と「既存の出力へ反映」は独立した操作である。候補だけ保存することも、保存せず出力だけへ反映することもできる。

保存に失敗した場合はチェックが残るため、そのまま再試行できる。「保存済みですが一覧の更新に失敗しました」と表示された場合、DBへの保存は完了している。ページを再読み込みして「AIプロンプト」ブロックを確認する。

ここで表示される英語タグは、AIが入力文から再利用しやすい意味のまとまりとして提案したDanbooru形式の候補である。厳密な公式タグであることや、すべての画像生成モデルで同じ効果になることは保証されない。日本語名とタグ内容を確認し、必要な候補だけを保存する。

## 8. エラーが表示された場合

### 指示を入力するよう表示される

空白以外の内容を入力する。2,000文字を超えている場合は、一枚のイラストに必要な説明へ絞る。

### プロンプト生成サービスを利用できないと表示される

次を確認する。

- 外部LLM APIが応答できる状態である。
- `ILLUSTRATION_LLM_BASE_URL`がLaravelの実行環境から到達できるURLである。
- `ILLUSTRATION_LLM_MODEL`が外部LLM APIで使用できるモデル名である。
- `.env`変更後に`php artisan config:clear`を実行した。
- 応答に時間がかかる場合、`ILLUSTRATION_LLM_TIMEOUT_SECONDS`が短すぎない。
- `ILLUSTRATION_LLM_NUM_PREDICT`が必要以上に大きく設定されていない。

この機能はプロンプト生成に不要な長い推論を避けるため、外部LLM APIへ思考モードを無効にする指定を送る。思考モードに対応するモデルでも、画面には最終的なpositive／negativeだけを返す。

### 生成サービスから不正な応答を受信したと表示される

外部LLM APIが要求されたJSON形式を返さなかった可能性がある。同じ入力で再試行し、繰り返し発生する場合は、使用モデルが構造化出力に対応しているか確認する。

### ボタンを押しても反応しない

配信用アセットが古い可能性がある。次を実行した後、ページを再読み込みする。

```sh
docker compose run --rm -T node npm run build
```

## 9. 保存とログについて

AI生成モーダルに入力した指示と生成結果は、候補を明示的に保存しない限りDBやファイルへ保存しない。入力全文、System Prompt全文、生成したpositive／negative全文を通常のアプリケーションログへ記録しない。

生成結果をクリップまたはお気に入りへ明示的に保存した場合は、それぞれの既存機能の保存対象になる。「選択した候補を保存」を押した場合は、選択した日本語名とタグだけがオプション項目として保存される。
