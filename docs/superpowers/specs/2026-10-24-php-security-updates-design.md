# PHPセキュリティ更新 設計

## 目的

未認証のリモートコード実行につながるCVE-2026-109618およびCVE-2026-109619の影響を受けるPHP 8.5.10を、修正版のPHP 8.5.12へ更新する。あわせて、既存のメジャーバージョンを維持したままComposer・npm依存を更新し、既知の脆弱性と古い依存を減らす。

## 対象

- DockerのPHPベースイメージを`php:8.5.12-fpm-bookworm`へ固定する。
- Composer依存を現在の制約内で更新する。
- npm依存を現在の制約内で更新する。
- `composer audit`および`npm audit`で既知の脆弱性を確認する。
- 更新後のPHPバージョン、静的検査、全テスト、Viteビルドを確認する。

## 対象外

- PHPUnit 13など、メジャーバージョンを越える依存更新。
- PHP 8.6など、PHPのマイナーバージョン変更。
- アプリケーション機能や業務仕様の変更。
- 実データ、永続ストレージ、ブラウザを使った確認。

## 検討した方法

1. PHPと脆弱なパッケージだけを更新する。変更は小さいが、同じ制約内の更新をまとめる機会を逃す。
2. PHPとComposer・npm依存を現在のメジャーバージョン内で更新する。安全性と互換性のバランスがよいため採用する。
3. PHPUnitなどのメジャー更新も含める。更新範囲と互換性リスクが大きくなるため今回は採用しない。

## 完了条件

- コンテナ内のPHPが8.5.12である。
- `composer audit --locked`と`npm audit`に既知の脆弱性が残らない。解消不能な場合は内容と理由を報告する。
- `sh scripts/check.sh`が成功する。
- `docker compose run --rm -T app composer test`が成功する。
- `docker compose run --rm -T node npm run build`が成功する。
- 作業ブランチへコミット後、`main`へマージし、マージ後にも必要な検証を行う。
