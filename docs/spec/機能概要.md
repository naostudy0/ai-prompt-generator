# 機能概要

## 目的と利用場面

画像生成ツールへ入力するpositive／negativeのプロンプトを、繰り返し入力する手間を減らして準備する。
利用者は普段使う文面を登録し、画面上部で必要な項目を選び、同じ画面で結果を確認・調整して、画像生成ツールのそれぞれの入力欄へコピーする。

## 最初に作る範囲

最初の選択項目はpositive／negativeそれぞれの「デフォルト」とする。
このデフォルトは、普段使う複数のタグを含む一まとまりの文章として扱う。
他の場所で見つけたプロンプトをそのまま貼り付けやすく、編集頻度も低いため、各側に一つのテキストエリアと一つの選択ボタンを設ける。
この編集形式はデフォルト項目に適用する。今後追加する項目の入力形式は、その利用目的に合わせて設計する。

| ID | 機能 | 達成する目的 | 設計書 |
| --- | --- | --- | --- |
| F01 | デフォルトプロンプトの登録・編集・取得 | いつもの文面をまとめて登録し、再利用できる | [F01](../design/features/F01-デフォルトプロンプト.md) |
| F02 | デフォルトの選択・プロンプトの表示 | 使う文面を選び、positive／negativeの結果を得られる | [F02](../design/features/F02-プロンプトの選択と表示.md) |
| F03 | 出力の編集・個別コピー | 今回必要な文面に調整し、画像生成ツールの各欄へ貼り付けられる | [F03](../design/features/F03-出力の編集とコピー.md) |
| F04 | プロンプト全体のお気に入り登録・呼び出し | 過去に用意したプロンプトを再利用できる | 詳細設計は今後作成 |
| F05 | LoRA・トリガー・服装の登録と選択 | ファイル名だけに頼らずLoRAを探し、対応する呼び出し文面を準備できる | [F05](../design/features/F05-LoRAの登録と選択.md) |

F01→F02→F03の順で設計を具体化し、実装・検証できる単位に分ける。F03のコピー動作は、画面内の出力文字列だけでも独立して検証できる。

## 確定している要件

- 個人利用とし、認証は設けない。デフォルトはアプリ内でpositive／negative各一つを管理する。
- 初期のデフォルト文面はSeederで登録する。
- 1ページ内の上部に選択欄、下部にpositive／negativeの出力欄を設ける。
- 入力欄は初見で入力側と分かる見出しを持ち、カテゴリごとに選択ボタンを並べる。初期はデフォルトのみとする。
- 出力欄は参考画像に寄せ、上の緑系positive、下の赤茶系negativeで貼り付け先との対応を示す。
- ページロード時、各側の「デフォルト」ボタンは選択状態で始まる。
- 各デフォルトボタンの近くに編集ボタンを置き、文面を追加・編集できる。
- デフォルトの編集は各側一つのテキストエリアで行い、空の文面も許容する。空にする操作で内容を削除できる。
- 選択後にボタンを押すと、同じ画面にpositive／negativeのプロンプトを表示する。
- 出力欄は編集可能なテキストエリアとし、個別の語句を手作業で消すなどの調整ができる。
- positive／negativeはそれぞれ個別にコピーできる。
- デフォルト文面はサーバー側のSQLiteに保存し、再読み込み後も取得できる。
- 保存時は`abc, def,`の形に整え、語句間のカンマの後に半角スペースを入れ、末尾にカンマを付ける。空の文面は空のままとする。
- カンマがない改行も区切りとして補完し、連続カンマによる空の要素と同一文面の重複を除去する。特殊記法は意味を壊さず扱える範囲で整形する。
- 出力ではセクション間に空行を一つ入れ、各文面のまとまりを見分けられるようにする。
- 出力欄の直接編集では保存済みデフォルトを変更しない。
- プロンプト全体をお気に入りとして登録し、過去のものを呼び出せるようにする。F01〜F03とは別の機能単位で詳細化する。
- LoRAはファイル名と利用者が付けた登録名を保存し、一つだけ選択できるようにする。
- LoRAのトリガーは登録名と文面を持ち、一つのLoRAに複数登録できる。選択できるトリガーは一つとする。
- 服装は登録名と文面を持ち、LoRAとの紐付けを任意にする。選択したLoRAに紐づく服装を上位に並べるが、それ以外の服装も選択できる。
- LoRAはフロント側で検索でき、複数行を常時表示する単一選択のリストから選ぶ。
- LoRAごとに0から1まで0.1刻みの推奨強度を保存し、初期値を1とする。LoRAタグは`<lora:ファイル名:強度>,`形式で出力する。
- トリガーと服装の文面には、デフォルトプロンプトと同じ整形規則を適用する。
- LoRA、トリガー、服装は追加・編集・削除できる。ファイル名の重複は禁止し、登録名の重複は許容する。
- 初期状態ではLoRA、トリガー、服装を選択せず、positiveにはデフォルト、LoRAタグ、トリガー、服装の順で出力する。

Seederの初期文面は[F01の初期データ](../design/features/F01-デフォルトプロンプト.md#初期データ)に定める。

## 画面構成案

配置・入力と出力の見分け方・参考画像との対応は[画面設計](../design/画面設計.md)に記載する。

```text
入力：使う項目を選ぶ
  positive → デフォルトカテゴリ → [デフォルト：選択中] [編集]
  negative → デフォルトカテゴリ → [デフォルト：選択中] [編集]

  編集中の側：positive または negative
  [デフォルト文面のテキストエリア]
  [保存] [キャンセル]

  [プロンプトを表示]

出力：画像生成ツールへコピー
  positive（緑系）   [編集可能なテキストエリア] [コピー]
  negative（赤茶系） [編集可能なテキストエリア] [コピー]
```

編集部分は編集ボタンを押したときに同じページ内で開き、保存・キャンセルで終了する。編集中は出力の表示操作を無効にする。配置と見た目は画面設計で調整する。
ボタンの表示文言「プロンプトを表示」は仮称。

## 確認事項

| ID | 決めること | 関係する機能 |
| --- | --- | --- |
| Q04 | お気に入りの登録対象・呼び出し先・識別方法 | F04 |

保存先はSQLite、出力の直接編集はデフォルトに反映しないことを確認済み（旧Q02）。
個人利用・認証なし、Seederの初期文面は確定。
出力は表示ボタンで反映し、直接手編集した出力も確認なしで作り直す。重複の完全一致比較、括弧全体の保護、Seederによる既存値の保持、空のセクションの除外、空欄のコピー無効化、複数タブでは最後の保存を優先する扱いも確定。
それ以外の設計上の提案は各設計書で「設計案」として区別する。

## お気に入りの概要

目的は、調整したプロンプト全体を保存し、後で呼び出して再利用できること。
普段使う部品としてのデフォルト文面と、出来上がったプロンプト全体を別の保存対象として扱う。
設計案は、登録時点のpositive／negativeの出力文面を一組で保存し、呼び出した文面を出力欄で再編集・コピーできる形とする。
一組で扱うか、選択状態も保存するか、名前や一覧でどう識別するか、呼び出し時に既存出力をどう置き換えるかは、F04の詳細設計で確認する。

## 将来の機能との境界

他の選択項目は、追加の要望に応じて目的・入力形式・結合順を定める。
今回の表示処理は登録文面と選択状態から文字列を用意する処理として設計する。
