# F19 プロンプトのクリップ

関連文書：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F03 出力の編集とコピー](F03-出力の編集とコピー.md)、[F04 お気に入りプロンプト](F04-お気に入りプロンプト.md)、[F10 セクションナビゲーションと選択概要](F10-セクションナビゲーションと選択概要.md)

## 目的と背景

利用者は、画像生成用プロンプトを少しずつ変えながら試す途中で、後から使うか判断できない文面を一時的に残しておきたい。
完成した内容を長期保存するお気に入りより少ない操作で現在の出力を退避し、必要になればすぐ呼び出し、不要ならすぐ削除できるようにする。

クリップは完成品の記録ではなく、同じタブ内での試行錯誤を支える一時保存とする。選択したタグやLoRAなどの選択状態は保存・復元せず、positive／negativeの出力文字列だけを扱う。

## 要件と範囲

| ID | 要件 |
| --- | --- |
| F19-R01 | 現在のpositive／negative出力を一組のクリップとして一時保存できる |
| F19-R02 | クリップへ名前を付け、右サイドメニューで識別できる |
| F19-R03 | クリップを呼び出すと、現在のpositive／negative出力を保存済み文字列へ置き換えられる |
| F19-R04 | クリップの呼び出しで、デフォルト、LoRA、トリガー、服装、オプションなどの選択状態を変更しない |
| F19-R05 | 不要なクリップを右サイドメニューから削除できる |
| F19-R06 | 同じタブでページを再読み込みしてもクリップを利用でき、タブを閉じた後は保持しない |
| F19-R07 | 複数のクリップを保存し、それぞれを個別に呼び出し・削除できる |

クリップの登録、一覧、呼び出し、削除を対象とする。名前や内容の編集、既存クリップへの上書き、画像添付、選択状態・選択概要・強度設定の保存、別タブや別端末との共有、長期保存は対象外とする。

## お気に入りとの差異

| 観点 | クリップ | お気に入り |
| --- | --- | --- |
| 目的 | 作業途中の文面を気軽に退避する | 後で再利用する完成プロンプトを残す |
| 保存期間 | 現在のタブを閉じるまで | 利用者が削除するまで |
| 保存先 | ブラウザーの`sessionStorage` | SQLiteとサーバー内ストレージ |
| 保存内容 | 名前、positive、negative、内部ID | 出力、選択状態、選択概要、名前、任意画像など |
| 呼び出し結果 | 出力欄だけを置き換える | 出力欄と復元可能な選択状態を置き換える |
| 操作場所 | 右サイドメニュー内で直接操作 | 出力付近の操作と一覧ダイアログ |

## 登録

右サイドメニューの「プロンプトを作成」ボタンの下に「クリップ」セクションを設ける。セクションの先頭に名前入力欄と「保存」ボタンを置き、その時点のpositive／negative出力欄の値を保存する。

positiveとnegativeが両方とも空の場合は保存できない。片方だけが空の場合は、空文字列を含む一組として保存できる。保存後も現在の出力と選択状態は変更しない。

名前入力欄には、現在のクリップ件数を基にした「クリップ N」を初期表示し、利用者が保存前に変更できるようにする。空白だけの名前では保存できない。前後の空白を除いて保存し、同名を許容して内部IDで区別する。名前は100文字以内とする。

保存操作ごとに新しいクリップを追加し、既存クリップを上書きしない。保存件数にはアプリケーション独自の上限を設けず、`sessionStorage`の利用可能容量まで複数保存できるようにする。

## 一覧・呼び出し・削除

保存済みクリップは保存順で並べる。各行に次を表示する。

- クリップ名
- 「呼び出す」ボタン
- 「削除」ボタン

プロンプト全文はサイドメニューへ常時表示しない。クリップ名は長い場合にサイドメニュー幅で折り返す。

「呼び出す」を押すと、保存したpositiveとnegativeで両方の出力欄を置き換える。片方が空文字列なら、その側の出力欄も空にする。コピー、お気に入り保存、人物LoRA差し替え、ComfyUI送信など、現在の出力欄を参照する既存操作は呼び出し後の文字列を使う。

呼び出し前後で入力側の選択状態と右側の選択概要を一切変更しない。そのため、呼び出し後の出力は現在の選択から生成される文面と一致しない場合がある。利用者がその後「プロンプトを作成」を押した場合は、既存仕様どおり現在の選択から生成した内容で出力を置き換える。

「削除」を押すと対象だけを削除する。削除によって現在の出力、選択状態、ほかのクリップは変更しない。作業途中の一時データであり再登録も容易なため、削除確認ダイアログは設けない。

## 画面配置

右サイドメニュー内を次の順にする。

```text
選択中
  現在の選択概要
  [プロンプトを作成]

クリップ
  [名前入力                ] [保存]
  クリップ 1       [呼び出す] [削除]
  別案             [呼び出す] [削除]
```

F10の右サイドメニューが表示される広い画面を対象とする。1,200px未満でサイドメニューが非表示になる間も`sessionStorage`内のクリップは削除せず、再び表示可能な幅にしたとき利用できるようにする。狭い画面専用のクリップ操作UIは今回の対象外とする。

保存・呼び出し・削除の結果はクリップセクション内の`role="status"`を持つ領域で通知する。クリップがない場合は「クリップはありません」と表示し、読み込み失敗と区別する。

## 保存形式とライフサイクル

サーバーへ送信せず、現在のページと同一オリジンの`sessionStorage`へJSONとして保存する。保存キーはアプリ固有かつ機能とバージョンを識別できる名前とし、ほかのブラウザー保存情報と衝突させない。

各クリップは次の値を持つ。

| 項目 | 内容 |
| --- | --- |
| `id` | 一覧操作で対象を識別するブラウザー内ID |
| `name` | 表示名 |
| `positivePrompt` | 保存時点のpositive出力全文 |
| `negativePrompt` | 保存時点のnegative出力全文 |

保存日時、選択状態、選択概要は保持しない。並び順は配列の順序で表す。

`sessionStorage`は同じタブの再読み込みでは保持されるが、タブを閉じるとそのページセッションとともに破棄される。別タブには共有しない。DB、サーバー内ストレージ、Cookie、`localStorage`には保存しない。

## フロントエンド設計

クリップの保存・形式検証・一覧操作を担当するJavaScriptモジュールを`resources/js/`へ追加する。DOM描画と`sessionStorage`への読み書きを分け、ストレージはテスト用実装へ差し替えられるようにする。

ページ初期化時に保存済みJSONを読み込み、配列と各項目の型を検証してから表示する。登録、呼び出し、削除はブラウザー内で完結し、API通信を行わない。

呼び出しではpositive／negativeを一つの操作として置き換え、既存の出力欄の`input`時と同じ状態更新を行う。これにより、空欄時のコピーボタン、お気に入り操作、人物LoRA差し替え、ComfyUI送信などの有効状態を現在値に同期する。選択状態を管理する各コントローラーや選択概要には更新を通知しない。

## 失敗時

- `sessionStorage`を利用できない、容量を超えた、または書き込みに失敗した場合は保存成功として一覧へ追加せず、現在の出力を維持して失敗を通知する。
- 保存済みJSONが壊れている、または期待する形式でない場合は不正な内容を表示・呼び出しせず、クリップを読み込めなかったことを通知する。自動的には上書きや削除をしない。
- 呼び出し対象が一覧更新前に存在しなくなった場合は、現在の出力を変更せず失敗を通知する。
- 削除の永続化に失敗した場合は一覧から消さず、再操作できる状態を保つ。

## 受入条件と検証

| 要件 | 前提／操作 | 期待結果 |
| --- | --- | --- |
| R01・R02 | positive／negativeがある状態で名前を付けて保存する | 名前と両方の出力が一つのクリップとして一覧へ追加される |
| R01 | positiveだけがある状態で保存する | positiveと空のnegativeが保存される |
| R01 | positive／negativeが両方とも空の状態で保存する | 保存されず、理由がクリップセクションに表示される |
| R03・R04 | クリップ保存後に出力と選択を変更してから呼び出す | 出力だけが保存済みpositive／negativeへ置き換わり、現在の選択と選択概要は変わらない |
| R03 | negativeが空のクリップを呼び出す | positiveが復元され、negative出力欄は空になる |
| R03 | クリップ呼び出し後にコピー、お気に入り保存、ComfyUI送信を行う | 各操作が呼び出した出力文字列を使用する |
| R04 | クリップを呼び出してから「プロンプトを作成」を押す | 選択状態は呼び出し前のままで、その選択から作った出力へ置き換わる |
| R05 | 二件のうち一件を削除する | 対象だけが一覧と`sessionStorage`から消え、現在の出力は変わらない |
| R07 | 異なる出力を三回保存する | 三件すべてが保存順に表示され、各クリップを個別に呼び出せる |
| R02・R07 | 同じ名前で二件保存する | 両方が別のクリップとして表示され、片方の呼び出し・削除がもう片方へ影響しない |
| R06 | 保存後に同じタブを再読み込みする | 保存したクリップが一覧へ再表示される |
| R06 | クリップを保存したタブを閉じ、新しいタブで開く | 閉じたタブのクリップは表示されない |
| R01 | `sessionStorage`への書き込みを失敗させる | 保存成功と表示せず、現在の出力と既存クリップを維持する |
| R03 | 壊れた保存データでページを初期化する | 不正な内容を出力欄へ反映せず、読み込み失敗を表示する |

JavaScript単体テストで保存形式、登録、呼び出し、削除、形式不正、ストレージ失敗を検証する。ページテストで右サイドメニューの操作、出力欄の置換、既存の選択状態を変更しないことを検証する。

## 設計上の判断

- 一時保存の寿命をタブのページセッションに合わせ、実装量を抑えながらお気に入りとの役割を分ける。
- 完成品の長期保存ではないため、選択スナップショット、画像、保存日時、編集・上書きを持たせない。
- 呼び出し時は出力だけを正本として復元し、現在の選択状態には触れない。
- 一覧ダイアログを開かず右サイドメニュー内で操作を完結させ、保存・呼び出し・削除の手間を減らす。
- サーバーへ保存しないため、Application、Domain、Infrastructure、HTTP APIは追加しない。

## 未決事項

実装を開始できない未決事項はない。クリップの並べ替え、編集・上書き、別タブ共有、`localStorage`またはDBによる長期保持、狭い画面用UIは、利用状況を見て別途検討する。
