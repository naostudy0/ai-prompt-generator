# F24 ComfyUI画像からのプロンプト復元

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F02](F02-プロンプトの選択と表示.md)、[F03](F03-出力の編集とコピー.md)、[F05](F05-LoRAの登録と選択.md)、[F08](F08-オプション項目の登録と選択.md)、[F09](F09-衣装LoRAの登録と複数選択.md)、[F12](F12-人物LoRAの系統と系統別デフォルト.md)、[F13](F13-ComfyUIへのキュー送信.md)、[F14](F14-人物LoRAの生成設定.md)、[F22](F22-AI生成タググループの保存.md)、[画面設計](../画面設計.md)。

## 目的

利用者は本アプリで作ったpositive／negativeをComfyUIへ送り、生成前後にComfyUI上で文面を調整する。後日その画像を基に作業を続ける際、完成時の文面を転記し、対応するLoRAやオプションを一件ずつ選び直す必要がある。

本機能は、このアプリに現在登録されているAPI形式ワークフローと同じ構造を持つComfyUI画像を読み込み、画像に記録された完成時のpositive／negativeを失わずに出力欄へ戻す。あわせて、全文一致する登録済み項目を選択状態へ復元し、未登録の文面を再利用可能なオプションとして追加する判断を助ける。構造照合は本アプリから実際に送信したことの証明ではなく、現在登録中のワークフローと可変入力以外が一致することの確認である。

画像内の完成文面を正本とし、登録項目から文面を再生成して置き換えない。これにより、ComfyUI上の調整、まだ登録していないタグ、登録後に変更された項目があっても、画像に記録された文面を失わない。

## 対象範囲

初期範囲はPNG画像一件の読み込み、登録ワークフローとの照合、完成文面のプレビューと反映、登録項目との照合、未登録文面からの通常オプション保存である。現在登録されている系統別ワークフローだけを照合対象とする。

次は対象外とする。

- 任意のComfyUIワークフローや、現在登録されていない過去のワークフローへの対応。
- JPEG、WebP等、PNG以外の画像形式への対応。
- 画像、解析結果、読み込み履歴の保存。
- 画像の画素内容の解析、画像認識、LLMによるタグ推測。
- 部分一致項目の自動選択。
- 未登録LoRAの自動登録。
- 複数画像の一括読み込み。
- 読み込んだ文面と現在の出力の自動マージ。

過去形式への対応が必要になった場合は、登録ワークフローの版管理または送信時のアプリ識別情報の埋め込みを別機能として設計する。

## 検討した方式

### 採用：登録ワークフローの構造照合

画像内のAPI形式ワークフローと、現在登録中の系統別ワークフローを比較する。送信時に本アプリが変更する入力位置の値を除外し、それ以外の構造と固定値が一致するワークフローを探す。一件だけ一致した場合に、その登録設定のpositive／negativeマッピングを使用する。

既存のワークフロー本体と入力マッピングを利用でき、画像、送信履歴、追加の外部識別子を保存せずに目的を達成できるため採用する。登録ワークフローを変更すると過去画像を読めなくなる可能性は、初期範囲では許容する。

### 不採用：送信時にアプリ識別情報を埋め込む

ワークフローの識別子や版を画像へ残せれば将来の照合は安定するが、ComfyUI側で確実に画像メタデータへ残る仕組みとワークフロー変更が必要になる。導入前の画像も扱えないため、初期実装には含めない。

### 不採用：送信履歴と画像を関連付ける

送信時のスナップショットを保存すれば復元精度を上げられるが、履歴の永続化、画像との関連付け、保持期間と削除の規則が必要になる。完成画像だけから作業を戻すという目的に対して過剰なため採用しない。

## 振る舞い

### 1. 画像を解析する

- **実行者・入力**：利用者が選択画面でPNG画像一件を指定し、「解析」を実行する。
- **事前条件**：画像が設定する上限以内であり、PNGとして解釈できる。
- **正常な流れ**：サーバーはファイルを永続化せず、PNGメタデータからComfyUIのAPI形式ワークフローを取得する。現在登録中の各系統のワークフローと照合し、一件に特定できた場合だけ設定済み入力位置からpositive／negativeを取得する。登録済み選択項目との照合結果を作り、現在の画面状態を変えずに返す。
- **出力**：ワークフローの一致結果、positive／negative、完全一致項目、部分一致項目、未登録文面、未登録または判別不能なLoRA。
- **事後条件**：画像、画像内JSON、解析結果を保存しない。現在の出力と選択状態は変わらない。
- **失敗**：メタデータがない、JSONとして不正、登録ワークフローに一致しない、複数に一致する、入力位置が存在しない、対象入力が文字列でない場合は反映可能な結果を返さない。

アップロード上限は実装計画前に、既存の画像アップロード上限と一般的なComfyUI出力サイズを確認して定める。業務上の理由なくF13のJSON上限5 MiBを流用しない。

### 2. 登録ワークフローと照合する

F13・F14でワークフローに属する役割とノードID・入力名が保存されている。比較時は次の役割に設定された入力値だけを可変値として除外する。

- positive
- negative
- seed
- checkpoint
- sampler
- scheduler
- output directory

可変入力の値以外は、ノードID、クラス種別、入力名、接続先、固定入力値を含めて比較する。JSONオブジェクトのキー順は意味を持たない。JSON送信時に`1.0`が`1`に整数化されるような、整数と数値として等しい有限小数の表現差は同じ固定入力として扱う。小数部分のある数値と整数、数値と文字列は別の値とする。配列の順序はワークフロー上の意味があるため維持する。登録側に存在しないノード・入力、画像側だけに存在するノード・入力、固定値の差は不一致とする。

一件も一致しない場合は「現在登録されているワークフローに一致しない」と示す。複数件に一致する場合は利用者へ系統を選ばせず、「ワークフローを一意に特定できない」として拒否する。系統とデフォルトの誤認を避けるためである。

### 3. 登録項目と照合する

positive／negativeを既存のプロンプト整形規則と同等の比較用表現へ正規化する。比較用正規化は、カンマ後の空白、改行、末尾カンマ等の表記差を吸収するために使い、出力欄へ反映する原文は変更しない。括弧や強調構文を壊す分割は行わない。

照合対象は次のとおりとする。

- 有効系統のpositive／negativeデフォルト。
- 人物・キャラクターLoRAと所属トリガー・服装。
- 衣装LoRAと所属トリガー。
- 通常のオプション項目と、項目に連動するnegative。

複数タグを持つ登録項目は、正規化後の全文が対象側に一つのまとまりとして含まれる場合だけ完全一致とする。一部のタグだけが含まれる場合は選択せず、部分一致候補にする。同じ文面が複数の登録項目に使われて選択対象を一意に決められない場合も、自動選択せず確認候補にする。

`single`のオプションブロックで複数項目が全文一致した場合は、同時に選択できないため全件を確認候補にする。連動negativeを持つオプション項目・服装・衣装LoRAトリガーは、positive側の登録文面と登録中のnegativeが画像内の各側にともに全文一致した場合だけ自動選択する。片側だけの一致は確認候補にする。

LoRAタグは通常文面とは分けて解析する。登録済みファイル名に一致する人物LoRAまたは衣装LoRAを候補とし、画像内の強度が既存仕様の0〜1かつ0.1刻みに一致する場合だけ、今回の選択強度として復元する。範囲外または刻みに合わない強度は丸めず、「登録済みLoRAだが強度を復元できない」として確認候補にする。人物LoRAと衣装LoRAの区分を一意に決められない、構文を安全に解析できない、またはファイル名が未登録の場合も自動選択しない。人物LoRAの所属系統が特定したワークフローの系統と異なる場合も自動選択しない。非表示の人物LoRAはF17のお気に入り復元と同じく選択せず、「登録済みだが現在利用不可」として示す。

完全一致項目が重なって同じタグを消費する場合は、より長い全文一致を優先しても利用者の登録意図を一意に復元できるとは限らない。このため初期版では競合する項目を自動選択せず、確認候補として示す。

### 4. 解析結果を確認して反映する

解析結果には、特定した系統、positive／negativeのプレビュー、自動選択できる項目数、確認が必要な部分一致、未登録文面、未登録または判別不能なLoRAを表示する。画像やワークフローJSON全文は表示しない。

利用者が「この内容を画面へ反映」を実行したときだけ、次を一つの画面操作として反映する。

1. 画像から取得したpositive／negative原文を出力欄へ設定する。
2. 特定した系統を今回の出力元系統として保持する。
3. 完全一致し一意に決められた登録項目だけを選択状態にする。
4. LoRA強度を復元できた場合は画像内の値を今回の強度へ設定する。
5. 部分一致と未登録文面を、反映後も確認できる案内として表示する。

現在の出力または選択状態が空でなければ、反映前に置き換わることを確認する。キャンセル時は現在状態を変えず解析結果を保持する。反映処理の途中で一部だけを適用せず、画面側で必要情報を検証してからまとめて状態を切り替える。

解析後、反映前に登録項目が編集・削除された場合は、現在の画面に存在し内容も一致する識別子だけを選択する。削除済みまたは内容が変わった項目を古い解析結果だけで選択せず、未登録または確認対象として扱う。

反映後に既存の「プロンプトを表示」を実行すると、選択状態から出力を再構築するため、未登録部分やComfyUI上の手編集が失われる可能性がある。未登録文面が残る間はその旨を表示し、再生成操作時に確認する。初期版では未登録文面を暗黙の選択項目として混ぜず、現在の出力を維持したい場合は再生成しないよう案内する。

### 5. 未登録文面を保存する

未登録文面は、括弧や強調構文を保護した既存の分割規則で安全に区切れるカンマ区切りのタグを一件ずつ候補にする。構文内部のカンマなど、安全に分割できない部分は一まとまりの候補として扱う。利用者は候補を一件または複数選び、登録名と保存先オプションブロックを入力して、選択した文面を一つのF08通常オプション項目として保存できる。F22のシステム管理グループへ自動保存せず、利用者が管理する既存ブロックへ明示的に追加する。文面には通常オプションと同じ整形・重複規則を適用する。

保存成功後は解析結果内で保存済みと示し、その項目を今回の選択状態へ対応付ける。ただし出力欄の原文は変更しない。同じ文面がすでに存在する、保存先が削除済み、入力エラー、通信失敗の場合は保存成功と扱わず、解析結果と出力を保つ。

部分一致候補は、そのまま新規保存させず、既存項目との差を確認できるようにする。既存項目を編集する操作はF08の管理機能へ案内し、本機能内では行わない。未登録LoRAも既存の人物LoRAまたは衣装LoRA管理へ案内し、本機能内で自動登録しない。

## 画面設計

選択画面の出力操作付近に「ComfyUI画像から復元」を置き、大型モーダルで画像選択、解析結果、反映操作を扱う。ブラウザーのファイル選択にはPNGだけを候補として指定するが、サーバーでも実体を検証する。

```text
ComfyUI画像から復元
  [PNG画像を選択] [解析]

  対応ワークフロー：Illustrious（一致）
  positive：読み取り済み [内容を表示]
  negative：読み取り済み [内容を表示]

  自動選択できる項目       12件 [詳細]
  確認が必要な部分一致      2件 [詳細]
  未登録の文面              4件 [選んで追加]
  未登録・判別不能なLoRA    0件

  [キャンセル] [この内容を画面へ反映]
```

positive／negativeの長文、部分一致、未登録文面は折りたたみまたはスクロール領域で確認できるようにする。件数だけで判断を要求しない。エラーはモーダル内に具体的に表示し、別画像を選び直せる状態を保つ。

反映ボタンには、現在状態が空でない場合の上書き確認があることを視覚的に示す。キーボード操作、フォーカス移動、モーダルを閉じた後のフォーカス復帰、状態を色だけに依存しない表示を既存モーダルと同じ基準で提供する。

## APIとアーキテクチャ

画像解析は状態を保存しない参照ユースケースとして`Queries`に置く。HTTP入口はmultipartのPNG一件を受け、解析結果DTOを返す。同じ要求内で画像を読み、レスポンス完了後に保持しない。PHPの一時アップロード領域からアプリの`storage`へ移動しない。

ワークフロー本文は既存の`ComfyUiWorkflowStore`を通して取得し、HTTP層やJavaScriptへ返さない。PNGメタデータ抽出はInfrastructureの専用ポート実装、ワークフロー構造照合と登録項目照合はApplicationから利用できる責務へ分ける。PNGチャンク形式やComfyUI固有のメタデータキーをドメインモデルへ漏らさない。

同一役割に複数の入力マッピングがある場合、画像内の対象値がすべて同じときだけその値を取得する。positiveまたはnegativeの同一役割内で値が異なる場合は、どれが完成文面かを推測せず解析失敗とする。

未登録文面の保存は新しい解析ユースケースへ混ぜず、F08の既存保存ユースケースを利用する。解析と保存を一つのトランザクションにせず、保存した候補ごとに結果を返す。

画像入力では、ファイルサイズ、MIME宣言だけでなくPNG署名、チャンク長、展開後メタデータ長、JSONの深さと要素数に上限を設ける。壊れたチャンク、過大な圧縮メタデータ、重複する対象メタデータ、循環を意図したような過度に深いJSONを安全に拒否する。具体的な上限は利用するパーサーの挙動を確認し、受入可能な架空fixtureと拒否する境界fixtureを用意してから決定する。

通常ログにはrequest ID、結果コード、一致件数、分類ごとの件数だけを残せる。ファイル名、画像本文、画像メタデータ、ワークフローJSON、positive／negative、登録項目の文面は残さない。

| R06・R08 | 登録済みLoRAの強度が0.85、1超、負値のいずれかである | 原文を保持し、LoRAを自動選択せず強度を復元できない確認候補として示す |
| R08 | 非表示の登録済み人物LoRAを含む | 自動選択せず、登録済みだが現在利用不可と示す |
| R09 | 未登録文面を選び、登録名と保存先を指定する | 通常オプションとして保存され、出力原文を変更しない |
| R09 | 安全に分割できる三つの未登録タグから二つを選ぶ | 選んだ二タグを一つの通常オプション項目として保存できる |
| R10 | 既存出力がある状態で反映する | 上書き確認を表示し、キャンセルすれば既存状態を保つ |
| R05・R07 | 解析後に完全一致した登録項目を削除してから反映する | 削除した項目を選択せず、出力原文を保持する |
| R11・R12 | 解析成功後と失敗後を検査する | 永続ストレージと通常ログに画像・プロンプト・JSON本文が残らない |
| R01 | PNGでないファイル、メタデータなし、壊れたPNG、上限超過を送る | 内容を反映せず、利用者が修正できる具体的なエラーを返す |

受入試験には、実際の保存画像や実データを使用せず、テスト用ワークフローと架空のpositive／negativeを埋め込んだPNG fixtureを新規作成して使用する。

## 設計上の判断

- 画像内の文面を正本にする。選択状態は文面を説明し再利用を助ける補助情報であり、復元時に原文を書き換えない。
- 自動選択は完全一致かつ一意な場合だけにする。未選択より誤選択の方が、その後の再生成で意図しないタグを追加する危険が大きいためである。
- 対応可否を利用者の申告やファイル名で決めず、保存済みワークフロー構造で検証する。
- 現在登録中のワークフローだけを対象にする。履歴や版管理を初期範囲へ加えず、必要性が明らかになった時点で拡張する。
- 画像は保存しない。本機能は画像管理ではなく、画像から作業状態を戻すための一時的な解析である。
- 解析と画面反映を分ける。入力を選んだだけで現在の作業を失わないようにする。
