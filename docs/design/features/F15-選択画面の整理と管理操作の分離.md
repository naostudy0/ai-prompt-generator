# F15 選択画面の整理と管理操作の分離

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[画面設計](../画面設計.md)、[F05](F05-LoRAの登録と選択.md)、[F08](F08-オプション項目の登録と選択.md)、[F10](F10-セクションナビゲーションと選択概要.md)、[F11](F11-人物LoRAの差し替えコピー.md)、[F17](F17-人物LoRAの非表示.md)、[構成判断](../../decisions/0003-フロントエンド構成の継続.md)。

## 目的と背景

個人利用者が多数のオプションと数百件の人物LoRAを扱っても、必要な候補を探して選べるようにする。選択画面は三列構成を維持し、左の長いナビゲーションと中央の大量のタグを整理する。分類・登録・並べ替えは、三列の幅に制約されない専用管理ページで行う。

## 調査と提案

2026-10-04に以下の原資料を確認した。一般的な指針と、このアプリへの適用判断を区別する。

| 参考資料 | 指針の要旨 | 本アプリへの適用案 |
| --- | --- | --- |
| [NN/g：Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) | 高度な操作や頻度の低い操作を必要なときに提示する | 選択と登録内容の管理を分離する |
| [NN/g：Accordions on Desktop](https://www.nngroup.com/articles/accordions-on-desktop/) | 折りたたみには情報を隠す代償があり、利用場面で判断する | 全部を閉じず、選択概要と件数を見出しに残す |
| [GOV.UK：Pagination](https://design-system.service.gov.uk/components/pagination/) | 操作性・性能が改善する場合に一覧を分割し、無限スクロールを避ける | 人物候補に明示的なページ切り替えを置く |
| [W3C：Accordion](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/)／[Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) | 開閉状態の通知、キーボード操作、ダイアログ内のフォーカス管理を定義 | 開閉ボタンと管理パネルの操作契約に適用する |

| 方式 | 利点 | 課題・判断 |
| --- | --- | --- |
| 現画面の編集モード | 位置関係を保って変更できる | 大量候補と並べ替えの長い画面は残る。第一候補にしない |
| 専用管理ページ | 選択画面から管理操作を除き、画面幅を使って一覧・編集・移動できる | 管理に入る一操作が増える。今回の推奨 |
| 中央を一セクションだけに切り替える | 表示量を最も減らせる | 複数ブロックを見比べにくい。初回は採用しない |
| 折りたたみだけを追加 | 変更が小さい | 開くと大量の管理ボタンが残る。管理分離と併用する |
| 人物LoRAの画像カード | 見た目で識別できる | 画像登録が新たに必要で密度も下がる。今回は対象外 |

これらは資料がこのアプリの最適解を保証するものではなく、現在の「候補を組み合わせる」作業への設計判断である。

## 要件とスコープ

| ID | 要件 |
| --- | --- |
| F15-R01 | 左のオプションブロックを利用者定義の一段のカテゴリへ分類できる。左サイドメニューでカテゴリをまたいでブロックをドロップした場合も所属を変更できる |
| F15-R02 | 通常画面に項目ごとの編集・削除・移動ハンドルを並べず、管理入口を明示する |
| F15-R03 | 選択画面のグループと中央の各セクションを開閉でき、それぞれの左側の三角マークで開閉状態が分かる。グループ名をセクション名より大きく表示し、両者の三角マークの色を分ける。グループ間は明確な実線、セクション間は薄い点線で区切る。グループ見出しに選択件数を表示せず、セクション見出しでは閉じても選択中の登録名を確認できる |
| F15-R04 | 専用管理ページで追加・編集・並べ替え・移動を行える |
| F15-R05 | 数百件の人物LoRAを検索・系統フィルター・ページ分割で探せる |
| F15-R06 | 検索・ページ変更・開閉で選択と表示済み出力を変更しない |
| F15-R07 | 右の選択概要、表示・コピー・送信と狭い画面での操作を維持する |

対象は既存の選択ページの表示整理と、オプション用の専用管理ページ。新しいSPA基盤、人物画像、利用頻度ランキング、階層カテゴリ、オプション項目のカテゴリの重複所属は対象外。

## ユースケース

実行者はいずれも個人利用者とする。

1. **分類する**：選択画面から専用管理ページへ移動し、カテゴリ名を登録し、ブロックの所属カテゴリを選んで保存する。成功後は選択画面の左と中央のカテゴリ表示に反映する。
2. **選ぶ**：左のカテゴリを開き、ブロック名を押す。中央の対象セクションを開いて移動する。候補を選んだ後、閉じても登録名を確認できる。検索に一致しない選択は独立した「選択中」欄へ残す。
3. **管理する**：「オプションを管理」から専用ページへ移動する。項目を編集・移動し、一操作ごとに保存する。「選択画面に戻る」で管理ページから戻る。
4. **人物を探す**：系統と検索文字列を指定し、ページを移動して一件を選ぶ。現在の人物は検索結果とは別に常時表示する。取得失敗を「該当なし」と混同しない。

## 業務ルール

- カテゴリはブロックを整理する単位であり、既存のブロック内の単一／複数選択規則を変更しない。一つのブロックはカテゴリ一つまたは未分類に属する。
- カテゴリ名は前後空白を除いて必須、同名を許容しIDで識別する。未分類はシステム表示で、カテゴリレコードとして作らない。
- **提案：分類と出力順を分離する。** カテゴリ変更は既存のブロック出力順を変えない。カテゴリ表示順は独立に保存し、カテゴリ内は既存ブロック順を使う。中央もカテゴリでまとめるため、カテゴリをまたぐ画面順と出力順は一致しない場合がある。管理に「プロンプト出力順」を表示して明示する。
- カテゴリを削除しても所属ブロック・項目は削除せず、未分類へ戻す。カテゴリと所属変更を同じトランザクションで行う。
- 通常画面と左メニューからドラッグ操作を除く。ブロック全体の出力順、項目順、ブロック間移動は管理で行う。F08の選択移動規則を維持する。
- 全体リセットは既存の選択・出力のリセットに加え、人物フィルターを全系統・検索空・先頭ページへ戻し、人物セクションを開く。カテゴリ、順序、非表示設定は変更しない。

## ドメイン・責務

`OptionCategory`は名前とカテゴリ表示順を守る小さな登録モデル。`OptionPromptGroup`は任意のcategory IDを参照する。カテゴリ所属と並び更新は`Application/PromptPreparation/Writes`、カテゴリ付き一覧は`Queries`からDTOを返す。既存の選択状態の正本は各JavaScriptモジュールに残し、左右メニューと管理画面はその投影とする。

画面開閉、検索、ページ番号、未保存入力はブラウザーの表示状態であり、ドメインの保存項目へ混ぜない。

## 画面・API

```text
左：セクション            中央：選ぶ                      右：現在の選択
 デフォルト               人物LoRA [管理]                （現行を維持）
 人物LoRA                  現在の人物／強度
 衣装LoRA                  [検索] [系統] 候補一覧 [前/次]
 ▼人物表現              ▼ 表情（笑顔、赤面） [管理]
   表情                      選択中：笑顔、赤面
   視線                      [検索] 候補ボタン
 ▶場面                  ▶ 視線（正面） [管理]
 ▶未分類                   [プロンプトを表示] [リセット]
                           positive / negative出力
```

- 左は固定入口＋カテゴリ開閉＋ブロック。カテゴリ名自体は開閉、ブロック名は移動を行う。ブロックを別カテゴリのブロックまたはカテゴリ領域へドロップすると所属カテゴリを変更し、同じカテゴリ内へのドロップは従来どおり出力順を変更する。左と中央のカテゴリ見出しは、左側に閉じた状態の`▶`、開いた状態の`▼`を表示する。中央も「カテゴリの開閉＞ブロックの開閉＞候補」の二段階とする。左と中央の開閉状態は独立で、左から移動すると対象の中央カテゴリ・ブロックを開く。
- 中央では外側のカテゴリを「グループ」、その配下のオプションブロックを「セクション」として見せる。グループ名はセクション名より大きくする。セクション見出しの左にも閉じた状態の`▶`、開いた状態の`▼`を表示し、グループ用と異なる色で階層を区別する。
- 中央のグループ同士は視認性の高い実線と余白で区切る。同じグループ内のセクション同士は、グループ境界より薄い点線と余白で区切る。境界線の強さで外側と内側の階層を示す。
- 中央のグループ見出しには選択件数や未選択状態を表示しない。
- 中央のセクション見出しは、選択中の登録名を併記するが、セクションごとの選択数は表示しない。未選択の場合は「未選択」と表示する。
- 初回はデフォルト・人物LoRA・衣装LoRAを開き、オプションは見出しと選択中欄を表示し候補を閉じる。複数セクションを同時に開ける。開閉状態はページ内で保持する。
- 通常の候補ボタンは登録名と選択状態のみ。全文は詳細表示で確認し、各項目に管理アイコンを置かない。
- 選択中に必要な候補がない場合に備え、通常画面の各ブロック内に項目追加だけを残す。ここから追加した項目は保存後そのまま選択し、単一選択ブロックでは従来の選択を置き換える。編集・削除・移動とブロック追加は管理ページで行う。
- 管理ページは`/prompt-options/manage`で表示する。三列レイアウトを使わず、最大幅は選択画面の左右サイドメニューを含む全体幅と同じにする。項目の並べ替えはドラッグ、ブロック間移動は移動先選択、カテゴリ順とブロック出力順は上下操作で行う。
- 管理ページのカテゴリ一覧は、カテゴリ名、所属ブロック数、操作を独立した列に配置する。カテゴリ名の文字数が異なっても、所属ブロック数と操作の表示位置を行ごとにずらさない。
- 保存中は対象更新を無効にする。編集フォームの保存またはキャンセルで操作を完結させ、保存済み操作を一括取消する方式にしない。
- 狭い画面でも中央のカテゴリ開閉と管理入口を表示する。管理ページは一列に切り替え、操作ラベルと順序を維持する。
- 開閉は見出し内button、`aria-expanded`、`aria-controls`を使用する。管理ページの入力にlabelを付け、アイコンの編集・削除操作には内容を示すアクセシブル名を付ける。

### 大量候補の表示

人物LoRAは登録名・ファイル名の大文字小文字を区別しない部分一致、系統は全系統または一系統。登録名・IDの安定順を使う。既存APIから取得したデータをブラウザーで絞り込み、**1ページ30人物**を描画する。30は表示量を抑えるUI値であり登録上限ではない。取得件数が性能問題になった場合はサーバーページングを再設計する。

差し替え一覧も人物単位で30件ずつ表示し、人物行を開くと所属トリガー候補を表示する。全組み合わせの候補キーとコピー・送信能力は残す。候補文面は操作対象だけを生成し、全件の全文を事前描画しない。

選択、チェック、送信結果はID／候補キーで保持しページ間で失わない。F13の「全選択／全解除」は検索とページに関係なく全表示対象候補へ適用し、文言を「表示可能な全候補を選択／解除」とする。総対象数と現在ページ数を区別し、送信前には現在の絞り込み外のチェック数も示す。F17の非表示候補は常に除外する。

### API案

| 操作 | 契約 |
| --- | --- |
| 分類一覧 | `GET /prompt-option-categories` → `categories: [{id,name,position}]` |
| 分類追加 | `POST /prompt-option-categories`、`name` → 201と追加カテゴリ |
| 分類改名 | `PUT /prompt-option-categories/{category}`、`name` → 200 |
| 分類移動 | `PATCH /prompt-option-categories/{category}/position`、`beforeCategoryId`（nullで末尾）→ 200と確定順 |
| 分類削除 | `DELETE /prompt-option-categories/{category}` → 204、所属を未分類へ |
| ブロック所属変更 | `PATCH /prompt-option-groups/{group}/category`、`categoryId`（nullで未分類）→ 200と確定ブロック |
| 既存一覧拡張 | `GET /prompt-options`の各groupへ`categoryId`を追加 |

JSONは既存の包み形式と入力エラー形式に合わせる。存在しない対象は404、不正な入力は422、セッション期限切れは419、障害は5xx。個人利用・認証なし、同一オリジン・Webミドルウェア・CSRF保護を維持する。API URLはBladeから渡す。管理入口の非表示はアクセス制御ではない。

## 永続化と失敗時

`option_categories`にID、name、position、timestampsを保存。positionはカテゴリ全体で一意・連続。既存`option_prompt_groups`にnullableな`option_category_id`を追加し、既存ブロックはすべて未分類へ移す。カテゴリ案の「人物表現」「場面」等を自動割当しない。名前・選択方式・ブロック順・項目順・IDを保持する。

カテゴリ順更新は影響順序を一トランザクションで保存する。所属更新とカテゴリ削除の競合は同じカテゴリ行のロックと外部キーで守る。削除時は所属をnullへ戻す。最後の確定更新を採用する既存方針を維持する。

通信失敗では入力・選択・出力を保持し、並べ替えは直前へ戻す。応答順序を識別して古い取得結果で新しい表示を上書きしない。更新成功後の再取得だけが失敗した場合は保存失敗と表示せず、保存済みであることと再読み込みが必要なことを通知する。結果不明の更新は自動再送せず、再取得で確定状態を確認する。ブロックの内容編集とカテゴリ所属変更は同じブロック行をロックし、並行更新で一方を古い値に戻さない。

## 受入条件と検証

| 要件 | 前提／操作 | 期待結果 |
| --- | --- | --- |
| R01 | 既存ブロックをカテゴリへ移し再読込 | 左・中央で分類され、選択方式・項目・出力順は変わらない |
| R01 | 左サイドメニューで未分類のブロックを別カテゴリへドロップ | 所属が保存され、左・中央の両方で移動先カテゴリに表示され、ブロックの出力順は変わらない |
| R01 | 所属ブロックのあるカテゴリを削除 | ブロックは未分類へ戻り、項目を失わない |
| R02・R04 | 通常表示から管理ページへ移動し項目を移動 | 通常画面に管理ハンドルがなく、管理ページでドラッグにより順序を変更できる |
| R04 | 文字数の異なる複数カテゴリを管理ページで表示 | 各行の「○ブロック」と操作ボタンが、カテゴリ名の長さにかかわらず同じ列位置に揃う |
| R03・R06 | 選択したブロックを閉じ、左から開く | 選択中の登録名が残り、ブロックごとの選択数は表示されず、再び候補へ移動できる |
| R03 | 選択画面のカテゴリを開閉 | 見出し左側のマークが閉じた状態の`▶`と開いた状態の`▼`に切り替わる |
| R03 | 選択画面のグループとセクションを表示・開閉 | グループ名がセクション名より大きく、両者の三角マークは異なる色で表示され、それぞれの開閉に応じて`▶`と`▼`が切り替わる |
| R03 | グループとセクション内の選択を変更 | グループ見出しに選択件数や未選択は表示されず、セクション見出しには選択中の登録名または未選択が表示される |
| R03 | 複数のグループと、同じグループに複数のセクションがある | グループ間は明確な実線、セクション間はより薄い点線で表示され、両者の境界を判別できる |
| R05・R06 | 500人物で検索し2ページ目を選ぶ | 一致一覧を分割表示し、ページ変更後も現在人物を確認できる |
| R05 | 複数トリガー候補を別ページでチェック | チェックと送信結果が保持され、全対象件数を確認できる |
| R06 | 管理保存失敗／未保存で閉じる | 入力と出力を保持し、失敗表示／破棄確認で回復できる |
| R07 | 狭い画面とキーボードのみで選択・管理 | 同じ選択・保存・コピー操作が可能でフォーカスを失わない |

実装時はカテゴリHTTP・DB整合性、表示投影の検証、実配信画面での探索・開閉・編集・ページ切り替えを確認する。静的チェック、関連テスト、Viteビルドは実装時に実施する。

## 未決事項・実装開始条件

- UI方式は本書の推奨案。カテゴリ内をまとめた表示と、分類に依存しない出力順の分離を利用者へ提示する。分類順を出力順にもしたい場合は、既存順の変更・移行方針を確認してから実装する。
- 初期カテゴリ名は利用者が登録する。30件の表示量は検証で調整可能なUI判断とする。
- F16・F17の確認事項はそれぞれの文書に定める。
