# F11 人物LoRAの差し替えコピー

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F02](F02-プロンプトの選択と表示.md)、[F03](F03-出力の編集とコピー.md)、[F04](F04-お気に入りプロンプト.md)、[F05](F05-LoRAの登録と選択.md)、[F09](F09-衣装LoRAの登録と複数選択.md)、[画面設計](../画面設計.md)。

## 目的と背景

利用者が同じ衣装・構図・表情などを複数の人物・キャラクターLoRAへ当てた仕上がりを比べる際に、人物LoRAと所属トリガーを一件ずつ選び直してプロンプトを生成する手間を減らす。

今回の出力を基に複数の人物LoRAへ差し替えたpositiveを一覧から続けてコピーできるようにする。画像生成そのものや複数LoRAを一つのpositiveへ同時に追加する機能ではない。

## 要件

| ID | 要件 |
| --- | --- |
| F11-R01 | 出力を用意した後に、人物LoRA差し替え用の一覧を同じ画面で開ける |
| F11-R02 | 登録済みの人物・キャラクターLoRAを登録名とファイル名で識別でき、トリガーがある場合は使用するトリガーも分かる |
| F11-R03 | 一件を操作すると、元の人物LoRAタグと一致する元トリガーを候補の初期強度のタグ・先頭トリガーへ差し替えたpositiveをコピーできる |
| F11-R04 | 出力欄で手編集した文面、衣装LoRA・そのトリガー・服装・オプション・デフォルトなど、差し替え対象以外の文面とnegativeを変えない |
| F11-R05 | 複数の候補を続けてコピーでき、コピー元の出力と入力画面の選択状態を変更しない |
| F11-R06 | コピー失敗や安全に差し替えられない場合に誤った文面をコピーせず、理由を確認できる |

## 対象範囲

人物・キャラクター用途の既存LoRAを候補にする。候補の取得にはF05の参照APIで得られるLoRA、推奨強度、所属トリガーを利用し、生成とコピーはブラウザー内で行う。候補数に応じて一覧をスクロールでき、登録名・ファイル名の検索を付ける。通常は一覧の各行を直接コピー操作にするため、候補選択とコピーを二画面に分けない。

衣装LoRAは差し替え対象に含めない。候補LoRAの登録・編集、コピー結果の一括保存、画像生成ツールへの自動送信、全候補の一括クリップボード書き込みは対象外とする。コピー結果をお気に入りに保存する場合は、別途F04の通常操作で出力欄に反映する設計が必要になるため、本機能からは行わない。

## ユースケース：人物LoRAを差し替えてコピーする

- **実行者・入力**：利用者がpositive出力を用意し、「人物LoRAを差し替えてコピー」を押す。続いて候補一覧の一件を押す。
- **事前条件**：positive出力欄にコピー元となる文面があり、人物LoRA候補の取得が成功している。候補のファイル名と強度からLoRAタグを作れる。
- **正常な流れ**：開いた時点の手編集を含むpositiveとnegative、今回の人物LoRA・トリガー、および候補一覧を固定する。人物LoRA候補を一覧に表示する。候補を押すたびに、元の人物LoRAタグと完全一致する元トリガーを除き、候補の推奨強度のタグと先頭トリガーを同じ位置に入れてクリップボードへ渡す。成功した候補を通知し、一覧は開いたままにする。
- **出力・事後条件**：クリップボードには押した候補のpositive全文が入る。画面のpositive／negative出力欄、今回選択中の人物LoRA・トリガー・服装やその他の選択、お気に入りは変更しない。
- **例外**：候補取得・クリップボード書き込み・差し替え可能性の検証に失敗したときはコピーせず、元の文面と選択状態を保って、再取得または手動操作を案内する。

## 差し替えの規則

コピー元はモーダルを開いた時点のpositive出力欄そのものとし、生成後の手編集も保持する。元の人物LoRAタグと元トリガーの完全一致する文面だけを除き、候補LoRAの推奨強度（登録時の初期値）のタグと、所属トリガー一覧の先頭の文面を同じ位置へ入れる。元の人物LoRAがない場合は、F05の出力順に従い、デフォルトの後・衣装LoRAの前に候補のセクションを挿入する。元のトリガーがない場合は候補のトリガーを追加し、候補にトリガーがない場合は人物LoRAタグだけを入れる。候補のトリガー本文は保存済みの文面を使用し、再整形しない。

人物LoRAとトリガーの区間を、同じ文字列が他のセクションにもあるという理由だけで全文置換しない。元の出力を組み立てた際の人物セクション位置と元のタグ・トリガー本文を保持し、現在の出力欄の対応位置で一致する文面だけを対象にする。元トリガーが一部でも書き換えられて一致しない場合、その手編集部分は検知・除去せずに残し、候補のトリガーを追加する。人物LoRAタグ自体が一致せず安全に位置を特定できない場合はコピーを止めて理由を示す。差し替え箇所以外の空白・改行・重複除去済みの文面を再生成・再整形しない。

候補一覧には現在選択中の人物LoRAも含める。登録名が重複していてもファイル名で区別できる。候補の強度は候補LoRAの推奨強度を使い、トリガーが複数ある場合はF05と同じ登録名・ID順の先頭トリガーを使う。各候補のコピー結果は独立し、前回コピーした候補のタグが次のコピー元にならない。

## 画面と操作

出力欄のpositive／negativeカードの後、お気に入り操作の近くに「人物LoRAを差し替えてコピー」ボタンを置く。positive出力が空、または人物LoRA候補の取得前・取得失敗時は利用できない理由を示す。

ボタンでモーダルを開き、登録名・ファイル名で絞り込める縦スクロール一覧を表示する。各行には登録名、ファイル名、採用する強度、採用するトリガー名を簡潔に示し、行全体または明確なコピー操作でその候補のpositiveをコピーする。トリガーがない候補はLoRAだけと示す。長いプロンプト全文は一覧に載せない。`aria-label`には候補名とコピー操作を含め、キーボードでも選べるようにする。

コピー成功時は既存の中立色トーストで候補名を通知する。失敗時はモーダル内に理由を示し、モーダルと検索結果を保つ。モーダルを閉じても出力欄は変えない。negativeは全候補で同じため、既存のnegativeコピーボタンから一度コピーする。候補を多数まとめて事前生成する必要はなく、押された一件だけを生成してコピーする。

## モデル・入出力・永続化

本機能は既存のLoRA参照結果とブラウザー内の現在の出力を利用する、保存を伴わない操作とする。新しいDBテーブル、更新API、保存用集約は設けない。既存の`GET /lora-prompt-options`が取得失敗したときは、空の候補一覧として扱わない。画面側は候補データの検証、人物セクションの差し替え、コピーの三つを分け、差し替え結果を純粋な文字列処理として検証できるようにする。

## 受入条件

| 要件 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| R01・R02 | positiveを表示して差し替えモーダルを開く | 登録済み人物LoRAが登録名・ファイル名とともに一覧表示される |
| R03・R04 | 人物LoRA、トリガー、衣装LoRA、服装、構図を含むpositiveから別の人物LoRAを選ぶ | コピー文面では人物タグとトリガーだけが候補用に変わり、残りの文面とnegativeは元のままになる |
| R03・R04 | 出力欄の人物以外の文面を手編集してから候補を選ぶ | 手編集した文面と元の衣装LoRAを保持し、人物タグと一致する元トリガーだけを候補用に差し替える |
| R03・R04 | 元トリガーを一部書き換えてから候補を選ぶ | 書き換えた部分はそのまま残り、候補の先頭トリガーが追加される |
| R03 | コピー元の人物LoRAを推奨値以外の強度で生成し、別の候補を選ぶ | コピー文面では候補LoRAの推奨強度を使う |
| R03 | トリガーがない候補を選ぶ | コピー文面に候補のLoRAタグを含み、元の人物トリガーは残らない |
| R03 | 元の人物LoRAがない出力から候補を選ぶ | 出力順に合う位置へ候補タグと必要なトリガーが挿入される |
| R05 | 二つの候補を続けて押す | 各コピー結果は最初に開いたコピー元を基準にし、出力欄と入力画面の選択は変わらない |
| R05 | 同じ登録名の候補が複数ある | ファイル名で区別でき、押した候補のタグをコピーする |
| R06 | クリップボード書き込みが失敗する | 成功通知を出さず、コピー元と候補一覧を保持して手動操作を案内する |
| R06 | 元の人物LoRAタグを手編集し、対応位置を安全に特定できない | コピーせず、元の出力と選択状態を保って理由を示す |
| R06 | モーダル表示中に検索する | 候補表示だけが変わり、出力文面と選択状態は変わらない |

## 設計上の判断

- 選択した候補を一件ずつコピーする方式を採る。通常の候補選択とコピーに通信は不要で、候補数が増えても押した一件だけを処理できるため、二画面の選択フローは用意しない。
- 差し替えるのは人物LoRAとトリガーだけとし、LoRAに所属する服装であっても現在の文面を残す。別人物で同じ衣装・構図を比較する目的を優先し、元LoRAとの所属の違いによって服装を削らない。
- 元トリガーの手編集部分は完全一致しなければ除去しない。手編集した文面を勝手に消さないための仕様であり、その部分と候補トリガーが両方残ることがある。
