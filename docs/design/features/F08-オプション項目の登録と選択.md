# F08 オプション項目の登録と選択

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F01](F01-デフォルトプロンプト.md)、[F02](F02-プロンプトの選択と表示.md)、[F07](F07-場所と構図と動作の登録と選択.md)、[画面設計](../画面設計.md)。

## 目的と背景

利用者が、専用カテゴリを増やすほどではない細かな指定を必要な数のグループに分け、今回の画像に必要なものを探してpositiveプロンプトへ反映できるようにする。

プロンプトには、表情・視線・服装・動作・場所・構図のいずれにも収めにくい細かな指定が多数ある。すべてを一つのオプション欄に置くと候補が増えたときに探しにくい一方、必要なグループ数は利用前に固定できない。そのため、利用者が「オプション1」「オプション2」…というブロックを必要に応じて追加し、各項目を一つのブロックへまとめられるようにする。

## 要件

| ID | 要件 |
| --- | --- |
| F08-R01 | オプション項目に登録名と一つ以上のタグを含む文面を保存できる |
| F08-R02 | 登録名を表示するバッジから、オプション項目を複数選択・選択解除できる |
| F08-R03 | オプション項目を追加・編集・削除できる |
| F08-R04 | 選択したオプション項目を安定した順序でブロックごとのpositiveセクションへまとめる |
| F08-R05 | 出力時に完全一致するタグの重複を除去し、括弧付きなど表記が異なるタグは残す |
| F08-R06 | オプションブロックを任意の数だけ追加し、追加順に表示できる |
| F08-R07 | 各オプション項目を一つのオプションブロックに所属させる |
| F08-R08 | 既存のオプション項目を最初の「オプション1」へ引き継ぐ |

## 選択画面の振る舞い

positive側に、追加順で「オプション1」「オプション2」…と表示するブロックを縦に並べる。最初のブロックは常に存在し、利用者は「オプションを追加」操作で末尾にブロックを追加できる。追加できる数に業務上の上限は設けない。

各ブロックには、そのブロックに所属する候補だけを登録名バッジとして表示する。バッジを押すたびにその候補の選択・選択解除を切り替える。同じブロックと異なるブロックのどちらでも複数候補を同時に選択でき、選択数に上限は設けない。

選択状態は色、チェック表示、`aria-pressed`で示す。編集・削除は選択バッジとは別の管理操作として見分けられる外観にする。候補領域には複数行分の高さを確保し、候補が領域を超えた場合は縦にスクロールする。ページロード時と新規登録後は未選択とする。

ブロックは保存された表示順、ブロック内の候補は登録名の昇順、同じ登録名ではIDの昇順に並べる。この順序を画面表示と出力結合の共通順序とし、選択した順番によって出力結果を変えない。今回は検索を設けず、候補数が増えて一覧性が不足した場合に利用状況を基に別途設計する。

ブロックの表示名は保存された表示順から自動的に作り、自由入力にはしない。今回の変更ではブロックの名称変更、並べ替え、削除を扱わない。項目の追加フォームは操作元のブロックを保存先として固定し、編集による別ブロックへの移動も扱わない。

## ユースケース

### オプション項目を登録・編集する

利用者は対象ブロックの管理操作から入力フォームを開き、登録名と文面を入力して保存する。新規項目は操作元のブロックに所属する。サーバーは入力形式、対象ブロックの存在、不変条件を検証し、文面を整形して保存する。成功後は一覧を再取得し、編集した候補が選択中なら選択を維持する。失敗時は入力内容、ブロック一覧、選択状態を保持する。

### オプションブロックを追加する

利用者が「オプションを追加」を実行すると、現在の末尾へ次の表示順を持つ空のブロックを保存する。追加成功後に一覧を再取得し、既存ブロックの候補と選択状態を維持したまま新しいブロックを表示する。追加中は重複実行を防ぎ、失敗時は既存の表示と選択状態を保持して再操作を案内する。

### オプション項目を選択して出力する

利用者は必要なバッジを複数選び、「プロンプトを表示」を実行する。選択中の文面をブロック順、各ブロック内の一覧順で処理し、ブロックごとに一つのpositiveセクションを作る。完全一致するタグは先のブロックを優先して、全オプションブロックを通して一つだけ残す。選択変更だけでは表示済みの出力を変更しない。

### オプション項目を削除する

削除前に登録名、文面のプレビュー、IDを表示して確認する。削除成功後は削除したIDだけを選択状態から取り除き、他の選択と表示済み出力を維持する。

## 登録・整形・業務ルール

一つのオプションブロックは整数IDと重複しない正の表示順を持つ。一つのオプション項目は、整数ID、所属ブロックID、登録名、positiveへ出力する文面を持ち、必ず存在する一ブロックだけに所属する。文面には複数タグを登録でき、`PromptText`でF01と同じ規則に整形する。登録名と整形後の文面は一文字以上を必須とし、空白・改行・カンマだけの文面は登録できない。

登録名と文面の重複は許容する。同名候補は管理操作で文面とIDを確認して識別する。同じ候補IDを二重に選択することはできず、選択状態はブラウザーでIDの集合として保持する。

出力時の重複判定では、括弧の外側にあるカンマをタグの区切りとして扱う。前後の空白を除いたタグが完全一致する場合は、一覧順で先に現れた一つだけを残す。大文字・小文字や括弧の有無など、文字列が異なるタグは別物として残す。括弧内のカンマはタグを分割しない。括弧の対応が壊れて安全に分割できない文面を含む場合は、内容を壊さず各候補の文面を半角スペース一つで結合する。

## データ・責務・API

更新用ドメインモデルは`OptionPromptGroup`と`OptionPrompt`とする。グループは追加順を、項目は所属グループ、登録名、文面の不変条件を守る。画面上の汎用的な表示構造を理由に場所や動作のドメインモデルへ統合しない。参照はオプション選択用のQueryから、表示順のグループと、その中で登録名・ID順に並ぶ候補を返す。

| 目的 | メソッド・URL | 成功時 |
| --- | --- | --- |
| オプションブロックと項目一覧を取得 | `GET /prompt-options` | `groups`配列を200で返す |
| オプションブロックを追加 | `POST /prompt-option-groups` | 保存結果を201で返す |
| オプションを追加 | `POST /prompt-options` | 所属ブロックを含む保存結果を201で返す |
| オプションを編集 | `PUT /prompt-options/{option}` | 保存結果を200で返す |
| オプションを削除 | `DELETE /prompt-options/{option}` | 204を返す |

更新APIはCSRF保護を適用する。不正入力は422、存在しないIDは404とする。認証は設けず個人利用とする。

一覧は次の構造で返す。`label`は保存値ではなく`position`から組み立て、項目の追加時は`groupId`を必須入力とする。編集では既存の所属グループを維持する。

```json
{
  "groups": [
    {
      "id": 1,
      "position": 1,
      "label": "オプション1",
      "options": [
        { "id": 10, "name": "高精細", "content": "detailed, sharp focus," }
      ]
    }
  ]
}
```

`option_prompt_groups`テーブルに整数ID、一意な正の表示順、作成・更新日時を保存する。`option_prompts`テーブルには所属ブロックIDを追加し、外部キーで存在するグループを参照する。登録名と文面にはDB上の一意制約を設けない。一回のグループ追加または項目の追加・編集・削除をそれぞれ整合性の単位とする。

グループ追加はトランザクション内で現在の最大表示順に1を加えて保存する。同時追加で一意制約に競合した場合は既存状態を変更せず失敗として返し、画面から再操作できるようにする。

移行時に表示順1のグループを「オプション1」として作り、既存の`option_prompts`全件をこのグループへ所属させてから所属ブロックIDを必須にする。既存ID、登録名、文面、作成・更新日時は維持する。既存データが0件でも「オプション1」は作成する。

## 出力と状態

選択した候補をブロック順、登録名・ID順で処理し、重複を除去したタグをカンマと半角スペースで結合して末尾にカンマを付ける。結果をブロックごとのオプションセクションとして、positiveの構図セクションの後ろへ順に追加する。未選択または重複除去後の結果が空になったブロックはセクションを出力しない。negativeには追加しない。

positive全体の順序は、デフォルト、人物・キャラクターLoRAタグ、そのトリガー、表情、視線、衣装LoRAタグ、衣装LoRAトリガー、服装、動作、場所、構図、追加順のオプションブロックとする。オプションの登録・編集・削除や選択変更では表示済み出力を変更せず、次の「プロンプトを表示」で反映する。

取得失敗時は未登録として扱わず、選択と表示操作を無効にして再取得を案内する。保存・削除中は同じ操作の重複実行とモーダルを閉じる操作を防ぐ。保存失敗時は入力内容を、削除失敗時は一覧と選択状態を保持する。

## 受入条件

| 要件 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| R01・R03 | 登録名`高精細`、文面`detailed, sharp focus,`を登録する | 整形済みの文面と登録名が保存され、一覧へ表示される |
| R01 | 空白とカンマだけの文面を保存する | 422となり登録されない |
| R02 | 二つのオプションバッジを選択する | 両方が選択状態になり、他の候補も選択できる |
| R02 | 選択中の一候補をもう一度押す | その候補だけが解除され、他の選択は維持される |
| R02・R04 | 候補を一覧と逆の順番で選択して表示する | 出力は選択順ではなく登録名・ID順になる |
| R04・R05 | `detailed, sharp focus,`と`sharp focus, (detailed),`を持つ候補を選択して表示する | `detailed, sharp focus, (detailed),`となり、完全一致する`sharp focus`だけが一つになる |
| R05 | 括弧内にカンマを含むタグを選択する | 括弧全体が一つのタグとして保持される |
| R04 | オプションを選ばず表示する | オプションセクションは出力されない |
| R04 | オプションと他のpositive項目を選択して表示する | オプションは構図の後ろに空行一つを挟んで追加され、negativeは変わらない |
| R03 | 選択中のオプションを編集する | 選択を維持し、次の表示時に編集後の文面が反映される |
| R03 | 選択中のオプションを削除する | 削除対象だけが選択から外れ、表示済み出力は次の表示まで変わらない |
| R03 | 保存または削除が失敗する | 入力内容、一覧、選択状態を保持して再操作を案内する |
| R06 | オプション1がある状態でブロックを二回追加する | オプション2、オプション3が末尾へ追加され、再読み込み後も順序を維持する |
| R06 | ブロック追加が失敗する | 既存ブロックと選択状態を維持し、再操作を案内する |
| R07 | オプション2から項目を追加する | 項目がオプション2だけに表示され、再読み込み後も所属を維持する |
| R04・R05・R07 | オプション1と2から同じタグを含む候補を選んで表示する | 先にあるオプション1へタグを残し、オプション2では同じタグを重ねて出力しない |
| R08 | 既存のオプション項目があるDBへ移行を適用する | 既存項目が同じ内容のままオプション1へ表示される |

## 設計上の判断

- 細かな指定を専用カテゴリとして固定せず、必要な数だけ追加できるオプションブロックにまとめて探索負担を抑える。
- オプションブロックは構造化されたカテゴリを補足する指定として、positiveの最後に追加順で配置する。
- 選択肢の再利用と組み合わせやすさを優先し、場所と同じ複数選択バッジを用いる。
- タグの重複除去は、場所と同じ構文認識と完全一致の規則を共有する。場所とオプションで規則が変わった場合に片方だけ更新されないよう、実装では用途に依存しない純粋な処理として切り出す。

## 未決事項

実装を開始できない未決事項はない。ブロック名の編集、並べ替え、削除、項目のブロック間移動、検索は、実際の利用状況から必要性を判断する。
