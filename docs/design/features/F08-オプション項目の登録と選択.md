# F08 名前付きオプションブロックの登録・並べ替え・選択

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F02](F02-プロンプトの選択と表示.md)、[F05](F05-LoRAの登録と選択.md)、[画面設計](../画面設計.md)、[選択カテゴリ統合の判断](../../decisions/0002-選択カテゴリをオプションへ統合.md)。

## 目的と背景

利用者が、LoRA固有の情報を除くpositive用の文面を、自分に合う分類・順序・選択方式で整理し、必要なタグを少ない操作で組み立てられるようにする。

表情・視線・場所・構図・動作と従来のオプションは、いずれも「登録名と文面を持つ候補を選び、positiveへ加える」という同じ目的とルールを持つ。専用カテゴリへ分け続けると画面・保存・APIの重複が増え、利用者が分類を変更できない。これらを名前付きオプションブロックへ統合し、ブロックごとに単一選択か複数選択かを設定する。

LoRA、LoRAトリガー、LoRAに属する服装は、ファイル、強度、親子関係、自動選択という固有ルールがあるため統合しない。

## 要件

| ID | 要件 |
| --- | --- |
| F08-R01 | ブロックに利用者が識別できる名前を保存できる |
| F08-R02 | ブロックごとに単一選択または複数選択を設定できる |
| F08-R03 | 項目に登録名と一つ以上のタグを含む文面を保存できる |
| F08-R04 | ブロックの選択方式に従って項目を選択・選択解除できる |
| F08-R05 | ブロックを追加・編集し、ドラッグ操作で並べ替えられる |
| F08-R06 | 項目を同一ブロック内で並べ替え、別ブロックへ移動できる |
| F08-R07 | ブロック順・項目順でpositiveセクションを生成し、完全一致するタグの重複を全ブロックで除去する |
| F08-R08 | 表情・視線・場所・構図・動作・既存オプションを、内容と用途を保って名前付きブロックへ移行する |
| F08-R09 | ポインター操作だけに依存せず、ブロックと項目を移動できる |
| F08-R10 | 各ブロックの項目を登録名でブラウザー内検索できる |

## オプションブロック

ブロックはID、名前、選択方式、正の表示順を持つ。名前は前後空白を除いて一文字以上とする。同じ名前は許容し、内部IDで対象を特定する。名前は利用者の整理方法であり、一意性を業務上の識別子にしないためである。

選択方式は次の二つだけとする。

| 選択方式 | 振る舞い |
| --- | --- |
| `single` | 未選択または一項目を選べる。別項目を選ぶと以前の選択を解除する |
| `multiple` | 未選択または複数項目を選べる。項目ごとに選択を切り替える |

追加フォームでは名前と選択方式を入力し、初期値は`multiple`とする。編集フォームで両方を変更できる。`multiple`から`single`へ変更した時点で複数選択中なら、ブロック内の表示順が最も早い一項目だけを残して他を解除し、トーストで知らせる。保存済み項目は削除しない。

ブロック削除は、所属項目を誤って失わないよう今回の範囲に含めない。空にしたい場合は項目を他ブロックへ移動するか個別に削除する。

## オプション項目

項目はID、所属ブロックID、登録名、文面、ブロック内の正の表示順を持ち、必ず一つのブロックへ所属する。登録名は前後空白を除いて一文字以上、文面は`PromptText`で整形した後も一文字以上とする。登録名と文面の重複は許容する。

項目は登録名だけを折り返さないバッジへ表示する。どちらの選択方式でも、選択状態を色、チェック表示、`aria-pressed`で示す。常時表示する操作はドラッグハンドル、選択バッジ、一つの管理ボタンに絞る。管理ボタンは移動ハンドルと異なる色にし、押すと画面中央のモーダルに編集・削除を表示する。

各ブロックに検索欄を置き、取得済み項目の登録名を大文字・小文字を区別しない部分一致で絞り込む。検索では通信せず、選択中の項目が一致しない場合も選択を見失わないよう表示に残す。検索は選択状態と保存データを変更しない。

## 並べ替えとブロック間移動

ブロックと項目にはドラッグハンドルを表示する。ブロックをドラッグするとブロック全体の出力順を変更する。項目をドラッグすると、同一ブロック内の順序変更または別ブロックへの移動を行う。項目本体の選択操作とドラッグ開始を分離する。

ドラッグ中は移動対象、挿入位置、移動先ブロックを視覚的に示す。画面外へ近づけた場合はページまたは候補領域を自動スクロールし、スマートフォンを含むポインター操作に対応する。

項目の同一ブロック内の並べ替えと別ブロックへの移動は、ドラッグして移動先の項目またはブロックへドロップして行う。項目ごとの移動先セレクトボックスや移動ボタンは表示しない。ブロック自体はドラッグに加えて見出しの「上へ」「下へ」でも移動できる。

並べ替え・移動はドロップ完了後に保存する。保存中は次の並べ替えを開始できない。成功後はサーバーの結果を表示し、表示済みのpositive出力は変更しない。失敗時は操作前の順序・所属・選択状態へ戻し、再操作を案内する。結果不明の更新を自動再送しない。

項目を別ブロックへ移した場合、現在の選択は次の規則で扱う。

- 未選択の項目は移動先でも未選択とする。
- 選択中の項目を`multiple`へ移す場合は選択を維持する。
- 選択中の項目を未選択の`single`へ移す場合は選択を維持する。
- 選択中の項目を別項目が選択済みの`single`へ移す場合は、移動先の既存選択を優先し、移動した項目を解除して通知する。

## 出力

選択中の項目をブロック表示順、ブロック内表示順で処理する。各ブロックから一つのpositiveセクションを作り、空のブロックは出力しない。ブロック名は整理用であり、プロンプト本文には含めない。

タグは括弧の外側にあるカンマで分割し、前後空白を除いた文字列が完全一致する場合、先に現れた一つだけを残す。重複除去はブロックをまたいで行う。大文字・小文字や括弧の有無が異なるタグは別物として残す。括弧内のカンマは分割しない。対応しない括弧を含み安全に分割できない場合は内容を変更せず、候補間を半角スペース一つで結合する。

positive全体は、デフォルト、人物・キャラクターLoRAタグ、そのトリガー、衣装LoRAタグ、そのトリガー、人物・キャラクターLoRAに属する服装、表示順のオプションブロックとする。negativeには追加しない。選択・編集・並べ替えでは表示済み出力を変更せず、次の「プロンプトを表示」で反映する。

## データと責務

更新用モデルは`OptionPromptGroup`と`OptionPrompt`とする。

- `OptionPromptGroup`は名前、選択方式、表示順の不変条件と選択方式変更時の規則を表す。
- `OptionPrompt`は所属先、登録名、文面、ブロック内表示順の不変条件を表す。
- ブロック並べ替えと項目移動は、影響する並び全体を一つのトランザクションで更新するApplicationのユースケースとする。
- 参照Queryは表示順のブロックと、その中の表示順の項目を画面用DTOとして返す。

`option_prompt_groups`は`id`、`name`、`selection_mode`、`position`、時刻を保存する。`position`は全体で一意とする。`option_prompts`は`id`、`option_prompt_group_id`、`name`、`content`、`position`、時刻を保存し、`(option_prompt_group_id, position)`を一意とする。位置は1から始まる連続値として更新する。

クライアントは移動対象のIDと基準位置を送る。サーバーは現在のDB状態を基に最終順序を計算し、クライアントから全行の位置番号を信頼しない。対象または移動先が存在しない場合は404、不正な選択方式や移動指定は422とする。同時更新は個人利用を前提として、サーバーが最後に受け付けた更新を反映する。

## API

| 目的 | メソッド・URL | 主な入力・結果 |
| --- | --- | --- |
| ブロックと項目一覧を取得 | `GET /prompt-options` | 表示順の`groups`と各`options` |
| ブロックを追加 | `POST /prompt-option-groups` | `name`、`selectionMode` |
| ブロックを編集 | `PUT /prompt-option-groups/{group}` | `name`、`selectionMode` |
| ブロックを移動 | `PATCH /prompt-option-groups/{group}/position` | `beforeGroupId`または末尾指定 |
| 項目を追加 | `POST /prompt-options` | `groupId`、`name`、`content` |
| 項目を編集 | `PUT /prompt-options/{option}` | `name`、`content`。所属は変更しない |
| 項目を移動 | `PATCH /prompt-options/{option}/position` | `targetGroupId`、`beforeOptionId`または末尾指定 |
| 項目を削除 | `DELETE /prompt-options/{option}` | 成功時204 |

更新APIはCSRF保護を適用する。一回のブロック追加・編集・移動、項目追加・編集・移動・削除をそれぞれ整合性の単位とする。

## 既存データの移行

移行前に新しいブロック構造を作り、次の順番と設定で既存カテゴリを移す。

| 移行順 | ブロック名 | 選択方式 | 移行元 |
| --- | --- | --- | --- |
| 1 | 表情 | `multiple` | `expression_prompts` |
| 2 | 視線 | `single` | `gaze_prompts` |
| 3 | 動作 | `multiple` | `action_prompts` |
| 4 | 場所 | `multiple` | `location_prompts` |
| 5 | 構図 | `single` | `composition_prompts` |
| 6以降 | 現在のブロック名 | `multiple` | `option_prompt_groups`と`option_prompts` |

従来の「オプション1」等の名前も初回移行時の正式な名前として保存し、後から編集できるようにする。各移行元内の項目順は、移行直前の画面表示と同じ登録名、IDの順とする。既存IDはテーブル間で重複する可能性があるため、新しい項目IDへ採番し、登録名、文面、作成・更新日時を保持する。移行が完了し件数と内容を検証してから旧カテゴリテーブルを削除する。

服装はすべてLoRAに紐づいていることを事前検査し、`outfit_prompts.lora_id`を必須にする。紐付かない服装が見つかった場合は推測で移行先を決めず、マイグレーションを失敗させてデータ修正を促す。

## 失敗時とリセット

一覧取得失敗時は未登録として扱わず、選択と管理操作を無効にして再取得を案内する。保存・削除・移動の失敗時は、入力内容、一覧、選択状態、表示済み出力を保持または操作前へ復元する。

全体リセットでは、全オプション項目の選択と検索文字列を初期化する。ブロック名、選択方式、並び順、項目の登録内容と所属は変更しない。

## 受入条件

| 要件 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| R01・R02 | `視線`という名前で`single`のブロックを作る | 再読み込み後も名前と選択方式が維持される |
| R02・R04 | `single`で二つ目の項目を選ぶ | 最初の選択が解除され、二つ目だけが選択状態になる |
| R02・R04 | `multiple`で二項目を選ぶ | 両方が選択状態になる |
| R02 | 二項目を選択中のブロックを`single`へ変える | 表示順が先の一項目だけが残り、解除を通知する |
| R05 | ブロックを末尾から先頭へドラッグする | 保存後と再読み込み後の表示・出力順が先頭になる |
| R06 | 項目を同じブロック内で並べ替える | 保存後と再読み込み後もその順序になる |
| R06 | 選択中項目を未選択の`single`へ移す | 所属と選択を維持し、一項目だけ選択された状態になる |
| R06 | 選択中項目を選択済みの`single`へ移す | 既存選択を維持し、移動項目は解除され、その旨が通知される |
| R07 | 異なるブロックから同じタグを含む項目を選ぶ | 先のブロックへタグを一つだけ出力する |
| R08 | 既存カテゴリのあるDBへ移行を適用する | 表情等が表の名前・方式・順序のブロックとなり、登録名と文面が保持される |
| R08 | LoRAに紐づかない服装があるDBへ移行を適用する | 移行が失敗し、服装は失われない |
| R09 | 項目を別ブロックへドラッグしてドロップする | 移動先ブロックの末尾またはドロップした項目の前へ移動し、順序と所属が保存される |
| R10 | ブロック内で登録名の一部を検索する | 通信なしで一致項目と選択中項目が表示され、順序と選択は変わらない |
| R05・R06 | 並べ替え保存が失敗する | 操作前の順序へ戻り、表示済み出力を変更せず再操作を案内する |

## 設計上の判断

- 同じ選択・整形・出力規則を持つカテゴリを名前付きブロックへ統合し、分類を利用者が変更できるようにする。
- 単一・複数選択は項目ではなくブロックの性質とし、一つのブロック内で操作規則を揃える。
- 並び順は表示だけでなく出力順を表す業務データとしてサーバーへ保存する。
- 項目の移動操作はドラッグハンドルへ集約し、各項目へ多数のボタンや移動先セレクトボックスを並べない。

## 未決事項

実装開始を妨げる未決事項はない。ブロック削除、ブロック名の一意制約、一括選択・解除は利用状況を見て別途設計する。
