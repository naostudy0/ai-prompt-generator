# F09 衣装LoRAの登録と複数選択

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F02](F02-プロンプトの選択と表示.md)、[F05](F05-LoRAの登録と選択.md)、[画面設計](../画面設計.md)。

## 目的と背景

利用者が、衣装を適用するLoRAを複数組み合わせ、それぞれに必要な強度とトリガーを対応関係が分かる状態で選び、positiveプロンプトへ反映できるようにする。

衣装LoRAは、登録名、ファイル名、推奨強度、トリガーという登録情報では人物・キャラクター用のLoRAと共通する。一方、一度に一つだけ使う既存LoRAとは異なり、衣装の一部を担う複数のLoRAを同時に利用することがある。トリガーは各衣装LoRAに属し、存在しない場合もあるため、LoRA一覧と一つの共通トリガー欄を複製するだけでは対応関係を表せない。

## 要件

| ID | 要件 |
| --- | --- |
| F09-R01 | 衣装LoRAに登録名、ファイル名、0から1まで0.1刻みの推奨強度を保存できる |
| F09-R02 | 衣装LoRAを登録名またはファイル名でブラウザー内検索できる |
| F09-R03 | 衣装LoRAを複数選択・選択解除できる |
| F09-R04 | 選択した衣装LoRAごとに強度を指定でき、選択時は保存済み推奨強度を使う |
| F09-R05 | 一つの衣装LoRAに、登録名と文面を持つトリガーを複数登録できる。トリガーが0件でもよい |
| F09-R06 | 選択した衣装LoRAごとに、そのLoRAに属するトリガーを未選択または一候補選べる |
| F09-R07 | 選択した衣装LoRAタグとトリガーを安定した順序でpositiveへ出力できる |
| F09-R08 | 衣装LoRAとそのトリガーを追加・編集・削除できる |
| F09-R09 | 既存LoRAと衣装LoRAを通してファイル名の重複を禁止する |

## 選択画面の振る舞い

既存のLoRA・トリガー・服装セクションの後ろに、独立した「衣装LoRA」セクションを置く。登録名またはファイル名を対象とする検索欄と、複数行分の高さを持つ縦スクロール可能なカード一覧を表示する。

一つのカードには登録名とファイル名を表示し、カードの選択ボタンで選択・選択解除を切り替える。選択状態は色、チェック表示、`aria-pressed`で示す。選択したカードは展開し、次をカード内に表示する。

- 0、0.1、0.2から1までを選べる、その衣装LoRA専用の強度欄。
- その衣装LoRAに属するトリガーだけを表示する単一選択欄。
- トリガーの選択解除、LoRA・トリガーの管理操作。

未選択のカードでは強度とトリガー欄を畳み、一覧性を保つ。検索は取得済みデータに対して大文字・小文字を区別しない部分一致で行い、サーバー通信を発生させない。選択中の衣装LoRAが検索条件に一致しない場合も、そのカードを一覧上部に残して選択と個別設定を見失わないようにする。残りの候補は登録名、IDの順を維持する。

ページロード時は衣装LoRAをすべて未選択とする。衣装LoRAを選択した時点で推奨強度を設定し、トリガーがある場合は登録名・ID順の先頭候補を自動選択する。トリガーがない場合は未選択のままにする。利用者は別のトリガーへの変更と選択解除ができる。

衣装LoRAを解除した場合は、そのLoRAに対する今回の強度とトリガー選択を破棄する。再度選択した場合は、保存済み推奨強度と先頭トリガーから開始する。他の衣装LoRAの選択と個別設定は変更しない。

## 登録・業務ルール

衣装LoRAは既存LoRAと同じく、前後空白を除いた一文字以上の登録名とファイル名、推奨強度を持つ。LoRAファイル名に`<`、`>`、`:`、カンマ、改行は使用できず、拡張子を含む登録値をそのままタグへ使う。登録名の重複は許容する。

ファイル名は人物・キャラクター用LoRAと衣装LoRAを通して一意とする。同じファイルを二つの用途へ重複登録せず、用途を変更する必要が生じた場合は編集で分類を変更する機能を別途設計する。

一つのトリガーは必ず一つの衣装LoRAに属し、登録名と整形後も一文字以上ある文面を持つ。文面は`PromptText`で整形する。トリガーの登録名と文面の重複は許容する。同じ衣装LoRAで同時に選べるトリガーは最大一つとする。

選択数には業務上の上限を設けない。同じ衣装LoRA IDを二重に選択することはできず、ブラウザーでは衣装LoRA IDごとに強度とnullableなトリガーIDを保持する。

## 出力

選択した衣装LoRAを登録名、IDの順で処理する。それぞれのファイル名と今回の強度から`<lora:ファイル名:強度>,`を作り、半角スペースで結合して一つの「衣装LoRAタグ」セクションとする。

選択した各衣装LoRAのトリガーを同じLoRA順で処理し、完全一致するタグの重複を除いて一つの「衣装LoRAトリガー」セクションとする。括弧付きタグと大文字・小文字が異なるタグは別物として残す。安全に分割できない括弧を含む場合は内容を変更せず半角スペース一つで結合する。トリガーを持たない、またはトリガーを解除した衣装LoRAは、LoRAタグだけを出力する。

positive全体は、デフォルト、人物・キャラクターLoRAタグ、そのトリガー、衣装LoRAタグ、衣装LoRAトリガー、人物・キャラクターLoRAに属する服装、表示順のオプションブロックとする。空のセクションは出力せず、セクション間を空行一つで区切る。negativeには追加しない。選択や強度の変更だけでは表示済み出力を変更せず、次の「プロンプトを表示」で反映する。

## データと責務

人物・キャラクター用と衣装用は、ファイルの識別、強度、タグ生成、トリガーの不変条件が同じため、既存の`Lora`、`LoraTrigger`、`LoraFileName`、`LoraStrength`、`LoraTag`を共通利用する。選択規則と画面状態は目的が異なるため、F05とF09の選択処理は分ける。

`loras`テーブルへ用途を表す`kind`を追加し、`character`または`clothing`だけを保存できるようにする。既存行はすべて`character`として移行する。`file_name`の一意制約はテーブル全体へ適用し続ける。`lora_triggers`は用途にかかわらず`lora_id`へ従属する。服装文面の必須`lora_id`は`character`だけを参照できるよう、保存時に用途を検証する。

参照Queryは衣装LoRAとそのトリガーだけを取得し、選択画面用DTOを返す。既存F05の参照Queryは`character`だけを返す。更新ユースケースは対象の用途を検証し、衣装LoRA用の入口から人物・キャラクター用LoRAやそのトリガーを変更できないようにする。

## API

| 目的 | メソッド・URL | 主な入力・出力 |
| --- | --- | --- |
| 衣装LoRA選択肢を取得 | `GET /clothing-lora-options` | 衣装LoRAと所属トリガーの一覧 |
| 衣装LoRAを追加 | `POST /clothing-loras` | 登録名、ファイル名、推奨強度 |
| 衣装LoRAを編集 | `PUT /clothing-loras/{lora}` | 登録名、ファイル名、推奨強度 |
| 衣装LoRAを削除 | `DELETE /clothing-loras/{lora}` | 成功時204 |
| 衣装LoRAトリガーを追加 | `POST /clothing-lora-triggers` | 衣装LoRA ID、登録名、文面 |
| 衣装LoRAトリガーを編集 | `PUT /clothing-lora-triggers/{trigger}` | 衣装LoRA ID、登録名、文面 |
| 衣装LoRAトリガーを削除 | `DELETE /clothing-lora-triggers/{trigger}` | 成功時204 |

更新APIはCSRF保護を適用する。入力不正、用途の不一致、既存用途を含むファイル名重複は422、対象が存在しない場合は404を返す。衣装LoRAの削除時は所属トリガーを同じトランザクションで削除する。

## 失敗時とリセット

一覧取得に失敗した場合は未登録として扱わず、衣装LoRAの選択と表示操作を無効にして再取得を案内する。保存・削除失敗時は入力、一覧、すべての選択と個別設定を維持する。保存・削除中は同じ操作の重複実行とモーダルを閉じる操作を防ぐ。

全体リセットでは、衣装LoRAの検索文字列、すべての衣装LoRA選択、それぞれの強度とトリガー選択を初期化する。登録済みの衣装LoRA、推奨強度、トリガーは変更しない。

## 受入条件

| 要件 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| R01・R08・R09 | 既存LoRAと同じファイル名で衣装LoRAを登録する | 422となり、既存LoRAは変更されない |
| R01・R03・R04 | 推奨強度0.8と1の衣装LoRAを二つ選ぶ | 両方が選択状態になり、それぞれ0.8と1が設定される |
| R02 | 登録名またはファイル名の一部を検索する | 通信なしで一致候補と選択中のカードが表示される |
| R03・R06 | 二つの衣装LoRAを選び、それぞれ別のトリガーを選ぶ | 各トリガーが所属する衣装LoRAのカード内で選択状態になる |
| R05・R06 | トリガーがない衣装LoRAを選ぶ | トリガー未選択のままLoRAを利用できる |
| R05・R06 | トリガーがある衣装LoRAを選ぶ | そのLoRAの先頭トリガーが自動選択され、解除もできる |
| R03 | 一つの衣装LoRAを解除する | そのLoRAの強度とトリガーだけが破棄され、他の選択は維持される |
| R07 | 強度0.8と1の衣装LoRA、各トリガーを選んで表示する | LoRAタグとトリガーがそれぞれ安定した順序のセクションとしてpositiveへ入る |
| R07 | 二つのトリガーに同じタグがある | 完全一致するタグを一つだけ出力する |
| R08 | 選択中の衣装LoRAを削除する | 所属トリガーが削除され、そのLoRAだけが選択から外れ、表示済み出力は次の表示まで変わらない |
| R08 | 選択中のトリガーを削除する | 対象衣装LoRAのトリガーだけが未選択になり、他の選択を維持する |
| R03 | 全体リセットを実行する | 衣装LoRAの検索、選択、強度、トリガーが初期化され、登録済みデータは残る |

## 設計上の判断

- 選択中の衣装LoRAごとにカードを展開し、強度とトリガーを同じカード内へ置くことで対応関係を明示する。
- 登録情報とタグ生成規則は既存LoRAと共通化し、複数選択の画面状態と出力構成は衣装LoRA専用にする。
- 選択順ではなく登録名・ID順で出力し、同じ選択集合から常に同じ結果を作る。
- トリガーは通常利用する先頭候補を自動選択するが、提供元がトリガーを指定していないLoRAと利用者が解除する操作を許容する。

## 未決事項

実装を開始できない未決事項はない。衣装LoRAの用途変更、並べ替え、選択上限は、実際の利用状況から必要性を判断する。
