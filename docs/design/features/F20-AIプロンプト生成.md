# F20 AIプロンプト生成

関連文書：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[アーキテクチャ](../アーキテクチャ.md)、[F02 プロンプトの選択と表示](F02-プロンプトの選択と表示.md)、[F11 人物LoRAの差し替えコピー](F11-人物LoRAの差し替えコピー.md)、[F19 プロンプトのクリップ](F19-プロンプトのクリップ.md)、[外部LLM連携の境界](../../decisions/0005-外部LLM連携の境界.md)、[利用者向け操作方法](../../operations/AIプロンプト生成の操作方法.md)

## 目的と背景

利用者は、描きたいイラストを日本語で説明し、構図、表情、背景、照明を含む画像生成向けの英語positive／negativeプロンプトを得たい。単純な翻訳ではなく、利用者が明示した内容と矛盾しない描写を補う。

生成した文面は独立した結果にせず、既存の出力編集、人物LoRA差し替えコピー、クリップ、お気に入り、ComfyUI送信に受け渡す。初回は一枚分の単一プロンプト生成と同期通信の実用性検証を目的とする。

## 要件とスコープ

| ID | 要件 |
| --- | --- |
| F20-R01 | 日本語のイラスト説明から英語のpositive／negative候補を一組生成できる |
| F20-R02 | `danbooru_tags`と`natural_language`の出力形式を選べ、未指定時は`danbooru_tags`を使う |
| F20-R03 | 利用者が明示した人数、人物属性、服装、場所を変更せず、矛盾しない描写だけを補完するようLLMへ指示する |
| F20-R04 | 生成結果を既存出力と別に確認・編集し、明示操作でのみ既存出力へ反映する |
| F20-R05 | 選択中の人物LoRAとトリガーをLLMに改変させず、反映時に識別可能な人物セクションとしてpositiveへ合成する |
| F20-R06 | 反映後のAI生成部分を保ったまま人物LoRA差し替えコピーを利用できる |
| F20-R07 | 生成に使ったモデル名、出力形式、Laravelから外部LLMへのHTTP通信時間を確認できる |
| F20-R08 | 接続、タイムアウト、上流HTTP、応答形式の失敗を分け、既存出力を変更せず再試行できる |
| F20-R09 | 入力全文と生成プロンプト全文を無条件に保存・ログ記録しない |
| F20-R10 | 接続先、モデル、接続タイムアウト、応答タイムアウトをサーバー側設定で変更できる |

初回範囲は生成用大型モーダル、単一生成API、Ollama Chat API互換アダプター、用途別System Prompt、既存出力への反映とする。

シナリオ解析、複数シーン抽出、複数結果の一括生成、生成履歴と指示文のDB保存、Queueによる非同期化、画像生成AIの呼び出し、LLMの導入・起動・配置手順は対象外とする。

## ユースケース：AIプロンプトを生成して出力へ反映する

- **実行者**：認証のない個人利用環境の利用者。
- **入力**：日本語を想定したイラスト説明と、任意のプロンプト形式。
- **事前条件**：Laravel実行環境から設定済みの外部LLM APIへ到達できる。
- **正常な流れ**：利用者が大型モーダルを開き、説明と形式を入力する。Applicationが形式に対応するSystem Promptを選び、Infrastructureアダプター経由でLLMへ同期送信する。応答を検証し、positive、negative、モデル、形式、生成時間をモーダルに表示する。利用者が候補を編集して「出力へ反映」すると、選択中の人物LoRAセクションをpositiveへ合成し、positive／negative出力を一度に置き換える。
- **出力・事後条件**：反映後の出力は手編集、コピー、クリップ、お気に入り、人物LoRA差し替え、ComfyUI送信で利用できる。デフォルト、LoRA、服装、オプション等の選択状態は変更しない。
- **例外の流れ**：入力不正は各入力に理由を表示する。通信、タイムアウト、上流HTTP、応答検証の失敗は既存出力を変更せずモーダルに再試行可能な案内を表示する。

## 業務ルール

### 入力

- `description`は必須の文字列とし、前後の空白を除いて1文字以上2,000文字以下とする。2,000文字は一枚分の説明に余裕を持たせつつ、シナリオ全体の誤送信と過大な待ち時間を抑える初期上限である。
- `promptStyle`は`danbooru_tags`または`natural_language`とし、未指定時は`danbooru_tags`とする。
- 文字列の言語判定は行わない。日本語を想定するが、日本語以外が混ざることだけを理由に拒否しない。

### LLMへの指示

スタイル別のSystem Promptで次を共通に指示する。

- 人数、人物属性、服装、場所など、利用者が明示した内容を変更しない。
- 指定のない人物を追加しない。不明な属性を過剰に決めつけない。
- 入力と矛盾しない範囲でポーズ、表情、視点、構図、背景、光源、照明、雰囲気、画面内配置を補完する。
- `positive_prompt`と`negative_prompt`だけを持つJSONオブジェクトを返し、説明文、Markdown、コードフェンスを含めない。

`danbooru_tags`ではカンマ区切りの英語タグを使い、Danbooru系の既存タグを優先して重複を抑える。正確性が不明な特殊タグを無理に作らない。`natural_language`では画像生成AIが理解しやすい自然な英文とし、人物、背景、照明、構図を具体化しつつ冗長にしない。

### 人物LoRAと生成結果

現在選択中の人物LoRAタグとトリガー文面はLLMへ送らない。LLMは利用者の説明だけを基に候補を生成する。

反映時に、選択中の人物LoRAタグとトリガーをAI positiveの後ろへ別セクションとして合成する。既存の人物LoRA差し替えに必要な、人物セクションの範囲、元LoRA、元トリガー、系統の情報を出力元メタデータとして保持する。

AI出力には系統別デフォルトを合成しない。別系統の人物LoRAへ差し替えるときもAI生成部分を維持し、系統別デフォルトの置換は行わない。人物LoRAが未選択なら人物セクションを合成せず、AI候補だけを反映する。

衣装LoRA、服装、デフォルト、オプション項目は自動合成しない。AI候補との重複を避けるためであり、それらの選択状態自体は変更しない。

## ドメインとApplication設計

この初回範囲は外部生成と出力反映の手順であり、保存する業務状態や独自の状態遷移を持たない。そのため新しい集約、Repository、DBテーブルは設けない。プロンプト形式の許可値と選択はApplicationの入力型で明示する。

生成は外部通信と計測という副作用を伴うため、返値が文字列であっても参照系ではなく`Application/PromptPreparation/Writes/GenerateIllustrationPrompt`へ置く。

想定する責務は次のとおり。実際のクラスは実装時に必要な最小単位で追加する。

| 単位 | 責務 |
| --- | --- |
| `GenerateIllustrationPromptInput` | 正規化済みの説明とプロンプト形式を持つ |
| `GenerateIllustrationPromptHandler` | System Promptを選び、ポートを呼び、ユースケース結果を返す |
| `GenerateIllustrationPromptResult` | positive、negative、モデル、形式、通信時間を持つ不変DTO |
| `IllustrationPromptGenerator` | 外部LLMへ一組の候補生成を要求するApplicationポート |
| System Prompt読み込み単位 | 形式に対応する専用ファイルを安全に読み、読み込み失敗を内部障害として扱う |

## 外部LLM連携

InfrastructureにOllama Chat API互換アダプターを置き、`POST /api/chat`を非ストリーミングで呼ぶ。モデル、systemメッセージ、userメッセージ、構造化出力のJSON Schemaを送る。モデル名は設定値を使い、特定名をApplicationの定数にしない。

接続先、モデル、タイムアウトは`config/services.php`と環境変数で管理する。設定項目は次を想定する。

- `ILLUSTRATION_LLM_BASE_URL`
- `ILLUSTRATION_LLM_MODEL`
- `ILLUSTRATION_LLM_CONNECT_TIMEOUT_SECONDS`
- `ILLUSTRATION_LLM_TIMEOUT_SECONDS`

ベースURLはサーバー側で固定し、リクエストから接続先を受け取らない。認証情報が将来必要になる場合は、別の設計を経てサーバー側設定からアダプターに与える。

System Promptは次の専用資材とし、PHPコード内の長文リテラルにしない。

```text
resources/prompts/illustration/
├── danbooru_tags.txt
└── natural_language.txt
```

### 応答検証

上流応答のHTTPステータス、トップレベルのチャット応答、assistant messageのcontentを順に検証する。contentはJSONオブジェクトとして解析し、次をすべて満たす場合だけ成功とする。

- `positive_prompt`が文字列で、前後空白を除いて空でない。
- `negative_prompt`が文字列である。空文字列は許容する。
- 必須キーが欠けていない。

コードフェンスの除去や、欠落キーの推測補完は行わない。不正な応答を成功扱いしないためである。

### 計測とログ

`generationTimeMs`はLaravelが外部LLMへのHTTPリクエスト送信を開始してから、応答本文の受信が完了するまでを単調時計で実測し、ミリ秒の整数で返す。

取得できる場合は次の指標を構造化ログに記録する。durationはナノ秒からミリ秒へ変換し、出力速度は`eval_count / eval_duration`からtokens/secを算出する。値が欠ける場合は推測しない。

- 追跡ID、結果分類、モデル名
- Laravelが実測したHTTP通信時間
- `total_duration`、`load_duration`
- `prompt_eval_count`、`prompt_eval_duration`
- `eval_count`、`eval_duration`
- 出力tokens/sec

入力全文、System Prompt全文、生成したpositive／negative全文、上流の生レスポンス本文は通常ログに記録しない。

## HTTP API

既存の画面からの操作であるため、`routes/web.php`にWebミドルウェアとCSRF保護を使う同一オリジンJSONエンドポイントを定義する。

```http
POST /illustration-prompts/generate
Accept: application/json
Content-Type: application/json
X-CSRF-TOKEN: <token>
```

リクエスト例：

```json
{
  "description": "黒髪ロングの女の子が夕暮れの教室で窓の外を眺めている。",
  "promptStyle": "danbooru_tags"
}
```

成功レスポンス例：

```json
{
  "positivePrompt": "1girl, solo, long black hair, looking outside, classroom, sunset",
  "negativePrompt": "low quality, blurry, bad anatomy",
  "model": "configured-model",
  "promptStyle": "danbooru_tags",
  "generationTimeMs": 3500
}
```

レスポンスは一件のオブジェクトとする。将来の複数シーン生成は別ユースケースと別エンドポイントで一覧を返し、各要素を本機能と同じpositive／negativeの組として反映可能にする。未実装の複数化のために初回レスポンスを配列にしない。

## 失敗とHTTPステータス

| 失敗 | ステータス | 利用者への扱い |
| --- | --- | --- |
| 必須、文字数、出力形式の入力不正 | 422 | 対象項目と修正理由を示す |
| 接続失敗、接続・応答タイムアウト、上流HTTPエラー | 503 | 一時的に生成を利用できないことと再試行を案内する |
| 上流の不正JSON、必須キー欠落、不正型、空positive | 502 | 生成結果を解釈できなかったことと再試行を案内する |
| System Prompt読み込み失敗等の内部障害 | 500 | 内部情報を含めず処理失敗を示す |

エラーレスポンスに接続先、スタックトレース、上流の生レスポンスを含めない。自動再試行は待ち時間と重複生成を増やすため初回は行わない。

## 画面とフロントエンド

既存のプロンプト準備画面に「AIでプロンプトを作成」ボタンを置き、画面遷移せず大型モーダルを開く。モーダルは次を持つ。

- 日本語指示のテキストエリア
- プロンプト形式の選択
- 生成ボタンと生成中表示
- 編集可能なpositive／negativeプレビュー
- 使用モデル名と生成時間
- 「出力へ反映」と「閉じる」
- 入力・通信・応答検証エラーを示す`role="status"`領域

生成中は二重送信を無効化する。モーダルを閉じる場合は`AbortController`で進行中のフロントエンドHTTP要求を中断する。中断後に応答が届いても破棄し、既存出力へ反映しない。失敗時は入力と有効なプレビューを保ち、再試行できる。

「出力へ反映」は生成成功後の有効なプレビューがある場合だけ有効にする。positiveを前後空白だけに編集した場合は反映できない。negativeは空を許容する。

反映時はpositive／negativeを一つの操作で置き換え、既存の出力変更時と同じ状態更新を行う。これによりコピー、お気に入り、クリップ、人物LoRA差し替え、ComfyUI送信の有効状態を同期する。反映後にモーダルを閉じる。

「プロンプトを作成」を後から実行した場合は、現在の選択内容から従来どおり出力を作り直し、AI反映結果を確認なしで上書きする。これは手編集済み出力と同じ既存仕様である。

AI生成UIのDOM参照、通信、プレビュー、反映を担当するJavaScriptモジュールを`resources/js/`に分離する。既存画面初期化はモジュールに、現在の人物LoRA出力元の取得と出力置換の関数を渡す。モジュールから既存画面の内部変数を直接操作しない。

## 永続化、トランザクション、同期・非同期

指示、生成結果、性能指標をDBやファイルストレージへ保存しない。新しいマイグレーション、Repository、トランザクションは不要である。プレビュー中の生成結果はモーダルのブラウザー内状態だけに保持する。

初回は同期HTTPとし、フロントエンドが一回の応答を待つ。タイムアウトや実測値から同期待機が実用的でないと分かった場合は、ジョブ識別子、結果取得、再実行時の整合性を含む別の非同期設計を行う。

## テスト方針

テストから実際の外部LLMへ通信しない。ApplicationはポートのFake、InfrastructureとHTTP入口はLaravel HTTPクライアントのFake、フロントエンドは既存のJavaScript DOMテスト環境を使う。テストデータは新規の架空データに限る。

検証範囲は次のとおり。

- 説明の必須、1文字、2,000文字、2,001文字とプロンプト形式の許可値。
- 未指定時の`danbooru_tags`適用と、形式別System Promptの選択。
- 外部LLMへ送るモデル、メッセージ、非ストリーミング指定、構造化出力指定。
- 正常応答の変換、モデル名、実測時間、任意の性能指標。
- 接続失敗、接続タイムアウト、応答タイムアウト、上流HTTPエラー。
- 不正なチャット応答、不正JSON、必須キー欠落、不正型、空positive。
- モーダルの二重送信防止、中断、再試行、プレビュー編集。
- 反映まで既存出力を変更しないことと、反映時のpositive／negative同時置換。
- 選択中の人物LoRAとトリガーの合成、未選択時の非合成。
- AI生成部分と人物以外の出力を保った人物LoRA差し替え。
- AI反映結果の手編集、クリップ保存・呼び出し、お気に入り、ComfyUI送信への受け渡し。
- 通常の「プロンプトを作成」による従来出力への置換。

## 受入条件と検証

| 要件 | 前提／操作 | 期待結果 |
| --- | --- | --- |
| R01・R02・R03 | 架空の日本語説明と`danbooru_tags`で生成する | 明示内容と矛盾しないカンマ区切り英語positiveと英語negativeがプレビューに表示される |
| R02 | 形式を指定せず生成する | `danbooru_tags`用System Promptが使われ、レスポンスに同じ形式が返る |
| R02・R03 | `natural_language`を選び架空の日本語説明で生成する | 明示内容を変えない冗長すぎない英文positiveとnegativeが表示される |
| R04 | 既存出力がある状態で生成する | プレビューまでは既存出力が変わらず、「出力へ反映」でのみ両出力が候補へ置き換わる |
| R04 | プレビューを手編集して反映する | 編集したpositive／negativeが出力欄に反映される |
| R05・R06 | 人物LoRAとトリガーを選択した状態でAI候補を反映し、別の人物へ差し替えコピーする | AI生成部分を保持し、識別した人物LoRAタグとトリガーだけが候補用に置き換わる |
| R05 | 人物LoRA未選択でAI候補を反映する | AI候補だけが出力され、存在しない人物セクションは作られない |
| R07 | 外部LLMのFakeが成功応答と性能指標を返す | 応答にモデル、形式、実測通信時間が含まれ、ログ用指標を変換できる |
| R08 | 外部LLMへの接続失敗またはタイムアウトを発生させる | 503と再試行可能な案内を返し、既存出力と入力を保つ |
| R08 | 不正JSON、キー欠落、不正型、空positiveのいずれかを返す | 502と再試行可能な案内を返し、不正な候補を表示・反映しない |
| R09 | 生成の成功と失敗をログ記録する | 追跡と性能に必要な項目は残り、入力全文と生成プロンプト全文は含まれない |
| R10 | 接続先とモデルをテスト用設定にする | リクエストが利用者入力ではなくサーバー設定の接続先とモデルを使う |
| R04・R06 | AI反映結果をクリップに保存し、呼び出して人物LoRA差し替えを行う | AI生成部分と出力元メタデータが復元され、人物セクションだけを差し替えられる |

プログラムが保証するのは、入出力形式、明示した指示、応答検証、失敗時の非反映である。LLMが生成するプロンプトの美的品質や画像生成結果は決定的に保証できない。実用性は固定した架空入力集合に対する人の評価と、モデル・時間・トークン指標の記録で別途判断する。

## 未決事項と将来拡張

実装開始を妨げる未決事項はない。

将来、シナリオから複数シーンを生成する場合は、シナリオ、シーン、人物固定設定の所有者と保存寿命を別途決める。複数結果は一覧から一件を選び、本機能と同じ「既存出力へ反映」操作に渡す。クリップの拡張と新しいシナリオ置き場のどちらを使うかは、長期保存、並べ替え、複数タブ共有の必要性を確認して決める。
