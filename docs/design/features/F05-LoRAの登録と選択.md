# F05 LoRA・トリガー・服装の登録と選択

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F01](F01-デフォルトプロンプト.md)、[F02](F02-プロンプトの選択と表示.md)、[画面設計](../画面設計.md)。

## 目的と背景

利用者が多数のLoRAから目的の人物・キャラクターを登録名で見つけ、LoRAタグと対応するトリガーや服装の文面をpositiveプロンプトへ反映できるようにする。

LoRAのファイル名だけでは内容を判別しにくいため、ファイル名とは別に利用者が付けた登録名を保存する。提供元が人物・キャラクター、髪型、服装ごとに異なる呼び出し文面を示す場合があるため、一つのLoRAに複数のトリガーと服装を関連付けられるようにする。

服装は別のLoRAでも流用するため、選択したLoRAに属する候補を探しやすくしつつ、すべての服装から選べる状態を保つ。

## 確定している要件

| ID | 要件 |
| --- | --- |
| F05-R01 | LoRAにファイル名と利用者が付ける登録名を保存する |
| F05-R02 | LoRAを検索でき、複数行が見えるスクロール可能なリストから一つだけ選択できる |
| F05-R03 | LoRAの検索はブラウザー内で行い、サーバーへの検索リクエストを発生させない |
| F05-R04 | LoRAごとに0から1まで0.1刻みの推奨強度を保存でき、初期値を1とする |
| F05-R05 | 選択したLoRAを`<lora:ファイル名:強度>,`形式の文面にする |
| F05-R06 | 一つのLoRAに、登録名と文面を持つトリガーを複数登録できる |
| F05-R07 | 選択したLoRAに属するトリガーだけを候補として表示し、一つだけ選択できる |
| F05-R08 | 服装に登録名と文面を保存し、LoRAとの紐付けなしでも登録できる |
| F05-R09 | 服装はすべて候補として表示し、一つだけ選択できる |
| F05-R10 | LoRAを選択したとき、そのLoRAに紐づく服装を候補の上位へ並べ、それ以外の服装も後ろに表示する |
| F05-R11 | トリガーと服装の文面をF01のデフォルト文面と同じ規則で整形する |
| F05-R12 | LoRAタグ、トリガー、服装をpositive側の出力候補として扱う |
| F05-R13 | LoRA、トリガー、服装を追加・編集・削除できる |
| F05-R14 | 服装を登録名でブラウザー内検索できる |

LoRA、トリガー、服装の同時選択数はそれぞれ最大一つとする。複数を同時に選ぶと一方が反映されない、または意図しない画像になる可能性があるためである。
ページロード時はLoRA、トリガー、服装をすべて未選択とする。LoRAを選択した場合は、そのLoRAに属するトリガーの先頭候補を自動選択する。服装は自動選択せず、利用者が必要な候補を明示的に選ぶ。

## 選択画面の振る舞い

### LoRA

LoRAカテゴリには次を配置する。

- 登録名またはファイル名を入力する検索欄。
- 複数候補を同時に確認でき、縦にスクロールできる単一選択リスト。
- 0、0.1、0.2から1までを選べる強度選択欄。LoRA選択時は、そのLoRAに保存された推奨強度を初期値とする。

検索は取得済みデータに対してJavaScriptで行う。登録名とファイル名を対象に、大文字・小文字を区別しない部分一致とする。検索文字列が空なら全件を表示する。全角・半角などの表記は変換せず、入力された文字列のまま比較する。

一つの候補には、利用者が識別に使う登録名と、出力に使われるファイル名の両方を表示する。選択に使う識別子とファイル名は分離し、同名表示による誤選択を避ける。

### トリガー

LoRAを選択したとき、そのLoRAに属するトリガーだけをトリガーセクションへ表示する。人物・キャラクターの標準形や髪型違いなどを別の候補として扱い、候補には登録名を表示する。

トリガーは最大一つを選択する。LoRAを選択または別のものへ変更した場合、それまでのトリガー選択を解除し、新しいLoRAに属する一覧の先頭候補を自動選択する。紐づくトリガーがない場合は未選択とする。自動選択後も、利用者は別候補への変更や選択解除ができる。

### 服装

服装はLoRAへの紐付けを任意とする。特定LoRAの提供元が示した服装はそのLoRAへ紐付け、汎用の服装は紐付けなしで登録できる。

服装候補は常に全件を表示する。LoRAが選択された場合は、そのLoRAに紐づく服装を先頭のグループへ移し、残りをその後へ並べる。並べ替えは候補の見つけやすさだけを変え、選択可能な範囲を狭めない。

服装は最大一つを選択する。LoRAを変更しても、選択済みの服装が登録済みである限り選択を維持する。これは、別のLoRAに属する服装や汎用の服装を意図して利用できるようにするためである。

服装は登録名の大文字・小文字を区別しない部分一致でブラウザー内検索する。検索文字列が空なら全件を表示する。検索は取得済みデータだけを対象とし、サーバーへ検索リクエストを送らない。選択済みの服装が検索条件に一致しない場合も、現在の選択を見失わないよう選択中の候補を検索結果の先頭に残す。

## 登録する情報

### LoRA

| 項目 | 内容 |
| --- | --- |
| 登録名 | 利用者が一覧と検索で識別する名前 |
| ファイル名 | LoRAタグへ埋め込む文字列 |
| 推奨強度 | 選択時に最初に使う強度。未指定時は1 |

### トリガー

| 項目 | 内容 |
| --- | --- |
| LoRA | 必ず一つのLoRAに属する |
| 登録名 | 人物・キャラクターや髪型などを識別する名前 |
| 文面 | positiveへ出力する一まとまりの文面 |

### 服装

| 項目 | 内容 |
| --- | --- |
| LoRA | 任意。提供元となるLoRAがある場合に紐付ける |
| 登録名 | 服装を一覧で識別する名前 |
| 文面 | positiveへ出力する一まとまりの文面 |

各登録名とLoRAファイル名は前後の空白を除いた後も一文字以上を必須とする。登録名の重複は許容する。候補には登録名だけでなくファイル名または紐づくLoRA名も併記し、同名でも識別できるようにする。

LoRAファイル名は衣装LoRAを含むアプリ全体で一意とする。タグ構造を壊す`<`、`>`、`:`、カンマ、改行は使用できない。登録された文字列を拡張子を含めてそのままLoRAタグへ使い、自動的な拡張子の追加・削除は行わない。

トリガーと服装の文面は、整形後も一文字以上あることを必須とする。空白、改行、カンマだけの文面は登録できない。デフォルトプロンプトの空保存は削除の意味を持つが、トリガーと服装には独立した削除操作があるため空文面を登録しない。

## 文面の整形と出力

トリガーと服装は外部からコピーして登録することが多いため、F01でも利用する`PromptText`と同じ振る舞いで整形する。

- カンマの後を半角スペース一つにし、空でない文面の末尾にカンマを付ける。
- カンマのない改行を区切りとして補完する。
- 空の要素と完全一致する重複を除去する。
- 対応する丸括弧内を一まとまりとして保護する。
- 解釈できない括弧がある場合は、意味を壊さず原文を保存する。

LoRAタグは文面整形を通さず、`LoraTag`値オブジェクトがLoRAのファイル名と強度から組み立てる。一覧取得APIは0〜1の各強度に対応するタグを返し、ブラウザーは選択された強度のタグを出力する。例えばファイル名が`lora-file-name`で強度が0.8なら、`<lora:lora-file-name:0.8>,`とする。強度1は`<lora:lora-file-name:1>,`と表記する。

LoRAタグ、トリガー、服装はそれぞれ独立したセクションとしてpositive出力へ渡す。全カテゴリでは、デフォルト、人物・キャラクターLoRAタグ、そのトリガー、表情、視線、衣装LoRAタグ、衣装LoRAトリガー、服装、動作、場所、構図、追加順のオプションブロックとする。未選択のセクションは出力せず、F02と同じくセクション間を空行一つで区切る。

negativeにはLoRA、トリガー、服装を追加しない。

## データと責務の分離

LoRAは登録名とファイル名を管理する単位とする。トリガーはLoRAに従属し、LoRAとの関係を持たない状態を許可しない。服装は独立して再利用できる登録情報とし、LoRAとの関係を任意にする。

想定する永続化関係は次のとおり。

```text
LoRA 1 ── 0..* トリガー
LoRA 1 ── 0..* 服装（服装側のLoRA関連は任意）
```

一つの服装に紐付けられるLoRAは最大一つとする。同じ文面を複数のLoRAへ紐付けたい場合は、LoRAごとに別の服装として登録する。

登録・更新は目的ごとに`Application/PromptPreparation/Writes/`へ置き、選択画面用の一覧取得は`Queries`から表示用DTOを返す。画面では取得したDTOを検索・並べ替え・単一選択に利用する。検索や表示順の変更ではDBを更新しない。

文面整形はデフォルト、トリガー、服装で同じ規則を共有するため、デフォルト専用の名前を持つ型をそのまま流用せず、用途に依存しないプロンプト文面の値オブジェクトへ規則をまとめる。LoRAタグは別の値オブジェクトがファイル名と強度の制約および文字列化を担う。

## 管理操作と削除時の整合性

LoRA、トリガー、服装は同じページから追加・編集・削除できる。通常の選択操作と混同しないよう、各カテゴリの管理操作から入力フォームを開く。保存・削除の完了後は一覧データを更新し、検索文字列は維持する。

- LoRAを削除すると、そのLoRAに属するトリガーも同じトランザクションで削除する。
- 削除したLoRAに紐づく服装は削除せず、LoRAとの紐付けを解除して汎用の服装として残す。
- トリガーと服装は個別に削除できる。
- 削除前に対象の登録名と影響を示して確認する。
- 選択中のLoRAを削除した場合は、LoRA、強度、トリガーの選択を解除する。選択中の服装は、その服装自体が残るため維持する。
- 選択中のトリガーまたは服装を削除した場合は、その選択を解除する。
- 登録情報の追加・編集・削除だけでは表示済みの出力を変更しない。次に「プロンプトを表示」を押したとき、現在の選択状態から出力を作り直す。

## APIと永続化

選択画面用の一覧は一度に取得し、フロント側の検索と並べ替えに使う。

| 目的 | メソッド・URL | 主な入力・出力 |
| --- | --- | --- |
| 選択肢を取得 | `GET /lora-prompt-options` | LoRA、トリガー、服装の一覧 |
| LoRAを追加 | `POST /loras` | 登録名、ファイル名、推奨強度 |
| LoRAを編集 | `PUT /loras/{lora}` | 登録名、ファイル名、推奨強度 |
| LoRAを削除 | `DELETE /loras/{lora}` | 成功時204 |
| トリガーを追加 | `POST /lora-triggers` | LoRA ID、登録名、文面 |
| トリガーを編集 | `PUT /lora-triggers/{trigger}` | LoRA ID、登録名、文面 |
| トリガーを削除 | `DELETE /lora-triggers/{trigger}` | 成功時204 |
| 服装を追加 | `POST /outfits` | 任意のLoRA ID、登録名、文面 |
| 服装を編集 | `PUT /outfits/{outfit}` | 任意のLoRA ID、登録名、文面 |
| 服装を削除 | `DELETE /outfits/{outfit}` | 成功時204 |

更新系はWebミドルウェアのCSRF保護を適用する。不正な入力とファイル名の重複は422、存在しないIDは404を返す。削除は対象と関連データの変更を一つのトランザクションで行う。

永続化は次の三テーブルに分ける。すべてに整数の`id`と作成・更新日時を持たせる。

| テーブル | 主な列と制約 |
| --- | --- |
| `loras` | `name`、一意な`file_name`、0〜10の整数で保持する`recommended_strength_step`、用途を表す`kind`。本機能は`character`だけを扱う |
| `lora_triggers` | `lora_id`、`name`、`content`。LoRA削除時は行を削除 |
| `outfits` | nullableな`lora_id`、`name`、`content`。LoRA削除時は`lora_id`をnullにする |

強度は小数の比較誤差を避けるため、DBとドメインでは0〜10の段階値として保持し、APIと画面の境界で0〜1の表示値へ変換する。例えば段階値8は0.8、10は1として扱う。

衣装LoRA追加時に既存行へ`kind = character`を設定する。F05の一覧取得と更新APIは人物・キャラクター用途だけを扱い、衣装用途の行を表示・変更しない。服装文面の任意のLoRA関連も人物・キャラクター用途に限定する。

## 失敗時の扱い

- 一覧取得に失敗した場合はLoRA、トリガー、服装を未登録として扱わず、再取得を案内する。
- 保存に失敗した場合は入力値を保持し、成功表示を出さない。
- LoRAを選択していない場合は、トリガーを選択できない。
- 削除に失敗した場合は一覧と選択状態を変更せず、再操作を案内する。
- 一覧の再取得中や保存・削除中は、同じ操作の重複実行を防ぐ。

## 設計上の判断

- ページロード時は意図しない出力を避けるためLoRA、トリガー、服装を自動選択しない。LoRAを明示的に選んだ後は、通常使用するトリガーの選択操作を省くため、そのLoRAに属する先頭候補を自動選択する。服装は用途による違いが大きいため自動選択しない。
- 作者の推奨値を繰り返し設定する手間を減らすため、推奨強度をLoRAへ保存する。今回だけの強度変更では保存値を変えず、LoRAの編集操作で推奨値を変更する。
- ファイル名はタグ生成の識別情報なので重複を禁止する。登録名は利用者向けの表示情報なので重複を許可する。
- 服装は再利用可能な独立データとして残すため、LoRA削除時に連動削除しない。
- 一つの服装を複数LoRAへ紐付ける中間テーブルは設けない。必要な場合はLoRAごとに別の服装を登録し、構造を単純に保つ。
