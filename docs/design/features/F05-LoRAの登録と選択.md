# F05 LoRA・トリガー・服装の登録と選択

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F02](F02-プロンプトの選択と表示.md)、[F08](F08-オプション項目の登録と選択.md)、[F09](F09-衣装LoRAの登録と複数選択.md)、[画面設計](../画面設計.md)。

## 目的と背景

利用者が多数の人物・キャラクターLoRAから目的のものを登録名で見つけ、LoRAタグと、そのLoRA固有のトリガーや服装を対応関係が分かる状態でpositiveへ反映できるようにする。

LoRA以外の汎用的な文面はF08のオプションへ統合する。トリガーと服装は特定LoRAの提供元が示す呼び出し条件であり、選択したLoRA以外で流用しないためLoRAへの所属を必須とする。

## 要件

| ID | 要件 |
| --- | --- |
| F05-R01 | LoRAにファイル名、利用者が付ける登録名、推奨強度を保存できる |
| F05-R02 | LoRAを登録名またはファイル名でブラウザー内検索し、一つ選択できる |
| F05-R03 | 選択したLoRAを`<lora:ファイル名:強度>,`形式にできる |
| F05-R04 | 一つのLoRAに登録名と文面を持つトリガーを複数登録できる |
| F05-R05 | 選択したLoRAに属するトリガーを未選択または一つ選べる |
| F05-R06 | 一つのLoRAに登録名と文面を持つ服装を複数登録できる |
| F05-R07 | 選択したLoRAに属する服装を未選択または一つ選べる |
| F05-R08 | LoRA、トリガー、服装を追加・編集・削除できる |
| F05-R09 | トリガーと服装の文面を共通規則で整形する |

## 選択画面

LoRAは複数行を表示する単一選択リストとし、登録名またはファイル名の大文字・小文字を区別しない部分一致で絞り込む。検索は取得済みデータを対象とし、通信を発生させない。ページロード時は未選択、強度は1とする。

LoRAを選択した場合は推奨強度を反映し、所属トリガーの登録名・ID順の先頭を自動選択する。トリガーがなければ未選択とする。服装は用途による違いがあるため自動選択しない。トリガーと服装には、選択中LoRAに属する候補だけを表示する。

LoRAを変更した場合、以前のトリガーと服装の選択を解除し、新しいLoRAの候補へ切り替える。LoRAを解除した場合は強度を1へ戻し、トリガーと服装も解除する。

## 登録と業務ルール

LoRAは前後空白を除いた一文字以上の登録名とファイル名、0から1まで0.1刻みの推奨強度を持つ。推奨強度の初期値は1とする。ファイル名は人物・キャラクター用と衣装用を通して一意とし、`<`、`>`、`:`、カンマ、改行を使用できない。

トリガーと服装は必ず存在する一つの人物・キャラクターLoRAへ属し、前後空白を除いた登録名と整形後も一文字以上ある文面を持つ。登録名と文面の重複は許容する。文面は`PromptText`で整形する。

LoRA削除時は、所属するトリガーと服装を同じトランザクションで削除する。所属なしの服装として残さない。トリガーと服装は個別にも削除できる。選択中データを削除した場合は該当する今回の選択だけを解除し、表示済み出力は変更しない。

## 出力

人物・キャラクターLoRAタグ、トリガー、服装をそれぞれ独立したpositiveセクションとして渡す。空のセクションは出力しない。negativeには追加しない。

positive全体は、デフォルト、人物・キャラクターLoRAタグ、そのトリガー、衣装LoRAタグ、そのトリガー、服装、表示順のオプションブロックとする。

## データとAPI

`loras`は用途`character`または`clothing`を持つ。F05の参照・更新は`character`だけを扱う。`lora_triggers`と`outfit_prompts`は必須の`lora_id`で人物・キャラクターLoRAへ従属し、外部キーで整合性を守る。更新ユースケースでもLoRA用途を検証する。

| 目的 | メソッド・URL | 主な結果 |
| --- | --- | --- |
| 選択肢を取得 | `GET /lora-prompt-options` | 人物・キャラクターLoRA、所属トリガー、所属服装 |
| LoRAを追加・編集・削除 | `POST /loras`、`PUT・DELETE /loras/{lora}` | 保存結果または204 |
| トリガーを追加・編集・削除 | `POST /lora-triggers`、`PUT・DELETE /lora-triggers/{trigger}` | 保存結果または204 |
| 服装を追加・編集・削除 | `POST /outfits`、`PUT・DELETE /outfits/{outfit}` | 必須LoRA IDを含む保存結果または204 |

更新APIはCSRF保護を適用する。不正入力と用途不一致は422、存在しないIDは404とする。

## 既存データ移行

服装の`lora_id`を必須へ変更する前に、全服装が存在する人物・キャラクターLoRAへ属することを検査する。所属なし、存在しないLoRA、衣装用途LoRAへの所属が見つかった場合は移行を失敗させ、データを失わず修正を促す。検査成功後にNOT NULL制約と外部キーを適用する。

## 失敗時とリセット

取得失敗時は未登録として扱わず、選択・表示・管理操作を無効にして再取得を案内する。更新失敗時は入力、一覧、選択状態を保持する。結果不明の更新は自動再送しない。

全体リセットではLoRA、トリガー、服装、強度、検索文字列を初期化する。登録済みデータは変更しない。

## 受入条件

| 要件 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| R01・R02 | 登録名またはファイル名の一部を検索する | 通信なしで一致するLoRAだけが表示される |
| R02・R05 | トリガーのあるLoRAを選ぶ | 推奨強度と先頭トリガーが選ばれ、所属する服装だけが表示される |
| R06・R07 | 選択中LoRAに二つの服装がある | どちらか一つまたは未選択を選べる |
| R07 | 別のLoRAへ変更する | 以前の服装が消え、新しいLoRAに属する服装だけが表示される |
| R08 | LoRAを削除する | 所属トリガーと服装も削除され、他LoRAのデータは残る |
| R09 | 文面`(dress,red), dress`を保存する | `(dress,red), dress,`として再取得できる |
| R09 | 空白とカンマだけの文面を保存する | 422となり登録されない |
| R01 | 人物用と衣装用で同じファイル名を登録する | 422となり既存データを変更しない |
| R06 | 所属なしで服装を登録する | 422となり登録されない |
| R06 | 所属なしの服装があるDBへ必須化の移行を適用する | 移行が失敗し、既存服装が保持される |

## 設計上の判断

- LoRA固有の候補だけをLoRA配下へ残し、汎用的な分類はF08へ統合する。
- 服装の所属を必須にし、現在選択しているLoRAと関係のない候補を表示しない。
- LoRA削除時は従属データも削除し、所属を失った服装を作らない。
