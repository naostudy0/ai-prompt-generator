# F12 人物LoRAの系統と系統別デフォルト

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F01](F01-デフォルトプロンプト.md)、[F02](F02-プロンプトの選択と表示.md)、[F04](F04-お気に入りプロンプト.md)、[F05](F05-LoRAの登録と選択.md)、[F11](F11-人物LoRAの差し替えコピー.md)。

## 目的と背景

利用者が人物・キャラクターLoRAを選ぶ際、そのLoRAを使う系統に合う共通のpositive／negative文面を毎回選び直さずに出力したい。Illustrious、anima、ponyなどでは使うタグが異なる場合がある。人物LoRAを系統へ紐づけ、系統ごとに二つのデフォルト文面を持たせる。

## 要件と範囲

| ID | 要件 |
| --- | --- |
| F12-R01 | 利用者が系統を名前で登録・改名・削除できる |
| F12-R02 | 人物LoRAを一つの系統へ紐づけて登録・変更できる |
| F12-R03 | 系統を登録した後、その系統専用のpositive／negativeデフォルト文面をそれぞれ入力・保存・再編集・取得できる |
| F12-R04 | 人物LoRAを選択してプロンプトを表示すると、所属系統のデフォルト文面が選択状態に応じて出力される |
| F12-R05 | 既存データを失わず、Illustrious系統へ移行できる |
| F12-R06 | 系統・LoRA・文面の変更や取得失敗があっても、別系統の文面を誤って出力しない |

この機能は人物・キャラクターLoRAとデフォルト文面を対象とする。衣装LoRA、衣装LoRAのトリガー、服装、オプションブロックと項目には系統を付けない。オプションの系統別管理や系統をまたぐ互換性判定も行わない。既存の文面整形、選択ボタン、出力欄の手編集・コピーの規則は維持する。

## ユースケースと画面

1. デフォルト欄から「系統を管理」を開き、名前を入力して系統を登録する。登録直後のpositive／negativeは空文面とする。同じ画面で系統名の変更と削除を行える。系統の登録だけで文面の入力を終えず、作成した系統のpositiveとnegativeを続けて設定できる導線を置く。
2. デフォルト欄に現在の出力系統名を表示する。デフォルト編集時には編集対象の系統選択欄と、positive・negativeそれぞれの編集ボタンを設ける。選んだ系統の該当する保存済み文面を一つのテキストエリアに表示し、各側を個別に入力・保存する。例えばanimaのnegativeを編集しても、animaのpositiveとIllustriousの両文面は変わらない。編集対象系統の変更は出力系統や表示済み出力を変えない。
3. 人物LoRAの追加・編集フォームで、登録済みの系統から所属先を必須選択する。初期の選択肢は Illustrious とする。人物LoRAの一覧でも所属系統を確認できるようにする。
4. 人物LoRAを選択すると、その所属系統が今回の有効系統となり、出力系統名を更新する。positive／negativeのデフォルト選択有無は維持する。プロンプト表示ボタンを押した時に、切り替え後の系統の文面を使用する。表示済みの出力欄は次の表示操作まで保持する。
5. 編集対象の系統と出力系統は別の状態として扱う。別系統のデフォルトを編集している途中にLoRAを選択しても、未保存の入力を勝手に切り替えない。

人物LoRA未選択時は Illustrious を有効系統とする。全体リセットでも Illustrious に戻し、保存済み文面は変えない。

## 業務ルール

- 系統はIDと前後空白を除いた空でない名前を持つ。名前は大文字・小文字を区別せず一意とし、内部ではIDで参照する。後から改名してもLoRAとの関連は維持する。
- 人物LoRAは必ず存在する一つの系統へ属する。所属先を変えてもLoRAファイル名、推奨強度、トリガー、服装は変わらない。衣装LoRAは所属系統を持たない。
- 一つの系統にはpositiveとnegativeがそれぞれ一件ずつ存在する。空文面は許容し、保存時の整形はF01の`PromptText`を再利用する。片方の保存は他方や別系統の文面を変更しない。
- 系統を利用中の人物LoRAがある場合は削除できない。系統の削除後に残るデフォルト文面を曖昧にしないため、削除可能な未使用系統の二つの文面は同時に削除する。Illustriousは初期・移行先として残し、削除できない。
- LoRA選択による系統の切り替えは、保存済み文面やすでに表示・手編集された出力を変更しない。次のプロンプト表示で現在の系統を反映する。取得に失敗した場合は前の系統の文面を流用せず、出力を止めて再取得を案内する。
- 複数タブで同じ系統の文面や名前を更新した場合は、最後にDB保存された値を採用する。編集中の入力は保存失敗時に保持する。

## ドメイン・責務

`ModelFamily`は系統の識別と名前の制約を担う。人物LoRAは系統IDを保持し、保存ユースケースでその系統が存在することを検証する。`DefaultPrompt`の識別を「種別」から「系統IDと種別」へ拡張する。文面の正規化は既存の`PromptText`へ集約する。

系統の登録・改名・削除、人物LoRAの所属変更、系統別デフォルトの保存はそれぞれ更新ユースケースとする。系統一覧・系統別文面・人物LoRA一覧は参照用DTOを返す。ブラウザーは取得済みの系統と文面をIDで管理し、選択・表示に使う。UIの切り替えだけでサーバー上のデフォルトを変更しない。

## API・永続化と移行

| 目的 | メソッド・URL | 主な入出力 |
| --- | --- | --- |
| 系統一覧 | `GET /model-families` | `[{id, name}]`。Illustriousを含む |
| 系統の追加 | `POST /model-families` | `{name}` → `{id, name}` |
| 系統の改名 | `PUT /model-families/{family}` | `{name}` → `{id, name}` |
| 系統の削除 | `DELETE /model-families/{family}` | 未使用時204、使用中またはIllustriousは409 |
| 系統別デフォルト取得 | `GET /model-families/{family}/default-prompts` | `{positive, negative}` |
| 系統別デフォルト保存 | `PUT /model-families/{family}/default-prompts/{polarity}` | `{content}` → `{polarity, content, formatSucceeded}` |
| 人物LoRA一覧・保存 | 既存の`/lora-prompt-options`・`/loras` | 人物LoRAに`modelFamilyId`を追加。保存時は必須 |

入力不正は422、存在しないIDは404、削除できない系統は409を返す。更新はCSRF保護を適用する。系統追加時は系統と二つの空文面を一トランザクションで保存する。削除時も文面との整合性を一トランザクションで守る。

`model_families`はID、名前、一意比較用の正規化名、日時を保持する。`loras`には人物用途に必須の`model_family_id`外部キーを加える。衣装用途ではNULLとし、用途と所属の組み合わせをDB制約と更新ユースケースで守る。`default_prompts`は系統IDと種別を複合キーにし、各系統で二件までを一意にする。LoRAと文面は系統の存在を外部キーで保証する。

移行では一件の Illustrious を作り、既存positive／negative文面をその系統の二件へそのまま移す。既存の人物LoRAをすべてその系統へ紐づける。衣装LoRAはNULLのままとする。Seederの再実行では Illustrious と欠けた初期文面だけを補い、編集済み文面、空にした文面、既存LoRAの所属を上書きしない。移行前後の件数と内容を検証し、データが期待と異なる場合は破壊的に推測せず移行を失敗させる。

## お気に入りとの境界

お気に入りには完成したpositive／negativeを引き続き正本として保存する。呼び出し時は人物LoRAの復元に成功したらその所属系統を有効系統とし、現在の系統別デフォルトで比較用文面を作る。人物LoRAがない場合は Illustrious を用いる。登録後にLoRAの所属系統や文面が変わって再生成結果が異なる場合は、F04の部分復元通知を出し、保存済みの完成文面は書き換えない。

F11の人物LoRA差し替えコピーで別系統の候補を選んだ場合は、人物LoRA・トリガーに加え、コピー用positive／negativeのデフォルト部分を両方とも候補系統の文面へ切り替える。元の出力欄は変更せず、候補ごとのpositiveとnegativeをそれぞれコピーできる画面にする。同系統の候補では既存の両デフォルトをそのまま使う。手編集を含む詳細な置換規則はF11に定める。

## 受入条件と検証

| 要件 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| R01・R03 | anima系統を登録する | 空のpositive／negativeが作られ、Illustriousの文面は変わらない |
| R02・R04 | animaへ紐づけた人物LoRAを選んで表示する | animaの選択中デフォルト文面と人物LoRAのタグ・トリガーが出力され、Illustriousのデフォルトは入らない |
| R03 | animaのnegativeだけ編集して再取得する | animaのnegativeだけが整形済み文面へ変わる |
| R03 | Illustriousとanimaそれぞれに異なるpositive／negativeを保存して再読み込みする | どちらの系統も両側の文面を個別に再取得・再編集できる |
| R04 | 出力後に人物LoRAをIllustriousの別LoRAへ変更する | 出力欄はそのままで、次の表示時にIllustriousの文面へ切り替わる |
| R05 | 既存DBに移行を適用する | 現在の文面と全人物LoRAがIllustriousに紐づき、衣装LoRAは変わらない |
| R05 | 編集済み文面と系統変更済みLoRAがある状態でSeederを再実行する | 既存の文面と所属先が保持される |
| R06 | 使用中の系統を削除する | 409となり、系統・LoRA・文面は残る |
| R06 | 系統別文面の取得に失敗して表示を押す | 前に選んだ別系統の文面では出力せず、再取得を案内する |
| R06 | 系統を改名する | 所属LoRAと文面は同じIDを参照し、名前だけが変わる |
| R04 | 人物LoRAを選ばずに表示する | Illustriousの選択中デフォルト文面が出力される |
| R04 | 人物LoRAを選び直してから全体リセットする | 出力系統が Illustrious に戻り、デフォルトの選択状態は従来どおり維持される |
| R04 | 別系統の人物LoRAへ差し替えコピーする | コピー用positive／negativeの両方に候補系統のデフォルトが入り、元の出力欄は変わらない |

更新ユースケース、SQLite移行、HTTP契約、画面での切り替えとお気に入り復元を検証する。

## 設計上の判断と確認事項

- 系統は自由入力文字列をLoRAごとに複製せず、独立した登録対象にする。改名時の一括反映と名前の揺れ防止のためである。
- デフォルト文面は系統をキーとして保存し、人物LoRA選択から出力系統を導く。系統ごとにオプションを複製することは今回の目的に含めない。
- Illustriousを人物LoRA未選択時の基準とする。別系統へのF11差し替えコピーではpositive／negative両方のデフォルトを候補系統へ切り替える。
- 別系統への差し替えコピーでは、元のデフォルト区間を安全に識別できる場合だけ置換する。区間内を手編集して識別できない場合は、誤った文面をコピーしないよう操作を止める。詳細はF11に定める。
