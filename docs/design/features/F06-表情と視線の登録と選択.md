# F06 表情・視線の登録と選択

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F01](F01-デフォルトプロンプト.md)、[F02](F02-プロンプトの選択と表示.md)、[画面設計](../画面設計.md)。

## 目的と背景

利用者が、同時に成立する複数タグを表情または視線として登録し、必要な表情を組み合わせて再利用できるようにする。

「口を開けて笑う」は`smile`と`open mouth`のように複数タグを必要とする。実際の利用では、表情を細かな部品として組み合わせることで多くのパターンを作れるため、登録した表情候補は複数選べるようにする。一方、カメラ目線と目線外しのような視線は同時に成立しにくいため、視線は最大一つに保つ。

## 要件

| ID | 要件 |
| --- | --- |
| F06-R01 | 表情に登録名と一つ以上のタグを含む文面を保存できる |
| F06-R02 | 表情は登録名を表示するバッジから複数候補を選択・選択解除できる |
| F06-R03 | 表情を登録名でブラウザー内検索できる |
| F06-R04 | 視線に登録名と一つ以上のタグを含む文面を保存できる |
| F06-R05 | 視線は未選択または一候補だけを選択できる |
| F06-R06 | 表情と視線を追加・編集・削除できる |
| F06-R07 | 選択した表情と視線をそれぞれpositiveのセクションとして出力候補へ渡す |

## 選択画面の振る舞い

表情には検索欄と、登録名だけを表示する複数選択バッジを置く。バッジを押すたびにその候補だけの選択・選択解除を切り替え、選択状態は色、チェック表示、`aria-pressed`で示す。候補領域には複数行分の高さを確保し、候補が増えた場合は領域内を縦にスクロールする。検索は取得済み候補の登録名に対する、大文字・小文字を区別しない部分一致とし、サーバー通信を行わない。

視線は検索欄を設けず、複数行が見えるスクロール可能な単一選択リストから選ぶ。表情・視線とも初期状態は未選択とする。視線には選択解除操作を用意し、別の候補を選ぶと以前の選択を解除する。

表情の検索で選択中の候補が一致しない場合も、選択を見失わないよう検索結果に残す。一覧は名前・ID順を維持し、選択や検索によって候補の位置を変えない。検索操作だけでは選択状態を変えない。

一覧は登録名の昇順、同じ登録名ではIDの昇順とする。この順序を表情バッジの表示と出力結合の共通順序とし、選択順によって出力を変えない。視線の長い登録名は折り返さず、候補リスト内を横にスクロールして全文を確認できるようにする。

## ユースケース

### 候補を登録・編集する

利用者は対象カテゴリの管理操作を開き、登録名と文面を入力して保存する。サーバーは入力形式と業務上の不変条件を検証し、文面を整形して保存する。成功後は一覧を再取得する。編集中の入力は保存成功まで保持し、失敗時に消さない。

### 候補を選択して出力する

利用者は表情から必要な候補を複数選び、視線から一候補までを選んで「プロンプトを表示」を実行する。表情は選択済み文面を一覧順で一つのセクションにまとめ、視線は選択した文面を独立したセクションとしてpositiveの出力候補へ渡す。選択だけでは保存済み候補や表示済み出力を変更しない。

### 候補を削除する

削除前にカテゴリ、登録名、文面のプレビューを表示して確認する。削除成功後、対象が選択中ならそのカテゴリの選択を解除する。別カテゴリの選択と既存出力は維持する。

## 登録・整形・業務ルール

表情と視線は、利用者が一覧で識別する登録名と、positiveへ出力する文面を持つ。文面には複数タグを登録できるが、整形後に一文字以上あることを必須とする。

文面は`PromptText`でF01と同じ規則に整形する。登録名は前後の空白を除いた後も一文字以上を必須とする。登録名と文面の重複は許容する。同じ名前がある場合も管理対象を識別できるよう、編集・削除時には文面のプレビューとIDを併記する。

表情と視線は互いに独立した登録情報とする。表情の選択によって視線を自動選択せず、視線の選択によって表情を変更しない。表情の複数選択数には上限を設けない。

## データ・責務・API

更新用ドメインモデルは`ExpressionPrompt`と`GazePrompt`に分ける。見た目の項目が同じでも、選択理由と今後の変更理由が異なるため、カテゴリ文字列だけを持つ一つの汎用モデルにはまとめない。参照は画面用の一つのQueryから両一覧を返してよい。

| 目的 | メソッド・URL |
| --- | --- |
| 表情・視線一覧を取得 | `GET /character-directions` |
| 表情を追加・編集・削除 | `POST /expressions`、`PUT・DELETE /expressions/{expression}` |
| 視線を追加・編集・削除 | `POST /gazes`、`PUT・DELETE /gazes/{gaze}` |

`expression_prompts`と`gaze_prompts`に整数ID、登録名、整形済み文面、作成・更新日時を保存する。更新系はCSRF保護を適用する。不正入力は422、存在しないIDは404、削除成功は204とする。

各更新は一候補をトランザクション境界とする。認証は設けず個人利用とする。登録名・文面にはDB上の一意制約を設けない。

## 出力と状態

選択した表情の文面を一覧順で結合し、括弧の外側にあるカンマをタグの区切りとして完全一致するタグの重複を除いた一つのpositiveセクションにする。`smile`と`smile`は一つにし、`smile`と`(smile)`は別のタグとして残す。括弧の対応が壊れて安全に分割できない文面を含む場合は、内容を壊さず候補間を半角スペース一つでつなぐ。視線は選択した一候補を独立したpositiveセクションとして渡す。全カテゴリでは、デフォルト、人物・キャラクターLoRAタグ、そのトリガー、表情、視線、衣装LoRAタグ、衣装LoRAトリガー、服装、動作、場所、構図、追加順のオプションブロックとする。未選択のカテゴリは出力しない。選択変更や登録情報の更新だけでは表示済み出力を変更せず、次の「プロンプトを表示」で反映する。

保存・削除後は一覧を再取得する。選択中の候補を編集した場合は選択を維持し、削除した場合は解除する。取得失敗時は未登録として扱わず再取得を案内する。保存・削除中は同じ操作の重複実行を防ぎ、失敗時は入力内容・一覧・選択状態を保持する。

## 受入条件

| 要件 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| R01・R02 | `笑顔`に`smile, open mouth`を登録して選ぶ | 二つのタグを含む一つの表情候補として選択される |
| R02 | 笑顔と口を開けるのバッジを選ぶ | 両方が選択状態になり、他の表情候補も選択できる |
| R02 | 選択中の笑顔をもう一度押す | 笑顔だけが解除され、他の表情選択は維持される |
| R02・R05 | ページを開く | 表情と視線は未選択で始まる |
| R03 | 表情名の一部を検索する | 通信なしで一致する候補と選択中の候補が表示される |
| R04・R05 | カメラ目線を選択後に目線外しを選ぶ | 目線外しだけが選択状態になる |
| R06 | 選択中の表情を削除する | 表情の選択が解除され、既存出力は次の表示まで変わらない |
| R07 | `smile, open mouth,`と`open mouth, blush,`の表情、視線を選択して表示する | 表情は`smile, open mouth, blush,`の一セクションとなり、視線とは空行一つで区切られてpositiveへ入り、negativeは変わらない |
| R01・R04 | 空白とカンマだけの文面を保存する | 422となり登録されない |

## 設計上の判断

- 表情と視線は人物の状態を表すため、服装・動作・背景より前に出力する。
- 表情は利用時の組み合わせで多くのパターンを作れることを優先して複数選択とし、視線は矛盾する指定を避けるため最大一つとする。
