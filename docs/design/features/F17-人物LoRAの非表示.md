# F17 人物LoRAの非表示

- 状態：設計案。消さずに非表示にする目的と、人物選択・差し替え候補に共通の非表示設定を適用することは確認済み。
- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F04](F04-お気に入りプロンプト.md)、[F05](F05-LoRAの登録と選択.md)、[F11](F11-人物LoRAの差し替えコピー.md)、[F13](F13-ComfyUIへのキュー送信.md)、[F14](F14-人物LoRAの生成設定.md)、[F15](F15-選択画面の整理と管理操作の分離.md)。

## 目的と背景

使用頻度の低い人物LoRAを、登録情報・トリガー・服装を削除せず日常の一覧から外す。必要になれば再表示して再利用できるようにする。

## 要件・範囲

| ID | 要件 |
| --- | --- |
| F17-R01 | 人物LoRAを非表示・再表示でき、再読込後も設定を保持する |
| F17-R02 | 非表示の人物と所属トリガー・服装を日常の候補から除外する |
| F17-R03 | 差し替えコピーと一括送信の候補から非表示人物の全トリガー組み合わせを除く |
| F17-R04 | 管理では非表示人物を検索・編集・再表示できる |
| F17-R05 | 非表示で登録情報、既存出力、お気に入り、送信済みジョブを失わない |
| F17-R06 | 非表示前の一括チェック状態が誤送信を起こさない |

人物LoRA単位の一つの共通設定を採用する。人物選択一覧と差し替えコピー候補の両方に適用する。衣装LoRA、所属トリガー単独、服装単独、オプション単独の非表示は対象外。非表示は一覧整理であり削除・アクセス権・ファイル無効化ではない。

## ユースケース

実行者は個人利用者。

1. **非表示にする**：人物管理で一件の「非表示」を押す。対象が存在することを確認し状態を保存する。成功後、選択一覧と差し替え候補から除外する。保存失敗は状態を変えず再操作を案内する。
2. **再表示する**：管理の表示状態を「非表示」に絞り、人物を検索し「再表示」を押す。既存の情報とIDのまま候補に戻る。選択と一括チェックは自動追加しない。
3. **過去の出力を使う**：非表示後も完成済み出力やお気に入りをコピーする。文字列は保持し、再生成とは区別する。

## 業務ルール

- 新規・既存人物は表示中を初期値とする。親人物の表示状態からトリガー・服装の候補表示を導き、子へ同じフラグを複製しない。
- **提案：選択中人物を非表示にした場合**は今回の人物・そのトリガー・服装を解除し、人物なしの系統へ戻す。保存済み情報と完成済み出力は保持し、「選択を解除しました。出力へ反映するには再表示してください」と通知する。非表示操作の直前にもこの影響をフォーム内に示す。
- お気に入り呼び出しでは完成済みpositive／negativeと登録時の説明をそのまま復元する。非表示人物とその子は今回の選択へ復元せず、その旨を通知する。再表示後に再び呼び出せば選択可能になる。
- 通常送信は完成済み出力を作った人物のF14設定を使える。非表示を理由に過去の完成出力のコピー・通常送信を拒否しない。送信対象人物を現在選択から取り違えない。
- 差し替え候補と一括チェックの正本を分離し、送信時の有効対象は「保存チェック ∩ 現在表示可能な候補」。検索／ページによる絞り込みは非表示と区別する。全非表示なら空状態と管理入口を示し、取得失敗とは区別する。
- 非表示になった全候補キーのチェックは解除してブラウザーへ保存する。再表示しても自動チェックしない。候補が初めて登録・検出された場合の初回チェックはF13を維持する。キーが消えたときの設定整理と、再表示後の未チェックを区別できるよう既知候補キーを記録する。
- 系統変更・削除可否や生成設定の使用判定では非表示人物も存在するものとして扱う。非表示にしても参照中設定は削除可能にならない。

## ドメイン・API・画面

人物`Lora`へ`isHidden`を追加し、用途が人物であることを更新モデルが保証する。状態設定は明示的なbooleanで行い、toggle APIにしない。同じ値を再設定しても同じ結果となる。

| 操作 | 契約案 |
| --- | --- |
| 表示状態保存 | `PATCH /loras/{lora}/visibility`、`{isHidden: boolean}` → 200と`{id,isHidden}`（既存JSON形式へ合わせる） |
| 既存一覧 | `GET /lora-prompt-options`の人物に`isHidden`を追加し、通常は非表示人物と子を取得対象から除外 |
| 管理一覧 | 同APIへ`visibility=visible|hidden|all`を追加。省略はvisible。管理にはall／hiddenを利用 |
| 完成出力・お気に入りの参照 | IDを指定する既存の復元・送信用参照経路は非表示でも取得可能とする |

管理には「表示中／非表示／すべて」のフィルターと表示状態を置く。通常画面から一時的に非表示候補を混ぜる操作は設けず「非表示を管理」から管理へ移動する。

一覧Queryが表示条件をDB取得へ適用し、通常レスポンスに非表示人物の子を混ぜない。管理Queryは表示状態を明示する。更新は`Writes/ChangeCharacterLoraVisibility`、参照は既存Queriesの拡張とし、ControllerからDBへ直接アクセスしない。認証なし・同一オリジン・CSRF保護を維持する。不正boolean／衣装用途は422、人物なしは404、セッション期限切れ419、障害5xx。

F13の一括・候補単独送信ではサーバーも人物の表示状態を再確認する。ブラウザーが古い候補を送った場合はその候補を失敗とし、外部送信しない。通常送信と候補送信を区別する入力`source=output|characterVariant`を追加する案とし、候補時は人物IDを必須とする。この区分は一覧整理の規則であり認可を表さない。候補を非表示にした後に既に受理済みのComfyUIジョブを取り消さない。

## 永続化・整合性・失敗

既存`loras`へboolean相当`is_hidden`、既定falseを追加する案。衣装はfalse固定とし更新不可。子テーブルは変更しない。既存ID、強度、系統、三生成設定、トリガー、服装、お気に入りを保持する。利用者共通のサーバー保存としlocalStorageだけの設定にしない。

一人物の状態変更を一更新単位とし、最後の確定保存を採用する。保存成功後に候補を再取得し、ページが空なら有効な直前ページへ戻す。結果不明時は再取得するまで当該候補操作を停止し、勝手に再送しない。

差し替え画面を開く際と送信開始前に最新表示状態を取得する。他タブの変更を開きっぱなしの画面に常時同期する仕組みは対象外。サーバー再確認後から外部受理までに非表示にした場合は送信を取り消せないため、状態確認時点で対象を確定したことを仕様とする。外部通信中にDBロックを保持しない。

## 受入条件と検証

| 要件 | 前提／操作 | 期待結果 |
| --- | --- | --- |
| R01・R02 | トリガー・服装付き人物を非表示にし再読込 | 人物と子が通常候補から消え、保存情報は残る |
| R03・R06 | 一括チェック済み人物を非表示 | 全組み合わせが対象から消え、件数減少、外部送信なし |
| R04 | 管理で非表示人物を検索し再表示 | 元IDと登録値のまま戻り、選択・チェックは追加されない |
| R05 | 選択中人物を非表示 | 人物と子の選択を解除し通知するが、完成出力を変えない |
| R05 | 非表示人物入りお気に入りを呼び出す | 保存文面を復元し、選択の非復元を通知する |
| R05 | 非表示前の完成出力を通常送信 | 出力時人物の最新生成設定を使用し、送信できる |
| R06 | 古い候補IDを候補送信APIへ送る | 非表示候補は失敗とし外部送信しない。他候補は継続する |
| R01 | 保存失敗または衣装用途の更新要求 | 表示状態と子情報を変更しない |
| R02・R04 | 全人物を非表示にする | 通常候補は空状態、管理は全人物を取得できる |

実装時は表示条件付きQueries、状態Writes、お気に入り復元、ブラウザー保存チェックとの交差、ComfyUI Fakeで非送信を検証する。

## 確認済み事項

- Q01は「人物選択一覧と差し替えコピー候補で共通の非表示設定」で解決済み。
- 保存フラグは人物LoRAごとの`isHidden`一つとし、所属トリガー・服装の候補表示も親人物の状態から導く。
