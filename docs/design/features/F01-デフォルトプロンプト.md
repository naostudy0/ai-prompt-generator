# F01 デフォルトプロンプトの登録・編集・取得

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F02](F02-プロンプトの選択と表示.md)。

## 目的と背景

普段使うpositive／negativeの文面をまとめて登録し、次のプロンプト準備でも利用できるようにする。
長い文面を他からコピーして取り込むことが多いため、各側一つのテキストエリアで全文を扱う。

## 要件

| ID | 要件 |
| --- | --- |
| F01-R01 | positive／negativeを区別してデフォルト文面を扱う |
| F01-R02 | 各側の編集ボタンから文面全体を一つのテキストエリアで編集する |
| F01-R03 | 貼り付けた文面への追記・置換・一部削除ができる |
| F01-R04 | 空文字列を許容し、内容を消せる |
| F01-R05 | ページロード時にデフォルト文面を取得し、選択・編集に使える状態にする |
| F01-R06 | サーバー側のSQLiteに保存し、再読み込み後も再利用できる |
| F01-R07 | 保存時に語句の区切りをカンマと半角スペースに整え、空でない文面の末尾にカンマを付ける |
| F01-R08 | カンマのない改行を区切りとして補完し、空の要素と重複する文面を除去する |
| F01-R09 | Seederでpositive／negativeの初期文面を登録する |

## 操作の流れ

1. ページロード時に両側の文面を取得する。
2. positiveまたはnegativeの編集ボタンを押す。
3. 同じページ内で、その側の保存済み文面を編集用テキストエリアに表示する。編集中は出力の表示操作を無効にする。
4. 利用者が編集し、「保存」で確定する。「キャンセル」で保存前の文面へ戻る。
5. 保存成功後、整形済みの文面で画面内の保存済み文面と編集欄を更新する。もう片側の文面は保持する。

取得中は編集・出力生成を待機させる。取得失敗は未登録の空データと区別して通知し、再取得できるようにする。
保存中は重複送信を防ぐ。失敗時は入力した文面を保持して再操作できるようにし、保存成功を表示しない。

## 保存時の文面の整形

保存時に`abc, def,`の形へ整える。語句間のカンマの直後は半角スペース一つとし、空でない文面の末尾はカンマとする。
末尾のカンマは、後続のプロンプトの先頭文字と最後の語句が結合することを防ぐために付ける。末尾カンマの後には保存用のスペースを付けない。
空文字列は空のまま保存する。整形済みの文面を再保存しても結果が変わらないようにする。
カンマのない改行も語句の区切りとして扱い、保存時にはカンマと半角スペースでつなぐ。連続カンマによる空の要素を除去する。
重複の単位は、区切りまでの文面一つとする。同じ文面が複数ある場合は一つにまとめる。強さを指定する操作は別途扱う。
各要素の前後の空白を取り除いて完全一致で比較し、最初に出現した要素を残す。大文字・小文字、要素内の空白、重み付け記法が異なる文面は別の要素として扱う。空白や区切りだけの入力は空文字列になる。
取得時は保存済みの整形結果を返す。

| 入力 | 保存・再取得する文面 |
| --- | --- |
| `abc,def` | `abc, def,` |
| `abc,  def,` | `abc, def,` |
| `abc, def,` | `abc, def,` |
| `abc` | `abc,` |
| `abc\ndef`（`\n`は改行） | `abc, def,` |
| `abc,\ndef` | `abc, def,` |
| `abc,, def, abc,` | `abc, def,` |
| 空文字列 | 空文字列 |

セクション間の空行はF02の表示処理で付ける。

### 特殊記法の保護

括弧内などの特殊記法は、意味を壊さないことを整形より優先する。初期実装では丸括弧を保護の対象とする。
対応が取れている`()`は括弧を含む全体を一まとまりとして扱い、その内部のカンマ・改行・空白は保持する。重複判定でも内部を分割せず、まとまり全体で比較する。
例えば`(abc,def:1.2),ghi`は`(abc,def:1.2), ghi,`とし、括弧内の一部を外側の要素と重複扱いにしない。
括弧の不一致や解釈できない構文がある場合は、原文を保持する扱いとし、整形できたと表示しない。フォールバック時は通常の整形後の書式保証を適用しない。
丸括弧の入れ子と、バックスラッシュでエスケープされた丸括弧に対応する。その他の種類の括弧は通常の文字として扱う。

| 入力 | 保存する文面 |
| --- | --- |
| `(abc,def), abc, (abc,def)` | `(abc,def), abc,` |
| `(abc,abc), abc` | `(abc,abc), abc,` |
| `(abc:1.2), (abc:1.3), abc` | `(abc:1.2), (abc:1.3), abc,` |
| `(abc,def` | `(abc,def`（全文を原文のまま保存） |

| 条件 | 保証すること |
| --- | --- |
| 事前条件 | 対象種別と文面が指定されている。空文字列も有効な指定である |
| 不変条件 | 種別はpositive／negativeのいずれかで、文面は文字列である |
| 事後条件 | 指定した側の整形済み文面（解釈できない場合は原文）が保存され、再取得した文面と一致する。もう片側は変わらない |

個人利用・認証なしとし、保存対象は種別で識別する。アプリ内でpositive／negativeを各一つ管理する。
利用者が外部から長いプロンプトを貼り付ける用途のため、初期実装では業務上の文字数上限を設けない。DBの`TEXT`型で保存できない規模が実際に必要になった場合に見直す。

## DDDと処理の配置

業務の文脈名は`PromptPreparation`とする。

| 責務 | 配置 |
| --- | --- |
| 種別とデフォルト文面の整合性 | `Domain/PromptPreparation/Models/DefaultPrompt/` |
| 文面の確定手順 | `Application/PromptPreparation/Writes/SaveDefaultPrompt/` |
| 両側の文面取得と参照DTO | `Application/PromptPreparation/Queries/GetDefaultPrompts/` |
| 保存の契約 | `Domain/PromptPreparation/Repositories/DefaultPromptRepository` |
| 取得の契約 | `Application/PromptPreparation/Ports/DefaultPromptQueryService` |

各種別のデフォルト文面を一つの更新単位とする。保存時の整形と特殊記法の保護は値オブジェクト`DefaultPromptText`が担う。
保存用文面の整形ルールはDomainで表現し、更新ユースケースから適用する。保存成功の応答には整形後の文面を含め、画面とDBの値を揃える。
SQLiteへの保存を担うRepository実装とEloquentモデルをInfrastructureへ配置する。

## API・永続化

保存先はサーバー側のSQLiteとする。

| 目的 | メソッド・URL | 入力 | 成功時 |
| --- | --- | --- | --- |
| 両側を取得 | `GET /default-prompts` | なし | `200 {"positive":"...","negative":"..."}` |
| 一方を保存 | `PUT /default-prompts/{polarity}` | `{"content":"..."}` | `200 {"polarity":"positive","content":"...","formatSucceeded":true}` |

- `{polarity}`は`positive`または`negative`。それ以外は404を返す。
- `content`は必須の文字列。空文字列を許容し、未指定・`null`・文字列以外は422を返す。
- `formatSucceeded`は通常の整形規則を適用できたかを表す。解釈できない特殊記法を原文保存した場合は`false`とする。
- `PUT /default-prompts/{polarity}`は`TrimStrings`と`ConvertEmptyStringsToNull`による変換の対象外とし、`content`を受信した文字列のまま検証してユースケースへ渡す。
- 同じ内容を再保存しても文面が重複追加されない操作とする。
- 同じ種別を複数タブから保存した場合は、DBで最後に保存が完了した文面を採用する。
- 認証なしでもWebミドルウェアのCSRF保護は適用する。

`default_prompts`テーブルは`polarity`を主キーとし、`content`を`TEXT`、作成・更新日時を保持する。所有者キーは設けない。

### 初期データ

Seederから次の初期文面を登録する。末尾はカンマまでとし、その後に空白を付けない。

| 種別 | 初期文面 |
| --- | --- |
| positive | `masterpiece, best quality, highres,` |
| negative | `bad anatomy, bad hands, extra fingers, missing fingers, extra limbs,` |

Seederでも保存時と同じ整形ルールを適用し、未登録の種別だけを作成する。再実行時に利用者が編集した値や空にした値を上書きしない。

## 受入条件

| 要件 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| R01・R03・R07 | positiveに`masterpiece, amazing quality`を保存し取得する | positiveに`masterpiece, amazing quality,`が返り、negativeは元の値のまま |
| R02 | negativeの編集ボタンを押す | negativeの全文を一つのテキストエリアで編集できる |
| R03・R07 | `(best quality:1.2),abc`を保存する | `(best quality:1.2), abc,`が返り、順序と重み付けが保持される |
| R07 | `abc,  def`を保存して再取得し、その結果を再保存する | どちらも`abc, def,`となる |
| R04 | 既存文面を空にして保存する | 再取得した文面が空で、以前の文面が復活しない |
| R05 | 取得に失敗する | 未登録と表示せず、取得エラーと再試行手段を表示する |
| R06 | 文面を保存してページを再読み込みする | 保存した文面をSQLiteから取得できる |
| R08 | `abc\ndef,,abc,`を保存する | `abc, def,`が返る |
| R08 | `(abc,abc), abc, (abc,abc)`を保存する | `(abc,abc), abc,`となり、括弧内は保持される |
| R07・R08 | 括弧が閉じていない`(abc,def`を保存する | 全文を原文のまま保存し、整形成功として通知しない |
| R01・R03 | 同じ種別に二つのタブから順に保存する | 最後にDB保存が完了した文面が再取得される |
| R09 | 未登録の状態でSeederを実行する | 両側に確定した初期文面が登録される |
| R09 | デフォルトを編集・保存した後にSeederを再実行する | 保存済みの文面が保持される |

テストでは入力文面と期待文面をテストメソッド内に明示する。保存方式に応じて更新・取得のテストと画面操作を検証する。
