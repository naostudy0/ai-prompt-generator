# F16 選択項目に連動するネガティブ

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F01](F01-デフォルトプロンプト.md)、[F02](F02-プロンプトの選択と表示.md)、[F04](F04-お気に入りプロンプト.md)、[F05](F05-LoRAの登録と選択.md)、[F08](F08-オプション項目の登録と選択.md)、[F09](F09-衣装LoRAの登録と複数選択.md)、[F11](F11-人物LoRAの差し替えコピー.md)、[F12](F12-人物LoRAの系統と系統別デフォルト.md)、[F13](F13-ComfyUIへのキュー送信.md)、[F15](F15-選択画面の整理と管理操作の分離.md)。

## 目的と背景

特定のオプションが似た別のものとして解釈されるのを抑える文面を、その選択時だけnegativeに含めたい。共通デフォルトに常時入れると無関係な選択まで制約するため、登録項目に任意のnegativeを持たせる。

## 要件・範囲

| ID | 要件 |
| --- | --- |
| F16-R01 | 対象登録項目に任意のnegative文面を保存・編集・空欄化できる |
| F16-R02 | 選択した項目のnegativeだけを次の表示操作で出力する |
| F16-R03 | negativeデフォルトの選択と項目連動negativeを独立させる |
| F16-R04 | 完全一致する連動negativeタグの重複を除き、特殊記法を保護する |
| F16-R05 | 直接編集・お気に入り・人物差し替え・ComfyUI送信で文面を失わない |

対象は**F08のオプション項目、人物LoRAに属する服装、衣装LoRAのトリガー**。利用者確認により人物LoRAのトリガーは対象外とする。「タグ」は文面内の単語ではなく、利用者が選ぶ登録項目を単位とし、各項目に`negativeContent`を追加する。

デフォルトそのもの、人物LoRAのトリガー、LoRAファイルタグ、オプションブロック全体へのnegative設定、タグ同士の意味的な矛盾検知、系統別negativeの自動変換、画像品質の保証は対象外。

## ユースケース

実行者は個人利用者。

1. **登録する**：管理で対象項目を開き、positive文面と任意negative文面を入力する。事前条件は対象と所属先が存在すること。既存整形規則で保存し、成功後に管理と候補データへ反映する。空欄でnegativeを解除できる。入力・通信失敗ではpositiveもnegativeも変更せず、両入力を保持する。
2. **出力する**：negative付き項目を選んで「プロンプトを表示」を押す。選択済みデフォルトと選択項目のnegativeを順に結合する。項目を解除して再表示すれば、その項目だけを由来とするnegativeが消える。他項目も同じ文面を要求していれば残る。
3. **再利用する**：手編集した出力をコピー・保存・送信する。出力欄の現在値を用い、送信時に登録negativeを勝手に追記しない。再表示したときだけ最新登録文面から再構築する。

## 業務ルール

- 任意negativeは`PromptText`の既存整形に従う。空／空白のみ／整形後空は空文字列で保存し、必須にしない。括弧の外のカンマ・改行、末尾カンマ、完全一致の比較規則はF01・F08と揃える。
- 「negativeデフォルト」を解除しても、選択中項目の連動negativeは出力する。ラベルを「共通negativeを使用」と補足し、全negativeのオン／オフと誤認させない。全negativeを空にしたい場合は出力欄を手編集できる。
- negativeは「選択中の系統別デフォルト」「選択した衣装LoRAのトリガー（衣装LoRA表示順）」「選択した人物所属服装」「ブロック順のオプション連動negative」の順。空は省き、セクション間は空行一つ。
- オプションの連動negativeはブロック・項目順で処理し、ブロックをまたいで完全一致重複を除く。デフォルトとの境界と、衣装／服装由来との境界では重複を保持する。由来を特定した安全な差し替えを優先し、デフォルトの文面を変更しないためである。
- positiveとnegativeは別々に処理する。positiveの完全一致重複除去である項目のpositiveが見えなくても、その項目が選択中ならnegativeを出す。意味的な矛盾を自動解決しない。
- 選択・保存・移動では表示済み出力を変えない。出力欄の手編集は登録negativeを更新しない。リセットは登録値を保持する。

## ドメイン設計

対象の既存モデルが空を許容する`PromptText`として任意negativeを保持する。positive必須の検証をそのままnegativeへ流用しない。新しい独立したnegative集約やnegative専用CRUDは作らず、対象項目の保存単位で両文面を一緒に更新する。

Applicationの既存Writes入力・ResultとQueriesのDTOに`negativeContent`を追加する。整形と許容条件はDomainが保証し、表示側の結合処理はDOMと分けた純粋関数で行う。検索対象は登録名のままとする。

## 入出力と画面

F15管理フォームに「positive文面」と「この項目を選んだときのnegative（任意）」を置く。通常候補に長いnegativeを表示せず、詳細で確認する。出力欄と右側概要の基本構造は維持する。

| API | 拡張契約 |
| --- | --- |
| `GET /prompt-options` | 各optionに`negativeContent: string`を追加 |
| `POST /prompt-options` | 既存入力に任意`negativeContent`を追加。省略・nullは空として保存 |
| `PUT /prompt-options/{option}` | `negativeContent`指定で更新、空／nullで解除、省略時は既存値を保持 |
| `/outfits`、`/clothing-lora-triggers`のPOST／PUTと既存一覧 | 同じ契約を追加。人物一覧内のoutfits、衣装一覧内のtriggersへ文字列を返す |

成功のステータス・JSON包み形式は既存APIに従う。形式不正は422、対象なし404、セッション期限切れ419、障害5xx。認証なしの個人利用とCSRF保護を維持する。旧クライアントによる省略で保存済みnegativeを消さない。

## お気に入り・差し替え・送信

- F04は完成文面をそのまま保存・復元する。登録negativeの変更後も呼び出しだけで本文を再生成しない。選択復元後の「表示」は最新値を用いる。
- F11の同系統候補はnegativeを維持し、別系統ではF12どおりデフォルト区間だけを変える。オプション・服装・衣装トリガー由来negativeは全候補で維持する。人物所属服装は元人物に属していてもpositiveを残す既存F11仕様に合わせ、そのnegativeも残す。
- 人物トリガーは対象外のため、新しい人物negativeの差し替えメタデータは不要。既存の系統デフォルト区間メタデータを使用し、連動negativeをデフォルト区間へ混ぜない。古いお気に入りの完成文面にも、現在の登録negativeを呼び出し時に自動追加しない。
- F13の通常送信は現在の完成文面、候補送信は本仕様とF11/F12で確定した両文面を使う。片側差し替え失敗の候補を送信しない。一括では候補単位の失敗として残りを続行する。

## 永続化・移行・失敗時

対象テーブルに`negative_content`（text、空文字列を既定）を追加。既存のID、positive、所属、順序を変えず、既存全件のnegativeを空で初期化する。対象テーブルは`option_prompts`、`outfits`、`lora_triggers`。衣装と人物は既存の`lora_triggers`を共有するため、negative保存は親LoRAの用途がclothingの場合だけ許可し、人物トリガーでは空固定とする。人物トリガーAPIから非空negativeを指定した場合は422とする。お気に入りの新しい出力メタデータ追加は不要。

一項目の両文面は同一トランザクションで保存。個人利用の最後の保存優先を維持する。保存中は二重更新を防ぎ、失敗時は両入力を保持する。必要な選択項目のnegativeが取得できなければ、不完全なnegativeを成功表示せず再取得を案内する。未選択カテゴリの取得失敗は既存F02の扱いを維持する。外部サービスの追加はない。

## 受入条件と検証

| 要件 | 前提／操作 | 期待結果 |
| --- | --- | --- |
| R01 | negative未入力で登録、後から設定し空に戻す | すべて保存でき、再読込でもそれぞれの値を保持する |
| R02・R03 | 共通negativeを解除し、negative付き項目を選び表示 | 選択項目のnegativeだけを出力する |
| R02 | 同じnegativeを持つ二項目から片方だけ解除し再表示 | 他方が由来となるnegativeは残る |
| R04 | 別ブロックに同一negative、括弧内カンマ付きnegativeを登録 | 完全一致重複は一つ、括弧内は分割されない |
| R04 | デフォルトと項目に同じ文面を設定 | 両由来を分離して保持し、デフォルト区間を安全に識別できる |
| R05 | 手編集してお気に入り保存・復元・通常送信 | 手編集後の文面を保持し、登録negativeを追加し直さない |
| R05 | オプション限定で別系統へ差し替える | デフォルトだけを切り替え、オプションnegativeを維持する |
| R02・R05 | 衣装トリガー・服装にnegativeを設定し、人物を差し替える | 選択した衣装と服装由来negativeは候補でも維持される |
| R05 | 連動negativeを手編集して別系統へ差し替える | 手編集を保持し、系統デフォルト区間だけを置換する |
| R01 | positiveとnegativeを変更して保存失敗 | 両方ともDBを変更せず、フォーム入力を保持する |

実装時は整形・選択結合の単体検証、保存・取得・移行・お気に入りのHTTP／DB検証、手編集後の候補コピー／送信を確認する。生成画像が必ず改善することは受入条件にしない。

## 確認済み事項と設計判断

- Q01は「オプション項目・人物所属服装・衣装LoRAトリガーを対象とし、人物LoRAトリガーは除外」で解決済み。
- 共通negativeの選択と項目連動negativeを独立させる。全negativeをまとめて無効化する新規操作は設けない。
- F08の「negativeには追加しない」は本案導入後に更新する。F05の服装、F09のトリガー、F02の出力構成にも本案を適用する。F11の人物差し替え範囲は変えない。
