# F07 場所・構図・動作の登録と選択

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F01](F01-デフォルトプロンプト.md)、[F02](F02-プロンプトの選択と表示.md)、[画面設計](../画面設計.md)。

## 目的と背景

利用者が、再利用できる場所や動作を必要な組み合わせで選び、矛盾しやすい構図は一つに限定してpositiveプロンプトを準備できるようにする。

公園とベンチ、遊園地とベンチのように場所の一部を共用する場合、完成した組み合わせごとに登録すると重複が増える。場所と動作は小さな意味のまとまりを複数選択できるようにし、今回必要な組み合わせを作る。正面と横からの構図のように同時成立しない候補は最大一つに制限する。

## 要件

| ID | 要件 |
| --- | --- |
| F07-R01 | 場所に登録名と一つ以上のタグを含む文面を保存できる |
| F07-R02 | 場所を複数選択でき、登録名を表示するバッジで選択を切り替えられる。出力時は完全一致するタグの重複を除く |
| F07-R03 | 構図に登録名と一つ以上のタグを含む文面を保存できる |
| F07-R04 | 構図は未選択または一候補だけを選択できる |
| F07-R05 | 動作に登録名と一つ以上のタグを含む文面を保存できる |
| F07-R06 | 動作を複数選択でき、登録名を表示するバッジで選択を切り替えられる |
| F07-R07 | 場所・構図・動作を追加・編集・削除できる |
| F07-R08 | 選択した各カテゴリの文面をpositiveの出力候補へ渡す |

## 選択画面の振る舞い

場所と動作は、登録名だけを表示するバッジを折り返して配置する。バッジを押すたびにその候補だけの選択・選択解除を切り替える。選択状態は色、チェック表示、`aria-pressed`で示す。候補領域には複数行分の高さを確保し、候補が領域を超えた場合は縦にスクロールする。

構図は複数行が見えるスクロール可能な単一選択リストとし、選択解除操作を用意する。場所・構図・動作はページロード時に未選択とし、候補の追加による自動選択を行わない。

場所と動作には今回検索を設けない。バッジによる一覧性で探しにくくなった場合は、実際の登録件数と利用状況を基に検索追加を別要件として設計する。

候補は登録名の昇順、同じ登録名ではIDの昇順に並べる。この順序をバッジ表示と出力結合の共通順序とし、選択した順番によって出力結果が変わらないようにする。

## ユースケース

### 候補を登録・編集する

利用者は対象カテゴリの管理操作を開き、登録名と文面を入力して保存する。サーバーは入力形式と不変条件を検証し、文面を整形して保存する。成功後は一覧を再取得し、編集対象が選択中なら選択を維持する。失敗時は入力を保持する。

### 候補を選択して出力する

場所・動作では必要なバッジを複数選び、構図では一候補までを選ぶ。「プロンプトを表示」を実行すると、場所と動作はカテゴリごとに選択中の文面を安定した一覧順でまとめ、構図は選択した文面をpositiveの出力候補へ渡す。

### 候補を削除する

削除前にカテゴリ、登録名、文面のプレビューを表示して確認する。削除成功後、削除したIDだけを選択状態から取り除く。他候補の選択と既存出力は維持する。

## 登録・整形・業務ルール

各候補は登録名とpositiveへ出力する文面を持つ。文面には複数タグを登録でき、`PromptText`でF01と同じ規則に整形する。登録名と整形後の文面は一文字以上を必須とする。

登録名と文面の重複は許容する。管理操作では同名候補を識別できるよう、文面のプレビューとIDを表示する。場所・構図・動作は相互に独立し、一つのカテゴリの選択変更によって他カテゴリを自動変更しない。

場所と動作の複数選択数には上限を設けない。個人利用であり、出力欄で最終調整できるためである。ブラウザー状態ではIDの集合として保持し、同じ候補を二重に出力しない。

## データ・責務・API

更新用ドメインモデルは`LocationPrompt`、`CompositionPrompt`、`ActionPrompt`に分ける。カテゴリごとに業務上の意味と選択規則が異なるため、カテゴリ列を持つ汎用モデルにはまとめない。参照は画面用Queryから三一覧をまとめて返してよい。

| 目的 | メソッド・URL |
| --- | --- |
| 場所・構図・動作一覧を取得 | `GET /scene-directions` |
| 場所を追加・編集・削除 | `POST /locations`、`PUT・DELETE /locations/{location}` |
| 構図を追加・編集・削除 | `POST /compositions`、`PUT・DELETE /compositions/{composition}` |
| 動作を追加・編集・削除 | `POST /actions`、`PUT・DELETE /actions/{action}` |

`location_prompts`、`composition_prompts`、`action_prompts`に整数ID、登録名、整形済み文面、作成・更新日時を保存する。更新系はCSRF保護を適用する。不正入力は422、存在しないIDは404、削除成功は204とする。

各更新は一候補をトランザクション境界とする。認証は設けず個人利用とする。登録名・文面にはDB上の一意制約を設けない。

## 出力と状態

場所と動作は、選択した候補を一覧の表示順で結合し、カテゴリごとに一つのセクションとしてpositiveへ渡す。動作は各候補の間を半角スペース一つでつなぐ。場所は括弧の外側にあるカンマをタグの区切りとして扱い、完全一致するタグを先に現れた一つだけ残してから、カンマと半角スペースで結合する。`indoors`と`indoors`は一つにし、`indoors`と`(indoors)`は別のタグとして残す。括弧の対応が壊れて安全に分割できない文面を含む場合は、内容を壊さず候補間を半角スペース一つでつなぐ。構図は選択した一候補を一つのセクションとして渡す。

未選択のカテゴリは出力しない。全カテゴリでは、デフォルト、人物・キャラクターLoRAタグ、そのトリガー、表情、視線、衣装LoRAタグ、衣装LoRAトリガー、服装、動作、場所、構図、追加順のオプションブロックとする。選択変更や候補の更新だけでは表示済み出力を変更せず、次の「プロンプトを表示」で反映する。

保存・削除後は一覧を再取得する。編集した候補の選択は維持し、削除した候補だけを選択集合から除く。取得失敗時は再取得を案内し、保存・削除失敗時は入力内容・一覧・選択状態を保持する。処理中は同じ操作の重複実行を防ぐ。

## 受入条件

| 要件 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| R01・R02 | 公園とベンチのバッジを選ぶ | 両方が選択状態になり、他の場所候補も選択できる |
| R01・R02 | `park, outdoors,`と`bench, outdoors, (outdoors),`を持つ場所を選んで表示する | 場所は`park, outdoors, bench, (outdoors),`となり、完全一致する`outdoors`だけが一つになる |
| R02 | 選択中のベンチをもう一度押す | ベンチだけが解除され、公園は選択状態を維持する |
| R03・R04 | 正面を選択後に横からを選ぶ | 横からだけが選択状態になる |
| R05・R06 | 座ると本を読むのバッジを選ぶ | 両方が選択状態になる |
| R02・R04・R06 | ページを開く | 場所・構図・動作はすべて未選択で始まる |
| R07 | 選択中の場所を削除する | 削除した場所だけが選択から外れ、既存出力は次の表示まで変わらない |
| R08 | 公園・ベンチ、横から、座る・本を読むを選択して表示する | 場所と動作は各一セクションへまとまり、構図は一セクションとしてpositiveへ入り、negativeは変わらない |
| R01・R03・R05 | 空白とカンマだけの文面を保存する | 422となり登録されない |

## 設計上の判断

- 人物の動作、背景となる場所、画像全体を決める構図の順に出力する。
- 場所と動作は部品を再利用して組み合わせられることを優先し、複数選択とする。構図は矛盾する視点を避けるため最大一つとする。
