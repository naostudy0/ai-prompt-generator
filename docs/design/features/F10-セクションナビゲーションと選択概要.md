# F10 セクションナビゲーションと選択概要

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[画面設計](../画面設計.md)、[F02](F02-プロンプトの選択と表示.md)、[F05](F05-LoRAの登録と選択.md)、[F08](F08-オプション項目の登録と選択.md)、[F09](F09-衣装LoRAの登録と複数選択.md)、[フロントエンド構成の判断](../../decisions/0003-フロントエンド構成の継続.md)。

## 目的と背景

利用者が多数の入力セクションを使うとき、目的のセクションを探すためのスクロールを減らし、離れたセクションで何を選んだかを確認しながらプロンプトを組み立てられるようにする。

現在の中央領域は一つの作業へ集中しやすい一方、縦に長くなると上で行った選択が画面外へ出る。入力欄を広げず、その外側の余白を補助表示へ利用する。

## 要件

| ID | 要件 |
| --- | --- |
| F10-R01 | 広い画面の左側に入力セクションへのナビゲーションを表示できる |
| F10-R02 | ナビゲーションから選んだ入力セクションへ移動できる |
| F10-R03 | 追加・編集・並べ替えたオプションブロックをナビゲーションへ即時に反映できる |
| F10-R04 | 広い画面の右側に現在選択中の項目をセクション単位で表示できる |
| F10-R05 | 選択・選択解除・設定値の変更を選択概要へ即時に反映できる |
| F10-R06 | 選択がないセクションを選択概要に表示しない |
| F10-R07 | ページをスクロールしても左右の補助メニューを参照できる |
| F10-R08 | 補助メニューを表示できない幅では既存の中央領域をそのまま利用できる |
| F10-R09 | 右側の選択概要から、中央の表示ボタンまで移動せずにプロンプトを生成できる |
| F10-R10 | 左メニュー上でオプションブロックをドラッグして並べ替え、保存できる |

## 対象範囲

対象は入力セクションへの移動と、現在のブラウザー内選択状態の表示である。選択概要からの選択解除・編集、選択状態のサーバー保存、出力テキストの解析、お気に入りとの連携は含めない。選択操作は元の入力セクションで行う。

出力欄は入力候補を探す対象ではないため、左ナビゲーションには含めない。「プロンプトを表示」による出力欄への既存の自動スクロールは維持する。

## 画面構成

中央領域は現在の最大幅を維持する。ビューポート幅が1,200px以上の場合だけ、三列のレイアウトへ切り替える。

```text
┌ セクション ┐  ┌──── 現在の入力・出力画面 ────┐  ┌ 選択中 ┐
│ デフォルト  │  │                                │  │ LoRA    │
│ LoRA        │  │    スマートフォン相当の幅       │  │  ○○ 0.8 │
│ 衣装LoRA    │  │                                │  │ 表情    │
│ 表情        │  │                                │  │  笑顔    │
│ …           │  │                                │  │ …       │
└────────────┘  └──────────────────────────────┘  └─────────┘
```

左は幅13rem、右は幅16remを基準とし、中央との間に1.5rem以上の間隔を取る。左右メニューは`position: sticky`で上端1.5remに追従させ、最大高をビューポート高から上下余白を除いた値にする。内容が最大高を超えた場合は各メニュー内だけを縦スクロールできるようにする。

1,200px未満では左右メニューを表示せず、現在と同じ中央一列のレイアウトを維持する。補助メニューを非表示にしても、すべての選択・編集・表示・リセット操作を利用できなければならない。

## 左側のセクションナビゲーション

次を入力画面の表示順で並べる。

1. デフォルト
2. 人物・キャラクターLoRA
3. 衣装LoRA
4. 保存済み表示順の各オプションブロック

デフォルトのpositiveとnegative、人物・キャラクターLoRAに従属するトリガーと服装、衣装LoRA内の個別カードは、それぞれ一つの親セクションにまとめる。メニューを過度に長くせず、到着先で関連項目をまとめて確認できるためである。

各リンクは対象セクションを示す安定したキーを持つ。固定セクションは用途を表すキー、オプションブロックはDBのIDを使う。同名のオプションブロックが複数あっても別の移動先として扱う。

左右のサイドメニューからセクション名を操作すると、アニメーションを使わず対象の見出しが見える位置へ即時移動し、見出しまたはセクションへフォーカスを移す。キーボード操作でも同じ結果になる。オプションブロックの追加、名前変更、並べ替えが成功した時点で、リンクの追加、表示名、順序を更新する。ブロック内の項目変更だけではナビゲーションを変更しない。

左メニューのオプションブロックにはドラッグ用のつまみを付ける。別のオプションブロック上に落とすと、そのブロックの前または後ろへ移動し、既存の並べ替えAPIで保存する。固定セクションは移動対象にしない。移動に成功したら中央のブロック、左メニュー、右の選択概要を保存済みの順序へ揃える。失敗時はサーバー上の順序を再取得して戻し、エラーを表示する。リンク本体の移動操作は維持する。

## 右側の選択概要

選択概要は登録された文面や生成後の全文ではなく、選択判断に使った登録名を表示する。長いプロンプト本文を表示して確認性を下げないためである。表示順は入力画面と同じとし、次の内容を扱う。

| セクション | 表示内容 |
| --- | --- |
| デフォルト | 選択中の`positive デフォルト`、`negative デフォルト` |
| 人物・キャラクターLoRA | LoRA登録名と現在の強度、選択中トリガー登録名、選択中服装登録名 |
| 衣装LoRA | 選択中の各LoRA登録名と現在の強度、そのLoRAで選択中のトリガー登録名 |
| オプションブロック | ブロック名と、選択中項目の登録名 |

選択が一件もないセクションは見出しを含めて表示しない。衣装LoRAのように親が複数選択できる場合は、LoRAごとに強度とトリガーの対応が分かるまとまりで表示する。トリガーまたは服装だけが未選択なら、その行だけを省略する。

選択、選択解除、単一選択の切り替え、LoRA強度変更、トリガー変更、全体リセットに同期して更新する。登録名の編集、項目の移動、ブロック名変更、選択中データの削除でも、現在の選択状態を維持できる範囲で表示名と所属を更新する。選択解除または削除によって空になったセクションは直ちに消す。

右の選択概要ではセクション名を操作すると中央の該当セクションへ移動する。各選択項目には枠を持たない赤い「×」を置き、操作すると中央の選択状態も解除する。人物・キャラクターLoRAの項目を解除した場合は所属トリガーも解除し、服装は別項目として個別に解除できる。

選択概要から選択内容の解除・編集は行わず、表示は読み取り専用とする。メニュー下部にはプロンプト作成ボタンを置き、中央の「プロンプトを表示」と同じ生成処理を実行する。両方のボタンは、取得済みのカテゴリに一つ以上の選択がある場合に有効とし、デフォルトだけの選択でも生成できるようにする。

## 状態とフロントエンド設計

選択状態の正本は引き続き各機能の画面コントローラーが持つ。ページ全体に二重の選択状態を作らない。

各コントローラーは次の二種類の画面用情報を返し、状態変化後にページコントローラーへ通知する。

- `navigationItems`: セクションキー、表示名、対象要素を特定する情報、表示順。
- `selectionGroups`: セクションキー、見出し、選択中項目の表示名、必要な補足値、表示順。

ページコントローラーはデフォルト、人物・キャラクターLoRA、衣装LoRA、オプションブロックのスナップショットを集約し、左右メニューを再描画する。通知はブラウザー内の同期処理とし、API通信を発生させない。登録・編集・並べ替えでサーバーから一覧を再取得した場合は、確定した取得結果から新しいスナップショットを通知する。

表示用スナップショットには登録名、ID、強度など表示に必要な値だけを含める。プロンプト本文を複製しない。メニューの再描画は中央領域のDOMを置き換えず、入力中の値、フォーカス、各一覧のスクロール位置へ影響させない。

## ドメイン・永続化・API

この機能は保存済み候補と今回のブラウザー内選択を見やすく投影するプレゼンテーション上の機能であり、新しいドメインモデル、DBテーブル、APIを追加しない。既存APIのレスポンスに含まれるID、登録名、順序、選択方式、推奨強度を利用する。

## 読み込み失敗と状態変化

ある機能の候補取得に失敗した場合、その機能の固定ナビゲーションは残し、選択概要には選択済みとして確定できる内容だけを表示する。再読み込み成功後に最新状態へ更新する。オプションブロック一覧を取得できない場合は、存在を確定できない動的リンクを表示しない。

左右メニューの更新失敗だけで選択操作を失敗扱いにしない。描画処理は受け取ったスナップショットから決定的に作り、次の状態通知で全体を再構築できるようにする。

## アクセシビリティ

- 左メニューは`nav`と識別可能な見出し、右メニューは補足情報を表す`aside`と見出しを持つ。
- 選択概要の変化を一操作ごとに音声で読み上げない。元の選択部品が状態変化を伝えるため、頻繁な重複通知を避ける。
- 左リンクはキーボードで操作でき、対象へ移動後もフォーカス位置から操作を続けられるようにする。
- 左右のサイドメニューによる移動は、利用環境の設定にかかわらず即時移動とする。
- 色だけで現在位置や選択状態を表現しない。

## 受入条件

| 要件 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| R01・R07 | 幅1,200px以上で長い入力画面を下へスクロールする | 左右メニューが画面内に追従し、内容が画面高を超える場合は各メニュー内をスクロールできる |
| R08 | 幅1,200px未満で画面を開く | 左右メニューは表示されず、中央領域の幅と全操作が維持される |
| R02 | 左メニューで衣装LoRAを選ぶ | 衣装LoRA見出しが見える位置へ移動し、そのセクションから操作を続けられる |
| R03 | オプションブロックを追加し、名前変更して先頭へ移動する | 左メニューへ追加され、変更後の名前と表示順へ即時に更新される |
| R04・R05 | 人物LoRAを強度0.8で選び、トリガーと服装を選ぶ | 右側の人物LoRA欄で各登録名と強度0.8を対応付けて確認できる |
| R04・R05 | 衣装LoRAを二つ選び、それぞれ強度とトリガーを変える | LoRAごとに現在の強度とトリガーを区別して確認できる |
| R04・R05 | 複数選択のオプションブロックで下側の二項目を選ぶ | ブロック名の下に二つの登録名が表示され、元の一覧のスクロール位置は変わらない |
| R05・R06 | 選択中の項目を解除して、そのブロックが空になる | 項目が消え、空になったブロック見出しも右メニューから消える |
| R05・R06 | 全体リセットを行う | LoRAとオプションの概要は消え、初期選択されるpositive／negativeデフォルトだけが残る |
| R03・R05 | 選択中項目を別のオプションブロックへ移す | 左メニューはブロック順を保ち、右メニューでは項目が移動後のブロックに表示される |
| R08 | 補助メニューを非表示にした幅で選択してから画面を広げる | 現在のナビゲーションと選択概要が表示され、選択をやり直す必要がない |
| R09 | 右側の選択概要で「プロンプトを作成」を押す | 現在の選択からpositive／negativeが生成され、出力欄の先頭へ移動する |
| R10 | 左メニューで後方のオプションブロックを先頭のオプションブロックへドラッグする | 中央・左右の表示順が更新され、ページを再読み込みしても順序が保たれる |

## 設計上の判断

- 中央領域の幅を変えず、広い画面の余白を補助メニューへ使う。
- 左は探す目的、右は確認する目的に分ける。
- 選択概要には登録名と必要な設定値だけを表示し、長いプロンプト本文は表示しない。
- 選択状態を複製せず、既存コントローラーの状態から表示用スナップショットを作る。
- フロントエンドは現在のJavaScriptモジュール構成を継続し、今回の機能だけを理由に全面移行しない。

## 未決事項

実装を開始できない未決事項はない。狭い画面向けの折り畳みメニュー、右側からの選択解除、現在表示中セクションの強調は、実際の利用状況を見て別機能として検討する。
