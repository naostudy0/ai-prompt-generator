# F21 人物LoRA差し替えグループ

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[画面設計](../画面設計.md)、[F11](F11-人物LoRAの差し替えコピー.md)、[F13](F13-ComfyUIへのキュー送信.md)、[F17](F17-人物LoRAの非表示.md)

## 目的と背景

人物LoRA差し替え候補の一括送信対象は、現在、候補ごとのチェック状態として同じブラウザーに保持している。構図や表現内容によって使いたい人物とトリガーの組み合わせが変わるため、利用者は用途が変わるたびに多数のチェックを付け外ししている。

用途ごとのチェック集合へ名前を付けて保存し、呼び出すだけで一括送信対象を切り替えられるようにする。人物単位ではなく「人物LoRAと特定トリガーの組み合わせ」を所属単位とし、同じ人物でも目などの描写を含むトリガーと含まないトリガーを別々に扱えるようにする。

## 要件

| ID | 要件 |
| --- | --- |
| F21-R01 | 現在チェックされている人物LoRAと特定トリガーの組み合わせへグループ名を付けて保存できる |
| F21-R02 | 保存済みグループを呼び出すと、現在のチェック状態をグループの保存内容へ完全に置き換える |
| F21-R03 | グループ呼び出し後のチェック変更は、明示的に上書き保存しない限り保存済みグループを変更しない |
| F21-R04 | 同名保存は確認後に上書きし、保存済みグループを確認後に削除できる |
| F21-R05 | 人物LoRAまたはトリガーが削除・非表示になってもグループを呼び出せ、利用可能な候補だけを選択して不足を通知する |
| F21-R06 | グループで復元したチェック状態を、F13の一括送信対象としてそのまま利用できる |
| F21-R07 | グループと現在のチェック状態を同じブラウザーに保持し、DB、サーバー内ストレージ、Cookieへ保存しない |
| F21-R08 | `localStorage`を利用できない場合も画面内のチェック操作を継続でき、保存・削除・永続化の失敗を通知する |

## 対象範囲

対象はF11の人物LoRA差し替えモーダルに表示される候補である。候補の所属単位は人物LoRA IDとトリガーIDの組み合わせとする。トリガーのない人物LoRA候補はトリガーなしを表す専用値との組み合わせとして扱う。

グループの作成、同名上書き、呼び出し、削除、全選択、全解除を初回範囲に含める。グループ名の変更、並べ替え、複製、インポート・エクスポート、別ブラウザー・別端末との同期、DB保存、利用者間共有は対象外とする。

グループは候補を絞り込んで一括送信対象を切り替えるためのブラウザー設定であり、人物LoRAやトリガーそのものの分類・属性にはしない。通常の人物LoRA選択一覧、人物LoRA登録内容、プロンプト出力順は変更しない。

## 用語

- **候補キー**：人物LoRA IDとトリガーIDから作る、差し替え候補を識別する文字列。既存の一括チェックと同じ`lora:{LoRA ID}:trigger:{トリガーID}`形式を使い、トリガーなしは`trigger:none`とする。
- **グループ**：グループ名と候補キー集合の保存済みスナップショット。
- **現在のチェック状態**：モーダルで現在選択されている一括送信対象。グループとは別の可変状態である。

## ユースケース1：現在のチェック状態をグループへ保存する

- **実行者・入力**：利用者が候補へチェックを付け、1文字以上100文字以下のグループ名を入力して保存する。
- **事前条件**：人物LoRA差し替え候補の読み込みが完了している。空のグループも、すべてを対象外にする用途として保存を許可する。
- **正常な流れ**：グループ名の前後空白を除き、現在チェックされている全候補の候補キーを重複なく取得する。新しい名前ならグループを追加し、保存済みグループ一覧へ反映する。
- **同名上書き**：前後空白を除いた名前を大文字小文字を区別せず比較する。同名があれば、対象名と現在の選択件数を示して確認し、承認された場合だけ内容を置き換える。既存の表示名は今回入力した名前へ更新する。
- **失敗**：名前が空、101文字以上、または`localStorage`へ保存できない場合は保存済み一覧を変更せず理由を表示する。
- **事後条件**：保存操作だけでは現在のチェック状態を変更しない。

## ユースケース2：グループを呼び出す

- **実行者・入力**：利用者が保存済みグループを選んで「呼び出す」を押す。
- **正常な流れ**：表示中の検索、系統絞り込み、ページ位置に関係なく、取得済みの全候補について一度チェックを外し、グループに保存された候補キーと一致する候補だけへチェックを付ける。現在のチェック状態として`localStorage`へ保存し、選択件数と一覧表示を更新する。
- **未保存変更**：現在のチェック状態に未保存の変更があっても追加確認は行わず、呼び出したグループの内容で置き換える。保存済みグループ自体は変更しない。
- **不足候補**：保存済み候補キーのうち現在の候補一覧に存在しないものは無視する。件数があれば「利用できない候補N件を除いて呼び出しました」と表示する。削除済み、非表示、または取得結果に含まれない理由をブラウザー側で区別しない。
- **新規候補**：グループ保存後に追加された人物LoRAまたはトリガーは自動選択しない。
- **事後条件**：F13の一括送信は呼び出し後の現在のチェック状態だけを対象にする。

## ユースケース3：グループを削除する

- **実行者・入力**：利用者が保存済みグループを選んで削除する。
- **正常な流れ**：対象名を示して確認し、承認後にだけ保存済み一覧と`localStorage`から削除する。
- **キャンセル・失敗**：確認を取り消した場合、または保存に失敗した場合はグループを残す。
- **事後条件**：削除時点の現在のチェック状態は変更しない。

## 初期状態と既存チェック状態

グループが一件もない場合も従来どおり候補チェックを利用できる。チェック状態が未保存なら全候補を選択した状態から始める。既存の一括送信用チェック状態は現在のチェック状態として引き続き使用し、自動的に名前付きグループへ変換しない。

「すべて選択」と「すべて解除」は取得済みの全候補へ適用し、検索結果や現在ページだけに限定しない。操作結果は現在のチェック状態へ保存するが、呼び出し元の保存済みグループは変更しない。

## 保存形式と整合性

保存済みグループは既存チェック状態とは別の`localStorage`キーへ、バージョンを持つJSONとして保存する。

```json
{
  "version": 1,
  "groups": [
    {
      "name": "目を描写しない構図向け",
      "candidateKeys": [
        "lora:12:trigger:41",
        "lora:18:trigger:none"
      ]
    }
  ]
}
```

読み込み時は外部入力として構造を検証する。バージョン、グループ配列、名前、候補キー配列の型が不正なデータは使用しない。候補キーは実際の候補一覧との完全一致にだけ使い、文字列からIDを復元してサーバー処理へ渡さない。一括送信時は従来どおり候補オブジェクトの人物LoRA IDを使用する。

保存済みグループの配列と候補キー配列は保存時の順序を保持する。候補表示順と一括送信順はF11・F13の既存順序を使い、グループ内の保存順では変更しない。

## UI設計

人物LoRA差し替えモーダルの候補一覧より前に、次のグループ管理欄を置く。

```text
グループ
[保存済みグループ ▼] [呼び出す] [削除]

[グループ名________________] [現在のチェックで保存]
[すべて選択] [すべて解除]  選択中 N件
```

- 保存済みグループがない場合、選択欄には「保存済みグループなし」を表示し、呼び出しと削除を無効にする。
- グループ名入力と保存操作は、現在のチェックをグループとして新規保存または同名上書きする操作であることが分かるラベルを持つ。
- 保存、呼び出し、削除、`localStorage`失敗、不足候補の結果はモーダル内のステータスへ表示する。
- グループ呼び出し後も検索条件と系統絞り込みは維持する。チェック状態は候補ページを移動しても維持する。
- 一件コピー、negativeコピー、単独送信はグループのチェック状態に関係なく従来どおり利用できる。

## エラーとプライバシー

`localStorage`の読み取りに失敗した場合はグループなし・現在の画面内では全選択として開始し、永続化できない旨を表示する。書き込みに失敗した操作は成功通知を出さず、保存済みグループのメモリ上の状態も操作前へ戻す。現在のチェック操作は画面内で継続できる。

グループには候補キーと利用者が付けたグループ名だけを保存する。プロンプト本文、人物名、ファイル名、トリガー名・文面、画像、生成結果は保存しない。通常のアプリケーションログへグループ内容を送らない。

## 実装境界

グループの検証、同名判定、保存用スナップショット、呼び出し時の候補キー集合計算は、DOM操作から分離したJavaScriptモジュールで扱う。人物LoRA差し替えページは、候補一覧・現在のチェック状態とグループ管理UIを結び付ける。

LaravelのApplication、Domain、Infrastructure、HTTP API、DBマイグレーションは追加しない。既存の人物LoRA参照APIとF13の送信APIをそのまま利用する。

## 受入条件と検証

| 関連要件 | 確認する場面 | 期待結果 |
| --- | --- | --- |
| R01 | 同じ人物の異なる二つのトリガーの片方だけをチェックして保存する | 呼び出すと保存した人物＋トリガーだけがチェックされる |
| R02・R03 | グループAを呼び出し、チェックを変更後にグループBを呼び出す | 未保存変更が破棄されてBの内容へ置き換わり、Aの保存内容は変わらない |
| R04 | 既存名で保存し、確認を取り消した後に再度承認する | 取り消し時は元内容を維持し、承認時だけ現在のチェックへ上書きされる |
| R04 | 保存済みグループを削除する | 確認後だけ一覧から消え、現在のチェックは変わらない |
| R05 | グループ保存後に候補の人物またはトリガーを削除・非表示にして呼び出す | 利用可能な候補だけが選択され、不足件数が通知される |
| R06 | グループを呼び出して一括送信する | 呼び出したグループと一致する候補だけが送信対象になる |
| R02・R06 | 検索、系統絞り込み、ページ分割を使用中にグループを呼び出す | 非表示ページを含む全候補のチェックが置き換わり、表示条件は維持される |
| R07 | ページを再読み込みする | 保存済みグループと現在のチェック状態が同じブラウザーで復元される |
| R08 | `localStorage`の読み書きを失敗させる | 失敗が表示され、保存済みグループを壊さず画面内のチェック操作を続けられる |
| R01・R07 | 保存内容を確認する | プロンプト本文、人物名、ファイル名、トリガー文面を含まず候補キーだけが保存される |

ブラウザー自動操作や実データ参照は行わず、JSDOMと架空の人物・トリガー・ストレージを使った自動テストで検証する。画面の最終的な視認性と実ブラウザーでの操作感は利用者確認事項とする。

## 未決事項

実装開始を妨げる未決事項はない。グループ名変更、並べ替え、複製、インポート・エクスポート、サーバー保存、複数端末同期は利用状況を見て別途設計する。
