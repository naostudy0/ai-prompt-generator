# F04 お気に入りプロンプトの登録・呼び出し

- 関連：[機能概要](../../spec/機能概要.md)、[用語集](../../spec/用語集.md)、[F02](F02-プロンプトの選択と表示.md)、[F03](F03-出力の編集とコピー.md)、[F05](F05-LoRAの登録と選択.md)、[F08](F08-オプション項目の登録と選択.md)、[F09](F09-衣装LoRAの登録と複数選択.md)、[F10](F10-セクションナビゲーションと選択概要.md)。

## 目的と背景

利用者が似た構成の画像を再び作るとき、以前調整した完成プロンプトを探し、当時の選択を一つずつ再現する手間を減らす。

選択項目から生成した後に出力欄を直接調整することがあるため、選択状態だけでは完成した文面を再現できない。お気に入りには出力欄の現在値と登録時の選択を両方保存し、完成文面の再利用と選択画面の再構築をそれぞれ行う。

## 要件

| ID | 要件 |
| --- | --- |
| F04-R01 | 出力欄に現在表示されているpositive／negativeを一組で保存できる |
| F04-R02 | 保存時に任意の名前を付けられる |
| F04-R03 | 登録時に選択していたデフォルト、人物・キャラクターLoRA、トリガー、服装、衣装LoRA、衣装LoRAトリガー、オプション項目と強度を保存できる |
| F04-R04 | 登録時の選択内容を、右側の選択概要と同程度にまとまった説明として後から確認できる |
| F04-R05 | 保存時に任意の参考画像を添付できる |
| F04-R06 | お気に入りを呼び出すと、保存したpositive／negativeを出力欄へそのまま復元できる |
| F04-R07 | 呼び出し時に現在も存在する選択項目を選択状態へ復元できる |
| F04-R08 | 削除・変更された候補のため完全に復元できない場合、その事実と影響を利用者へ通知できる |
| F04-R09 | お気に入りの一覧表示、呼び出し、編集、削除ができる |
| F04-R10 | 呼び出したお気に入りを現在の出力と選択内容で上書きするか、別のお気に入りとして保存できる |

## 対象範囲

お気に入りの名前、完成済みpositive／negative、選択スナップショット、説明用の選択概要、任意画像をSQLiteとサーバー内ストレージへ保存する。一覧からの呼び出し、名前・画像・完成プロンプト・選択内容の変更、別のお気に入りとしての保存、削除を対象とする。

呼び出し時点の候補から保存済みの完成プロンプトを自動的に書き換えること、存在しない選択項目を自動作成すること、画像生成ツールから生成画像を自動取得することは対象外とする。

## 登録

登録対象のpositive／negativeは、登録ボタンを押した時点の出力テキストエリアの値とする。選択から生成した直後の値ではなく、利用者が直接編集した後の値を保存する。両方が空の場合は登録できない。片方だけが空の場合は登録できる。

名前は任意入力とする。空欄時の一覧上の表示名は、登録日時を使った「YYYY/MM/DD HH:mmのお気に入り」とする。この表示名は保存名を補う画面表示であり、`name`は空のまま保持する。名前の重複は許容し、DBのIDで識別する。

選択状態は復元用の識別情報として次を保存する。

| 種別 | 復元用の値 |
| --- | --- |
| デフォルト | positive／negativeごとの選択有無 |
| 人物・キャラクターLoRA | LoRA ID、今回の強度、トリガーID、服装ID |
| 衣装LoRA | 選択した各LoRA ID、各強度、各トリガーID |
| オプション | 選択した項目ID |

復元用IDだけでは、候補が後で削除・改名された場合に登録時の内容を説明できない。そのため、登録時点の右側の選択概要に相当する表示用スナップショットも保存する。表示用スナップショットはセクション名、選択した登録名、強度、トリガーや服装との対応を持ち、お気に入りの説明に使う。後から候補名を変更しても、保存済み説明は登録時の表記を維持する。

## 呼び出しと復元

呼び出しでは、最初に保存済みpositive／negativeを出力欄へそのまま表示する。これにより、登録前に直接編集した語句も失わない。続いて現在の候補一覧と選択スナップショットを照合し、存在する項目だけを選択状態へ反映する。

復元後、現在の選択からpositive／negativeを再生成した比較用文面を作る。ただし、この比較のために出力欄を上書きしない。次のいずれかに該当する場合は部分復元として通知する。

- 保存時に選択していたIDが現在は存在しない。
- LoRAとトリガーまたは服装の所属関係が変わり、保存時の組み合わせを選べない。
- オプション項目が別ブロックへ移動し、現在の単一選択規則と両立しない。
- 現在の登録文面やデフォルト文面が変わり、復元した選択からの再生成結果が保存済みpositive／negativeと一致しない。
- 保存後の直接編集により、登録時点から選択だけでは同じ文面を生成できない。

通知は「選択項目または登録内容が変わったため、一部を選択状態へ反映できませんでした。保存済みのプロンプトはそのまま表示しています。」を基本とし、反映できなかった登録時の表示名を確認できるようにする。完全復元できた場合は通常の呼び出し完了だけを通知する。

呼び出し前に画面上にあった選択と出力は、お気に入りの内容へ置き換える。呼び出し自体ではお気に入りや候補を更新しない。呼び出した出力は通常の出力と同じく直接編集・コピーできる。

## 画像

画像はお気に入りの内容を視覚的に識別する参考資料として、一つのお気に入りにつき任意で一枚添付する。JPEG、PNG、WebPを許可し、最大容量は20MBとする。拡張子だけで判断せず、サーバー側で画像とMIME typeを検証する。画像ファイル本体はLaravelの管理するサーバー内ストレージへ保存し、DBには保存先、元のファイル名、MIME type、サイズを記録する。ブラウザーから直接任意パスへ保存しない。

お気に入り削除時は対応する画像も削除する。画像を差し替える場合は、新しい画像の保存とDB更新が成功した後に古い画像を削除し、失敗時に既存画像を失わないようにする。

## 画面

出力欄付近に「お気に入りへ保存」と「お気に入りを開く」を置く。登録フォームには任意の名前、任意の画像、保存対象となる選択概要を表示する。

「お気に入りを開く」から、画像付きカードの一覧をモーダルで表示する。各カードでは名前、画像のサムネイル、登録日時、登録時の選択概要を確認できる。一覧項目から呼び出し、編集、削除を行う。長いpositive／negative全文は通常の一覧へ常時表示せず、詳細表示で確認できるようにする。画像がない場合は画像領域を空白にせず、画像未登録と分かる共通の表示を使う。

お気に入りを呼び出した後に出力や選択を変更して保存する場合は、「上書き保存」と「別のお気に入りとして保存」を選べるようにする。上書き保存は呼び出し元と同じIDへ現在の完成プロンプト、選択スナップショット、選択概要、指定した名前と画像を保存する。別保存は元のお気に入りを変更せず、新しいIDで登録フォームを開く。

呼び出し結果の通知は出力欄と復元後の選択の両方を確認できる位置に表示する。部分復元の場合は、保存済み出力が失われていないことと、反映できなかった選択を明示する。

## データ設計

`favorite_prompts`をお気に入りの集約ルートとし、次を保持する。

| 項目 | 内容 |
| --- | --- |
| id | お気に入りの識別子 |
| name | nullableな利用者入力名 |
| positive_prompt | 登録時のpositive出力全文 |
| negative_prompt | 登録時のnegative出力全文 |
| selection_snapshot | 復元用ID・強度を持つJSON |
| selection_summary | 登録時の説明表示を持つJSON |
| image_path | nullableな保存先 |
| image_original_name | nullableな元ファイル名 |
| image_mime_type | nullableなMIME type |
| image_size | nullableなバイト数 |
| created_at／updated_at | 登録・更新日時 |

`selection_snapshot`と`selection_summary`は、お気に入りを登録時点の記録として一括して読み書きする値であり、個別検索や外部キーによる追従更新を目的としないためJSONで保持する。候補の削除時にもお気に入り内の記録は削除しない。呼び出し時の不一致検出に利用する。

お気に入りの登録・更新・削除は更新ユースケースに分ける。一覧・詳細・呼び出し用データの取得は参照ユースケースに分ける。登録時は画像保存、DB保存、失敗時のファイル削除をアプリケーション層で調整する。

## API案

| 目的 | メソッド・URL | 主な入力・出力 |
| --- | --- | --- |
| 一覧取得 | `GET /favorite-prompts` | ID、名前、選択概要、画像URL、登録日時 |
| 詳細取得 | `GET /favorite-prompts/{favoritePrompt}` | 完成プロンプト、選択スナップショット、選択概要、画像情報 |
| 登録 | `POST /favorite-prompts` | 名前、positive、negative、選択スナップショット、選択概要、画像 |
| 編集・上書き | `POST /favorite-prompts/{favoritePrompt}` | 名前、positive、negative、選択スナップショット、選択概要、画像、画像削除指定。ファイル送信のため`POST`とし、`_method=PUT`を指定 |
| 削除 | `DELETE /favorite-prompts/{favoritePrompt}` | 成功時204 |

更新APIはCSRF保護を適用する。両プロンプトが空、名前・画像が制約違反、スナップショット形式が不正な場合は422、対象が存在しない場合は404を返す。

## 失敗時

- 登録・編集に失敗した場合は入力した名前、現在の出力と選択を画面上で維持する。ブラウザーの制約で画像ファイルの再設定が必要な場合は、そのことを案内する。
- 一覧取得に失敗した場合は未登録と表示せず、再取得を案内する。
- 呼び出し用データの取得に失敗した場合は、現在の出力と選択を変更しない。
- 削除に失敗した場合は一覧から消さず、画像も残す。
- 画像だけ保存されDB保存に失敗した場合は、今回保存した画像を削除する。

## 受入条件

| 要件 | 前提・操作 | 期待結果 |
| --- | --- | --- |
| R01・R02・R03・R04 | 選択から生成した出力を直接編集し、名前を付けて登録する | 編集後のpositive／negative、選択IDと強度、登録時の選択概要が一つのお気に入りとして保存される |
| R01 | positiveだけに文面がある状態で登録する | positiveを保存し、negativeは空文字列として保存される |
| R01 | positive／negativeが両方とも空の状態で登録する | 422となり、画像を含むお気に入りは作成されない |
| R05 | 画像を指定して登録する | お気に入りと画像が対応付いて保存され、一覧にサムネイルが表示される |
| R06・R07 | 保存後に候補を変更せず呼び出す | 保存済み出力がそのまま表示され、登録時の選択が復元される |
| R06・R08 | 出力を直接編集して保存したお気に入りを呼び出す | 編集済み出力が表示され、選択からの再生成結果との差を通知する |
| R07・R08 | 保存時に選択したオプションを削除してから呼び出す | 存在する選択だけを復元し、削除された登録時の表示名と部分復元を通知する |
| R07・R08 | 保存後にデフォルトまたは候補文面を変更して呼び出す | 選択は復元され、現在の再生成結果と保存済み出力が異なることを通知する |
| R07・R08 | 保存時の単一選択規則と両立しないスナップショットを呼び出す | 復元可能な一項目だけを選び、反映しなかった項目を通知する |
| R09 | お気に入りを削除する | DBの記録と添付画像が削除され、候補や現在の出力は変更されない |
| R02 | 名前を空欄にして登録する | 一覧では登録日時を使った「YYYY/MM/DD HH:mmのお気に入り」と表示される |
| R05 | JPEG、PNG、WebP以外または20MBを超える画像を指定する | 422となり、お気に入りと画像を保存しない |
| R10 | お気に入りを呼び出して出力と選択を変更し、上書き保存する | 同じお気に入りの完成プロンプト、選択スナップショット、選択概要が現在値へ更新される |
| R10 | お気に入りを呼び出して変更し、別のお気に入りとして保存する | 呼び出し元を変更せず、新しいIDのお気に入りが登録される |

## 設計上の判断

- 完成文面を正本として復元し、選択状態は再編集を助ける情報として復元する。
- 復元用IDと説明用表示名を分け、候補が変更・削除されても登録時の内容を確認できるようにする。
- 復元後の再生成文は差分検出だけに使い、保存済み完成文面を上書きしない。
- 不一致をエラーとして呼び出し失敗にせず、復元できた範囲と保存済み出力を利用できるようにする。
- 候補削除時に過去のお気に入りを連動削除せず、登録時点の記録として保持する。

## 未決事項

実装を開始できない未決事項はない。お気に入り件数が増えた場合の検索・絞り込み・ページ分割は、実際の利用状況を見て別途設計する。
